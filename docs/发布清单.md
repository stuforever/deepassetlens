### smart_skill_pipeline / smart_skills 终态（死代码整链删除）

五巨人第五个 `smart_skill_pipeline.py` 与其唯一 import 方 `smart_skills.py` 已**作为死代码整链删除**，而非拆分。依据（删除前逐一核实）：

1. **从未挂载**：`app/main.py` 不含 smart_skills router；活后端 OpenAPI 共 216 路径，**零个含 "smart"**（v1 `/smart-skills*`、`/smart-skill-workflows*` 路由从未注册）。
2. **无引用方**：全仓（含 tests/前端）无任何模块 import 这两个文件；`app/api/__init__.py` 不存在；`_invoke_skill`/`_pick_script_assistant_llm` 仅在两文件内部互引。`app/services/skill_injections.py` 仅 docstring 提及（其自身被 boss_router 等活代码使用，不受影响）。
3. **既有断链**：`from .smart_apps import ...` 中 `app.api.smart_apps` 全仓不存在（git HEAD 亦无），本链本就无法 import。
4. **领域已由 v2 承载**：受控 Skill 平台 v2（v2_skills）为活 API；`SmartSkill`/`SmartSkillType` 模型类保留于 `models/base.py`（不再被引用，定义无害）；`kg_smart_skills` 表迁移逻辑不动。

删除同时化解「>800」与断链两项，符合 YAGNI（不为死代码发明 `smart_apps` 模块）。

### 附：v2_skills secrets 既有缺陷修复

v2 技能密钥柜三端点 `GET/POST /api/v2/secrets`、`DELETE /api/v2/secrets/{key_name}` 调用 `get_skill_storage()` 但函数内缺失局部 import（311849b 版同样缺，既有 NameError 缺陷），已在 `v2_skills_misc.py` 三处补 `from app.core.skill_storage import get_skill_storage` 修复。
