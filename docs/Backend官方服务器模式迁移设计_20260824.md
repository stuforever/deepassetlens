# Backend 官方服务器模式迁移设计（批13-Y）

> 2026-08-24 定稿。用户定调：「如果确实不是官方建议的模式，我们尽量改成官方建议的服务器模式」。
> 本文档替代《装配层配置化设计》§四残留风险中"记录在案的偏离"处置——从**记录偏离**升级为**迁移消除**。

---

## 〇、结论定调

**迁移**：`/skills/` 与 `/memory/` 两条路由从 `FilesystemBackend`（窄化使用）迁移至 `StoreBackend`（官方 Web 服务器推荐组合：`CompositeBackend(default=StateBackend, routes={...: StoreBackend})`），技能/纪律文件在**装配时种子进 store**，运行时 Agent 路径**零磁盘访问**。

六条既定纪律不变：默认钉死代码；红线不入库；探针必做保险丝；fail-safe 配置 fail-closed 代码；e2e 串行唯一验收；能力开关语义不变。

---

## 一、现状与官方偏离（证据链）

### 1.1 现状（tupu_deepagent.py L855-874）

```python
CompositeBackend(default=StateBackend(),
  routes={"/skills/": FilesystemBackend(root_dir="backend/data/skills", virtual_mode=True),
          "/memory/": FilesystemBackend(root_dir="backend/data/memory", virtual_mode=True)})
```

### 1.2 官方警告原文（FilesystemBackend docstring，2026-08-24 摘录）

> 「⚠️ 此 backend 授予 Agent 直接的文件系统读写权，谨慎使用。
> 适用：本地开发 CLI、CI/CD 流水线。
> **不适用：Web 服务器或 HTTP API——应改用 StateBackend、StoreBackend 或 SandboxBackend。**」

我们当前的五层缓解（窄化锚定 / virtual_mode / 写工具拉黑 / permissions 三规则 / 能力开关）已实证有效（目录穿越攻击实验两变体全拦），但**性质仍是"记录在案的偏离"**。本批将其消除。

### 1.3 官方自己也在用 FilesystemBackend 的地方（诚实登记）

SkillsMiddleware docstring 官方示例即 `FilesystemBackend(root_dir="/path/to/skills")`——官方文档内部存在张力（示例图省事 vs 警告讲安全）。**我们按警告的严格标准走**，因为我们是生产 Web 服务器，不是示例代码。

## 二、可行性验证（全部源码实证，2026-08-24）

| # | 验证点 | 证据 | 结论 |
|---|---|---|---|
| 1 | 技能元数据加载只走 backend | SkillsMiddleware.before_agent L186-197：`_list_skills_with_errors(backend, source_path)`，逐 source 扫描 | backend 是技能体系唯一文件通道 |
| 2 | 运行时渐进披露也走 backend | 系统提示词模板官方原文："Use `read_file` on the path shown in the skill list"——read_file 由文件站转发给 backend | 换 backend 即全链路切换，无旁路 |
| 3 | StoreBackend 实现完整协议 | 源码：aget/aglob/als/aput/asearch_store_paginated 全套（L294-527） | 能扫目录（技能发现）、能读文件（渐进披露） |

| 5 | 文件按 namespace 组织 | `store.put(namespace, file_path, value)`；namespace 是工厂函数 | `("tupu","skills")` / `("tupu","memory")` 两个固定 ns，无需用户隔离 |

**关键结论**：技能加载（before_agent 扫描）与运行时读取（read_file）**全部且仅**经过 backend 接口，因此把路由指向 StoreBackend + 装配时种子，即为完整迁移，无需改任何站。

## 三、目标架构

```python
# _build_agent 内（替代 L855-874 的 FilesystemBackend 两行）
_store = _agent_store  # create_deep_agent(store=...) 同源实例；种子与运行时同库

def _seed_files(store, ns, root: Path) -> None:
    """装配时把磁盘技能/纪律树种子进 store。key=相对路径，镜像目录结构。
    例: scenarios/distribution-overload/SKILL.md -> ns 下同名 key。"""

if _on("filesystem_tools"):
    _seed_files(_store, ("tupu", "skills"), _skills_root)
    _seed_files(_store, ("tupu", "memory"), _memory_root)
    backend = CompositeBackend(
        default=StateBackend(),   # 路由表外路径: 会话草稿纸(驱逐历史等),语义不变
        routes={
            "/skills/": StoreBackend(store=_store, namespace=lambda _rt: ("tupu", "skills")),
            "/memory/": StoreBackend(store=_store, namespace=lambda _rt: ("tupu", "memory")),
        })
else:
    backend = StateBackend()      # 能力开关语义不变:关=纯内存
```

**缓存键扩展**（新鲜度保障，L1162-1183）：

```
{conn}#g{guard_ver}#c{caps_ver}  →  {conn}#g{guard_ver}#c{caps_ver}#f{files_hash}

files_hash = sha256(逐文件 相对路径+mtime+size 的有序拼接)  # 技能树+纪律树
```

技能/纪律文件任何增删改 → hash 变 → 缓存未命中 → 自动重装配+重种子。**今天**文件修改靠 FilesystemBackend 实时读盘即时可见；**迁移后**靠 hash 触发重装配（下次请求生效）。

**种子清场**：重种子前先清空两个 namespace（store.batch([PutOp(ns, key, None)])），避免删除文件后旧 key 残留（InMemoryStore 无 TTL）。

## 五、诚实代价与残留风险

1. **新鲜度语义变化（真实权衡）**：今天 FilesystemBackend 实时读盘——技能文件改完，**进行中的会话下一次 read_file 即可见**；迁移后——进行中会话用旧种子直到结束，新请求才重装配。运维感知：改剧本后秒级生效变成下次请求生效。**可接受**（剧本修改是低频运维操作），按钮/文档写明。
2. **种子代码是自研**（~80 行）：框架**不提供**磁盘→store 的种子工具（官方假设文件是 Agent 生成的，不是预置的）。"官方服务器模式"仍需这段胶水——如实登记，不夸大"纯官方"。
3. **内存驻留**：整个技能+纪律树进 InMemoryStore（当前规模数 MB 级），可接受；若将来剧本库膨胀至百 MB 级需换持久化 store（触发条件写死，YAGNI 缓议）。
4. **结构收益（为何值得）**：运行时 Agent 文件路径**结构性无磁盘**——目录穿越攻击类别整体消失（不是被拦，是不存在）；官方警告完全消除；安全叙事从"五层缓解的偏离"变成"官方推荐组合+冗余保险带"。
5. **skills_metadata 会话级缓存**（before_agent 已在 state 则跳过）：跨请求的既有行为，与本次迁移正交，不新增风险。

1. 基线回归：`backend/scripts/_pw_e2e.py` 跑「重过载」类问题，剧本渐进披露（read_file SKILL.md → 模板 → SQL）全链路正常；

3. 探针三连（两份真相/路由外不可达/开关关闭无路由）probe_ok；
4. 攻击面验证：对装配后 Agent 尝试任意磁盘路径读取 → 全部落 StateBackend 死路；
5. reset-defaults 后回到基线（本批默认值即目标架构，无回退开关——迁移是一次性的，能力开关 filesystem_tools 仍可整体关闭）。
