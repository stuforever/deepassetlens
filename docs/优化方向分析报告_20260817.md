## 一、前端 · 高优先级（P1 架构）

### 1. 路由零代码分割 — 首屏加载全部页面 + 重依赖
- 证据：`frontend/src/routes.tsx:1-14` 16 个页面**全部静态 import**；全 src `React.lazy` / `lazy(` **零命中**；`index.tsx:14-24` 无 Suspense、无 ErrorBoundary。
- 重依赖可达性：`@antv/g6` 在 4 处 import（`ForceCanvas.tsx:12`、`LineageGraph.tsx:2`、`Neo4jForceCanvas.tsx:2`、`TreeCanvas.tsx:2`），经 `GraphManager.tsx:10-13` → routes 静态链进入首屏 bundle；monaco 在 2 处（`SkillManagerV2.tsx:13`、`SqlIntegrationTab.tsx:4`）。即进首页聊天也要下载全部图谱/编辑器代码。
- **草稿未提的放大器——KeepAlive 常驻挂载**：`AppTabs.tsx:6,120-141` 所有已开页签**同时挂载**（非活动页 `display:none`），多开页签时多个重组件常驻内存。lazy 拆分收益因此**更大**：首屏只拉 home chunk，开哪个页签才拉哪个 chunk。
- 建议：`routes.tsx` 改 `React.lazy + Suspense`；g6/monaco 相关组件独立 chunk。注意：lazy 后 KeepAlive 语义仍成立（已挂载组件不卸载），无需改动 AppTabs。

### 2. 巨型组件没有拆分（行数为实测非空/总）
- `components/ModelTreeManager.tsx` **1628/1729**
- `pages/MappingManager.tsx` **1561/1681**
- `pages/SourceManager.tsx` **1355/1432**
- `pages/MetricManager.tsx` **1275/1341**
- `components/RightPanel.tsx` **900/951**（草稿漏了它）
- `pages/FreePlanChat.tsx` **811/844**
- 状态、表单、表格、抽屉混在一个文件，改动触发全量重渲染，难以测试。建议按「列表区 / 编辑抽屉 / 表单子组件」拆分。

### 3. 渲染优化几乎为零（口径修正后）
- **`React.memo` 全库 = 0**（整个 src 逐文件统计）；`useMemo=58`、`useCallback=18`（全库）。
- 最高频对话链路四件套全部 0/0/0：`FreePlanChat.tsx`、`conversation/AssistantCanvas.tsx`、`conversation/ConversationMessageList.tsx`、`conversation/CardRenderer.tsx`。
- 修正：conversation 目录确有 13 处 useMemo（`ClarificationCard:29,41`、`FinalAnswer:160,178`、`MessageTabs:85`、`QueryEntityResultCard:39,61,77`、`SqlExecutionResultCard:22,34`、`SqlResultTable:40,63`、`WorkflowExecutionTimeline:198`），说明部分卡片已做派生数据缓存；但**组件级 memo 为零**，流式（SSE/thinkStream）场景每条 token 仍会穿透整棵渲染树。
- 建议：给消息列表项、卡片组件包 `React.memo`；对最高频的 CardRenderer 分支做按 type 拆分的 memo 化。

### 4. any 泛滥 — 类型安全名存实亡（计数口径：`:\s*any` / `as any` / `<any>`）

## 二、前端 · 中优先级（P2 可维护性）

### 5. API 层封装不统一（axios 绕行，已纠偏）
- 统一实例：`services/api.ts:6-33` 有 token 注入 + 401 清 token 跳首页的拦截器。
- **完全裸奔（无 token、无 401）**：
  - `pages/DataSourceConfig.tsx:11` — `axios.create({ baseURL: '/api/v1' })`
  - `pages/DorisConfig.tsx:12` — 同上
  - `components/ModelTreeManager.tsx:863` — 直接 `axios.get('/api/v1/data-sources')`
  - `services/skillV2Api.ts:5`、`services/dataIntelligenceApi.ts:15` — 各自自建实例，无拦截器（草稿未提）
- **自管认证（重复造轮子）**：`components/ResourceAclDrawer.tsx:47-54` `authedClient()` 手动拼 Authorization，但缺 401 跳转（草稿误列它为「漏掉认证」）。
- 若 `/api/v1/data-sources`、`/api/v1/doris/*`、`/api/v2/*` 需鉴权，上述请求会拿不到 Bearer → 401 且不跳登录，行为不一致。建议全部收敛到统一实例。

### 6. 错误处理缺失统一层
- `api.ts:21-33` 只处理 401；其余错误各组件自行 catch（或不 catch），报错风格不一（`message.error` 文案五花八门）。建议响应拦截器加统一 `message.error` 兜底。

### 7. 硬编码 URL 残留（基本合规，一处例外 + 两处过时注释）
- 合规：整体遵守相对路径铁律，`setupProxy.js:12` 用 `REACT_APP_API_PROXY_TARGET` 兜底 `http://127.0.0.1:28000`。
- 例外：`components/ApiMappingTab.tsx:317` placeholder 写了 `http://localhost:1200/...`（仅为提示文案，但易误导照抄），建议改为相对路径示例。
- **过时注释**（新发现）：`setupProxy.js:2-8` 头注释仍写「直连 8000 / 走 3000 proxy」；`dataIntelligenceApi.ts:8` 注释仍写「转发到后端 8000」——均已过时（现 28000），易误导排查。
