## 一、五级 + 两类实体（对象视角）

```
主数据侧（被查询的对象本身）
L1 ─ 主数据大类（3 个：客户 / 设备 / 组织）
  └─ L2 ─ 主数据小类（19 个，每个 L2 下挂一组 L2X 实体）
       └─ L2X ─ 主数据实体（107 个，对象视角的数据集，不是物理表）
            ├── ★ 主实体   is_main_table = true   每 L2 唯一 1 个
            └── ○ 关联实体 is_main_table = false  每 L2 可能有 0~N 个

业务活动侧（主数据上发生的业务事件）
L3 ─ 业务大类（9 个业务流程）
  └─ L4 ─ 业务小类（34 个具体业务类型）
       └─ L4X ─ 业务活动实体（业务活动对象视角的数据集）
```

### 关键约束（容易理解错的点）

1. **每个 L2 下只有 1 个主实体**——主实体是 L2 的"代表"，其他 L2X 是其关联实体。
2. **只有主实体才能关联 L4X**——关联实体（联系人、地址、账户等）不能直接挂业务。
3. **L2X ↔ L4X 是多对多**——一个主数据可发生多种业务，一种业务可发生在多个主数据。
4. **L2X/L4X 是对象视角数据集，不是源表**——查源表只是为了溯源，不是主路径。
5. **主实体 ↔ 关联实体也是关系**——但属主数据内部关联，不出现在业务关联里。

## 二、主谓宾语法（最关键的一句）

> **主语 = L2X，谓语 = 关联关系（relation），宾语 = L4X**

| 语法成分 | 来自 | 例子 |
|---|---|---|
| 主语 | L2X 主实体 | 变压器设备档案 |
| 谓语 | 关系名（relation_catalog） | 发生 |
| 宾语 | L4X 业务活动实体 | 变压器检修记录 |

举例：
- 「变压器发生过哪些检修」→ 主语"变压器设备档案(L2X)" + 谓语"发生" + 宾语"变压器检修记录(L4X)"
- 「客户发起过哪些投诉」→ 主语"客户档案(L2X)" + 谓语"发起" + 宾语"客户投诉(L4X)"

## 三、三类实体（业务分类）

| 类型 | 标识 | 谁来用 | 例子 |
|---|---|---|---|
| **主实体** | L2X, is_main_table=true | 主谓宾的"主语" | 变压器设备档案、客户档案、电能表 |
| **关联实体** | L2X, is_main_table=false, 挂主实体下 | 主数据内部附属 | 变压器技术参数、客户联系人、客户用电地址 |
| **业务活动实体** | L4X | 主谓宾的"宾语" | 变压器检修记录、客户投诉、电能表采集数据 |

## 四、三类实体间关系

### 关系 1：主数据内部包含关系 — 主实体 ↔ 关联实体

**业务含义**：主数据对象内部有附属信息，不是事实关系，是组成/归属。

**特征**：1 对多、强归属、同 L2 下、不挂业务

**示例**：
- 「变压器设备档案」主实体 → 含「变压器技术参数」「变压器巡视记录」「变压器试验报告」关联实体
- 「客户档案」主实体 → 含「客户联系人」「客户用电地址」「客户银行账户」关联实体
- 「电能表」主实体 → 含「电能表通讯参数」「电能表安装位置」关联实体
- 「线路」主实体 → 含「线路杆塔」「线路金具」「线路导线」关联实体

### 关系 2：主谓事实关系 — 主实体 ↔ 业务活动实体

**业务含义**：主数据对象上发生过什么业务事实，是真正的"事件"。

**特征**：多对多、跨 L1/L2/L3/L4、**必须先建关系才能问**

**示例**：
- 「变压器设备档案」 ↔「变压器检修记录」「变压器试验记录」「变压器故障记录」「变压器巡视记录」
- 「客户档案」 ↔「客户用电记录」「客户缴费记录」「客户投诉记录」「客户报装记录」
- 「电能表」 ↔「电能表采集数据」「电能表故障记录」「电能表更换记录」
- 「线路」 ↔「线路故障记录」「线路检修记录」「线路巡视记录」
- 「供电所」 ↔「供电所考核记录」「供电所故障处理记录」

**未建关系时**：该主数据对象上未发生此类业务，需要先在图谱里建立关系

### 关系 3：业务活动内部时序关系 — L4X ↔ L4X（同 L4 下）

**业务含义**：同一类业务下，不同活动实体有先后发生顺序，构成业务流程/状态机。

**特征**：严格时序、前后驱动、单向流转、状态推进（每个 L4X 有自己的状态字段）

**示例 1：检修业务（L4=检修）**
```
报修登记 → 现场勘查 → 缺陷定级 → 检修派工 → 检修执行 → 检修验收 → 归档
```

**示例 2：业扩报装业务（L4=新装增容）**
```
业务受理 → 现场勘查 → 供电方案答复 → 设计审查 → 中间检查 → 竣工验收 → 装表接电 → 归档
```

**示例 3：客户投诉业务（L4=投诉处理）**
```
投诉受理 → 投诉派单 → 现场处理 → 处理反馈 → 回访确认 → 工单归档 → 满意度评价
```

**示例 4：故障抢修业务（L4=故障处理）**
```
故障报修 → 故障定位 → 抢修派工 → 抢修到达 → 抢修执行 → 抢修恢复 → 回访归档
```

**示例 5：电能表更换业务（L4=表计更换）**
```
换表申请 → 旧表底度记录 → 拆表 → 新表出库 → 装表 → 新表底度记录 → 归档 → 采集验证
```

## 五、三类关系在用户问句里的体现

| 用户问法 | 触发关系 | 涉及对象 |
|---|---|---|
| "查下变压器有哪些技术参数" | 关系 1 | 主实体 + 关联实体属性 |
| "变压器发生过哪些检修" | 关系 2 | 主实体 + 业务实体列表 |
| "这个报修工单走到哪一步了" | 关系 3 | 同 L4 下当前 L4X 状态 |
| "报修后下一步是啥" | 关系 3 | 当前 L4X 的后继 L4X |
| "这台变压器走完检修全过程耗时" | 关系 2+3 | 串起多个 L4X 计算时长 |
| "客户投诉处理进度" | 关系 3 | 沿 L4X 链推进状态 |

## 六、少量存在的边角场景（存在但很少）

| 场景 | 出现频率 |
|---|---|
| 跨 L2 主数据关联 | 很少 |
| 跨 L4 业务关联 | 很少 |
| 反向查询（关联实体→主实体） | 很少 |

> 这三类边角场景不是核心流程，按需特判。
