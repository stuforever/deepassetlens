# 交付体验演进 v2：纯结构化交付（用户定调版）

> 2026-08-24 · 设计窗口产出 · **v2 修订：推翻 v1 中「卡内流式」保留项**
> 用户原话定调：不要把未结构化的答案打印到输出屏幕上；生成期显示「答案生成中」，收尾期显示「答案整理中，正以结构化方式输出，请稍候」；不要重复打印结果。

---

## 一、v1 → v2 修订说明（诚实记录）

| | v1（单帧交付，2026-08-24 早） | v2（本版，用户定调） |
|---|---|---|
| 答案 token 流式 | 保留，流入卡内正文槽 | **全部取消**——answer_draft 不再上屏，任何形态都不进输出区 |
| 生成期输出区显示 | 骨架卡+槽内流式文字 | **纯状态行**：「答案生成中…」 |
| 收尾期（自评/整理） | 徽标「复核中」占位 | 状态行升级为：「答案整理中，正以结构化方式输出，请稍候…」 |
| 最终呈现 | done 补齐槽位 | done **一次性**渲染完整结构化卡（唯一一次打印） |

v1 的错误在于用「容器美化」保留了「过程暴露」；用户要的是**过程完全不可见、结果一次成型**。

## 二、输出区状态机（施工级定义，FreePlanChat）

```
事件驱动（后端 SSE 协议零改动，仅前端消费策略变化）：

提交              → status = 「正在理解问题…」
首个 tool_start   → status = 「检索数据中…」        （步骤明细照旧进 ThinkStream 折叠区）
first_answer_token→ status = 「答案生成中…」        ← answer_draft token 全部丢弃，不写 streaming_answer
answer_committed  → status = 「答案整理中，正以结构化方式输出，请稍候…」
                     ← 此状态天然覆盖 rubric 评分尾巴（12s 级）与收尾期
done              → 一次性渲染完整交付卡：
                    ┌ 查询结果 · 置信度徽标
                    ├ 数据表（全量）
                    ├ 结构化正文（结论/关键发现/风险建议）
                    └ 推荐追问 chips
rubric 事件       → 若晚于 done（B'-2 异步化后），徽标原地翻转，不再触发二次排版
```

**不变式：输出区在任何时刻要么显示状态行，要么显示完整交付卡，不存在第三种形态。**

## 三、为什么这个方向成立（三点支撑）

1. **等待长度已经被架构解决**：直通管道（L0）2~4s、锚定代理（L1）8~15s——状态行阶段的实际时长被飞轮持续压缩，「看状态行难受」的前提（长等待）正在消失；
2. **无重复打印由构造保证**：正文只有一个来源（done 时的结构化渲染），流式副本不复存在，v1 的「先裸文本后框架」两段式从机制上不可能再发生；
3. **成本极低**：批1-A 已实施的前端双写回退即可（不再把 token 写进 streaming_answer/气泡），后端事件协议一个字节不用改；新增的只是两条状态文案映射。

## 四、可选项（默认关）：表格提前入卡

`TUPU_EARLY_TABLE` 开关：sql_result 到达即把**表格**（结构化元素）先行入卡，正文仍等 done。冷题（45s+）可显著缓解等待感且不违反「未结构化不上屏」。默认关闭，观察冷题占比后再决定。

## 五、实施清单

| 步 | 改动 | 落点 | 量级 |
|---|---|---|---|
| ① | 撤销批1-A 双写：answer_draft 不再写 streaming_answer/气泡，改为驱动状态机 | FreePlanChat.tsx flushTokens/事件处理 | 0.5d |
| ② | 状态机四态文案 + done 一次性渲染交付卡 | AssistantCanvas/消息组件 | 0.5d |
| ③ | （沿用既有序）金标扩容喂直通 + B'-1 规则跳过 + B'-2 自评异步 | 见批10 原①②④ | 不变 |
| ④ | 可选 EARLY_TABLE 开关 | 前端 | 0.25d |

验收（Playwright e2e）：
- 全程输出区不出现任何逐字流式文本；
- answer_committed 与 done 之间可见「答案整理中，正以结构化方式输出，请稍候…」；
- done 后交付卡完整一次成型，无二次排版跳动；
- 直通路径端到端 <4s，状态行一闪而过。
