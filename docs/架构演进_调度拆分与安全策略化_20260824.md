# 第二部分：调度大文件拆分设计

## 现状

`data_intelligence_stream.py` 1059 行单文件，一个生成器函数 `chat_freeplan_stream()` 身兼七职：会话锁、预处理编排、事件翻译（最大块）、rubric 桥接、输出契约、evidence 聚合、SSE 收尾。改任何一段都要在巨型函数里找位置，回归风险高。

## 目标结构（包内拆分，对外路由与协议零变化）

```
backend/app/api/freeplan/
├── __init__.py           # 导出路由，路径仍为 POST /api/data-intelligence/freeplan/stream
├── endpoint.py           # FastAPI 端点 + 瘦编排器（只保留「步骤顺序」知识，~200 行）
├── session.py            # 会话锁 / agent 单例获取 / checkpoint 读写
├── prep.py               # 追问改写调用 + 路由调用 + 契约消息组装（产出 input_messages/rubric注入）
├── translator.py         # ★最大块：astream_events → SSE 归一化
│                         #   prefix 状态机(decision_draft/answer_draft/notes 过滤)、
│                         #   tool_end→sql_result/data_result 去重、transition、超时看门
├── delivery.py           # 输出契约校验/scrub、evidence 聚合、done 载荷、recommend
└── sse.py                # yield event 帧的小工具（format_sse 等）
```

## 拆分纪律

1. **行为零变化**：纯移动+重命名，不改任何逻辑分支；SSE 事件序列字节级一致（用现有 e2e 回归护航）；
2. **三步走，每步全绿再下一步**：
   - 第一步抽无状态纯函数（sse.py / delivery.py）——最安全；
   - 第二步抽有状态翻译器（translator.py，把 prefix 状态机封装成类）；
   - 第三步瘦身主干（endpoint.py 只留顺序编排）；
3. **测试同步**：注意有测试用字符串匹配源码断言装配（如 test_m3 断言 `"RubricMiddleware(model=..." in src`）——涉及 tupu_deepagent.py 时同步更新测试锚点；
4. 拆完后旧文件删陠除外，保留一个 deprecation 转发壳一个迭代周期防外部 import。

量级：1~1.5 天（含回归）。

# 第三部分：安全控制策略化（逐条函数化 + 后台可配）

## 设计原则（先把边界说死）

你要的灵活性我全部给，但有一条底线要保住：**后台配置本身不能成为绕过安全的门。** 所以六道控制分三级：

| 级别 | 控制 | 后台权限 |
|---|---|---|
| 🔴 红线级（只可看，不可关） | SQL 只读校验（SELECT-only+函数黑名单）、绝对禁止工具（task/write_file 等 6 个） | 管理页灰显展示+触发统计，无开关 |
| 🟡 策略级（可开可关，变更留审计） | 模板指纹守卫、引擎锁、stop_when 终止纪律、输出契约清洗、HITL 人审 | 开关+模式(block/warn/log)，每次变更写审计账 |
| 🟢 参数级（随时调数值） | LIMIT 上限(500)、纠错次数上限(2)、示例相似度阈值(0.85/0.90/0.95)、自评超时 | 数值输入即时生效 |

## 机制：守卫管道（Guard Pipeline）

### 统一接口（每个安全控制 = 一个独立类/函数）

```python
# app/services/guards/base.py
@dataclass
class GuardContext:
    contract: "QueryContract | None"
    tool_name: str
    tool_args: dict
    sql: str | None
    state: dict          # 引擎锁定记录/是否已获数据等运行时状态
    phase: str           # "pre_tool" | "pre_sql" | "post_answer"

@dataclass
class GuardResult:
    guard_id: str
    passed: bool
    reason: str = ""
    action: str = "block"    # block | warn | log

class Guard(Protocol):
    guard_id: str                      # 如 "template_fingerprint"
    tier: str                          # "redline" | "policy" | "param"
    def check(self, ctx: GuardContext) -> GuardResult: ...
```

### 六个守卫实现（逻辑不搬家，只包壳）

| guard_id | 包裹的现有实现 | 现位置 |
|---|---|---|
| whitelist | 契约 allowed/forbidden 检查 | skill_policy.py 内联段 |
| engine_lock | 引擎一致性比对 | skill_policy.py 内联段 |
| stop_when | 已获数据收窄 | query_contract+skill_policy |
| sql_safety | validate_sql（🔴） | secure_query_executor.py |
| template_fingerprint | 模板 AST 比对 | template_guard.py |
| output_contract | 明细清洗 | delivery 段 |

**原函数原封不动成为守卫的实现体——守卫只是统一接口的适配器+策略开关宿主。** 这样迁移风险最小，也符合「逻辑一处、策略多处引用」。

### 管道执行与策略解析

```python
# app/services/guards/registry.py
DEFAULT_PIPELINE = ["whitelist", "engine_lock", "stop_when",
                    "sql_safety", "template_fingerprint"]   # post_answer 阶段跑 output_contract

def run_guards(ctx: GuardContext) -> GuardResult:
    policy = load_policy()            # DB 读取+进程内缓存(TTL 5s)；读取失败→全默认启用(fail-closed)
    for gid in DEFAULT_PIPELINE:
        g = GUARDS[gid]
        p = policy.for_(gid)
        if not p.enabled:             # 红线级忽略此开关（load_policy 强制 True）
            continue
        r = g.check(ctx)
        if r.passed:
            continue
        if p.mode == "log":
            audit(gid, r, ctx); continue
        if p.mode == "warn":
            audit(gid, r, ctx); emit_warning(r); continue   # 放行但记录+提示
        return r                          # block：短路返回拒绝
    return GuardResult(guard_id="pipeline", passed=True)
```

- SkillPolicyMiddleware 内部改为调用 `run_guards(phase="pre_tool")`——中间件壳保留（挂载点不变），检查逻辑全部走管道；
- secure_query_executor 在执行前调 `run_guards(phase="pre_sql")`；
- delivery 段调 `run_guards(phase="post_answer")`。

### 后台配置页（管理端新增「安全策略」）

```
┌──────────────────┬──────┬───────────┬──────────────────┐
│ 守卫             │ 级别 │ 状态       │ 近24h 触发         │
├──────────────────┼──────┼───────────┼──────────────────┤
│ SQL只读校验       │ 红线 │ 🔒强制启用  │ 拦截 12 次         │
│ 绝对禁止工具      │ 红线 │ 🔒强制启用  │ 拦截 0 次          │
│ 模板指纹守卫      │ 策略 │ [启用▼模式:block] │ 拦截 3 次    │
│ 引擎锁           │ 策略 │ [启用▼warn] │ 警告 1 次          │
│ stop_when        │ 策略 │ [启用▼block]│ 拦截 5 次          │
│ 输出契约清洗      │ 策略 │ [启用▼block]│ 清洗 2 次          │
├──────────────────┴──────┴───────────┴──────────────────┤
│ 参数：LIMIT上限[500] 纠错上限[2] 锚定阈值[0.85] 直通阈值[0.95] │
└────────────────────────────────────────────────────────┘
每次变更：写 governance 审计(谁/何时/改了什么) + 即时生效(缓存失效)
```

### 数据模型

```sql
CREATE TABLE guard_policies (
  guard_id   VARCHAR(64) PRIMARY KEY,
  enabled    BOOLEAN NOT NULL DEFAULT TRUE,
  mode       VARCHAR(16) NOT NULL DEFAULT 'block',   -- block|warn|log
  params     JSON NULL,                              -- 参数级的数值
  locked     BOOLEAN NOT NULL DEFAULT FALSE,         -- 红线级=TRUE，API 层拒改
  updated_by VARCHAR(64), updated_at DATETIME,
  remark     VARCHAR(255)
);
```
