## 一、目标与原则

1. SKILL.md 变更后，**不重启**，下一次请求即拿到完全一致的新内容——兑现 13-Y「改剧本=下次请求重装配」的完整承诺；
2. 文件未变时行为**逐字节不变**——保住 13-G「同 skill_id+步骤同内容逐字节一致」前缀缓存契约（13-I C1）；
3. 机制零新增：不引入 watchdog/文件监视新依赖（YAGNI）；新鲜度信号沿用仓内既有先例；
4. 公开签名零变化：两个生产调用点、4 个单测、1 个调试脚本全部零改动或零语义变化。

## 二、方案对比（三选一）

| 方案 | 内容 | 裁决 |
|---|---|---|
| **一（推荐）** | **指纹键缓存**：缓存键带上文件指纹，文件变→键变→自然失效 | ✅ 机制零新增、热路径开销仅 stat、13-G 契约天然保持 |
| 二 | 重装配钩子 `cache_clear()`：Agent 缓存未命中重建时清 `_load_skill_md` 缓存 | ❌ 否决：契约消息构建（每请求）与 Agent 获取（缓存键判定）非同一钩子，时序对不齐；且一次清空全部技能缓存（跨技能爆炸半径）；把文本缓存耦合进 Agent 缓存链 |
| 三 | AGENTS.md 运维铁律「改 SKILL.md 必重启」 | ❌ 不作主案：把 13-Y 设计承诺降级为运维纪律，files_hash 机制的存在意义被架空；仅作本件落地前的**过渡登记**（实施前建议先在 AGENTS.md 加一行，落地后删除） |

**指纹信号选择：`(st_mtime_ns, st_size)`**（stat 即得，不读文件内容）。依据：`_compute_files_hash` 已用 mtime+size 作为 **Agent 整体重装配**的触发信号（L398，且是秒级 mtime，粒度更粗）——若该信号足以信任到触发全量重装配，则足以触发文本缓存失效；同信号族同语义，本设计用 `st_mtime_ns`（100ns 粒度）严格更精细。SkillCatalog 的 sha256 先例（L217-218）面向低频目录加载（每次全读文件），不适配本处每请求热路径（读盘换失效检测，得不偿失）。

**逐条性质论证**：
- **新鲜度**：文件任何改动 → mtime_ns/size 变 → 新缓存条目 → 新正文；旧条目留待 maxsize 淘汰（32×~50KB ≈ 1.6MB 上限，可忽略）；
- **13-G 同一性契约**：文件不变 → 指纹不变 → 同一缓存条目 → 同一字符串对象 → `test_load_skill_md_cached` 的 `is` 断言保持绿，13-I C1 前缀缓存逐字节一致保持；
- **子技能降级共享**：键用 resolved_path 后，`distribution-overload-impact/-power/-link/-verdict` 五个名字解析到同一文件 → 共享一条缓存（现状是五条，反而省）；
- **调用点零改动**：data_intelligence L241 / tupu_deepagent L443 签名不变；
- **注释修正**：L276「文件运行期只读，缓存安全」改为「指纹键缓存：mtime_ns+size 变化即失效（对齐 _compute_files_hash 信号族），改剧本不重启下次请求生效」。

### 件2：`_GUIDANCE_SECTIONS` 指纹感知

**现状**（query_contract.py L377-407）：模块级 `_GUIDANCE_SECTIONS` 首次调用解析后永久冻结。

**改法**（global 名保留，`_b2_debug.py` 导入不破）：

```python
_GUIDANCE_SECTIONS: Optional[Dict[str, str]] = None
_GUIDANCE_SIG: Optional[tuple] = None   # (mtime_ns, size)

def _load_guidance_sections() -> Dict[str, str]:
    global _GUIDANCE_SECTIONS, _GUIDANCE_SIG
    try:
        st = os.stat(_SKILL_SQL_QUERY_PATH)
        sig = (st.st_mtime_ns, st.st_size)
    except OSError:
        return _GUIDANCE_SECTIONS or {}          # 文件消失：沿用旧值（与现状容错语义一致）
    if _GUIDANCE_SECTIONS is not None and _GUIDANCE_SIG == sig:
        return _GUIDANCE_SECTIONS                 # 未变：命中（现状行为）
    # —— 原 L388-405 解析逻辑原样执行，成功后 ——
    _GUIDANCE_SIG = sig                           # 解析失败时 sig 不写，下次重试（与现状略优）
    return _GUIDANCE_SECTIONS
```

单文件单 global，最小 diff；每请求多一次 stat（µs 级）。

## 五、风险登记

| 风险 | 评估 |
|---|---|
| 同 tick 双改（mtime_ns 不变内容变） | NTFS mtime_ns 粒度 100ns，实际不可达；且 `_compute_files_hash` 用**秒级** mtime 已接受同风险面触发全量重装配——本设计粒度严格更细 |
| ⟦⟧ 实体解析的元数据维度 | 缓存值含 `_resolve_entity_refs` 结果，**元数据**漂移（表改名）不触发失效——现状 lru_cache 同样冻结，本设计不放大不解决；表改名通常伴随 SKILL.md frontmatter（entity_aliases）同步修改，届时文件指纹自然连带失效 |
| 每请求 stat 开销 | µs 级，登记可忽略；技能库若未来膨胀到千级文件再评估 stat fast-path 之外的方案（YAGNI） |
| 多 worker 未来 | 指纹键天然各自收敛（各 worker stat 各自文件），无跨进程一致性问题 |
