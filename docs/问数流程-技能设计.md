# 问数流程 — 技能设计文档

> 版本：v1.0
> 案例：「用电客户的名称、用能地址、联系电话、证件类型、证件号码等信息」
> 核心原则：业务逻辑全写在技能里，LangGraph 节点只做转译

---

## 1. 整体流程

首页拆两个功能入口：**问数**（📊 蓝）/ **知识问答**（📚 绿），砍掉 boss_router 二分类。

问数流程 3 步，全程 LangGraph + 技能编排：

```
START → locate_l2 → locate_entity_attr → sql_assembly → END
         （定L2）     （子图全量给LLM      （拼SQL，已有技能）
                        定实体+属性）
```

每个节点 = 一个技能（`data/skills/{code}/`），节点函数只调 `mod.execute()`，不写业务。

## 2. 技能与技能管理的关系

**是同一套**。`backend/data/skills/` 既是技能管理平台的文件存储层，又是 LangGraph 运行时的脚本源：

```
前端技能管理 ──→ /api/v2/skills ──→ Skill表 ──→ 同步写 data/skills/{code}/五件套
LangGraph节点 ──→ importlib 加载 data/skills/{code}/scripts/main.py 的 execute()
```

每个技能五件套：`SKILL.md` + `scripts/main.py` + `assets/input_schema.json` + `assets/output_schema.json` + `references/`。

## 3. 技能1：locate_l2（确定 L2 业务域）

### 输入
```json
{"user_query": "用电客户的名称、用能地址、联系电话..."}
```

### 输出
```json
{
  "status": "locked | candidates | needs_clarification",
  "l2_name": "用电客户",
  "l2_id": "uuid",
  "confidence": 0.95,
  "candidates": [{"l2_name":"","l2_id":""}],
  "reason": "用户问用电客户"
}
```

### execute 逻辑
1. `fn = _injected("_injected_fetch_l1_l2_tree")` → 拿 L1-L2 全量（22条）
2. 拼文本：`"L1:客户 → L2:用电客户、发电客户..."`
3. `client = _injected("_injected_llm_client")` → 调 LLM 匹配 L2
4. 置信度分流：≥0.8 locked / 0.5~0.8 candidates / <0.5 needs_clarification

### System Prompt
```
你是业务域定位器。根据用户问句匹配最相关的 L2。
规则：多个可能→confidence<0.8+candidates；无匹配→confidence=0
输出JSON：{l2_name, l2_id, confidence, candidates, reason}
```

### 沙箱注入
`build_fetch_l1_l2_tree()`：查 `kg_concepts` level=1/2，组装 `{L1_name: [{L2_name, L2_id}]}`。

## 4. 技能2：locate_entity_attr（L2 子图全量给 LLM）

### 以 L2 为起点的子图
```
L2（起点）
├── L2X 实体（Entity.concept_id = L2.id）
│   └── 每个实体的全部属性（properties_schema）
└── 跨链（ConceptRelation source/target = L2.id）
    └── L3 / L4
        └── L4X 实体（Entity.concept_id = L3/L4.id）
            └── 每个实体的全部属性
```

案例数据：L2=用电客户 → 9 个 L2X 实体 + 512 个属性，全量给 LLM。

### 输入
```json
{"user_query": "...", "l2_id": "uuid"}
```

### 输出
```json
{
  "status": "locked | candidates | needs_clarification",
  "entity_code": "dim_cst_elec_cons_cust",
  "entity_name": "用电客户主数据联接表",
  "attributes": [{"attribute_code":"cons_name","attribute_name":"客户名称"}],
  "confidence": 0.9,
  "candidates": [],
  "reason": "..."
}
```

### execute 逻辑
1. `fn = _injected("_injected_fetch_subgraph_by_l2")` → 拿完整子图
2. 拼子图文本（全量）：实体名 + is_main_table + 全部属性列表
3. `client = _injected("_injected_llm_client")` → 调 LLM 匹配实体+属性
4. 置信度分流

### System Prompt
```
你是实体属性定位器。用户已确定L2，基于子图确定实体和属性。
规则：is_main_table优先；匹配用户问句涉及的属性；不确定→confidence<0.8+candidates
输出JSON：{entity_code, entity_name, attributes, confidence, candidates, reason}
```

### 沙箱注入
`build_fetch_subgraph_by_l2(l2_id)`：
1. `SELECT * FROM kg_entities WHERE concept_id={l2_id}` → L2X 实体 + properties_schema
2. `SELECT * FROM kg_concept_relations WHERE source_concept_id={l2_id} OR target_concept_id={l2_id}` → 跨链 L3/L4 → 再查 L4X

## 5. LangGraph 节点转译

节点函数只调 execute + 写回 state，不写业务：

```python
def locate_l2_node(state):
    sec = _sec_from_dict(state["secretary_state"])
    mod = _get_new_skill_module("locate_l2")
    result = mod.execute({"user_query": sec.user_input})
    sec.confirmed.L2 = result.get("l2_name")
    sec.confirmed.L2_id = result.get("l2_id")
    # pending_clarification 按置信度设置
    return {"secretary_state": secretary_state_to_dict(sec)}

def locate_entity_attr_node(state):
    sec = _sec_from_dict(state["secretary_state"])
    mod = _get_new_skill_module("locate_entity_attr")
    result = mod.execute({"user_query": sec.user_input, "l2_id": sec.confirmed.L2_id})
    sec.confirmed.L2X = result.get("entity_code")
    sec.confirmed.attributes = result.get("attributes")
    return {"secretary_state": secretary_state_to_dict(sec)}
```

## 6. 案例跑通预演
