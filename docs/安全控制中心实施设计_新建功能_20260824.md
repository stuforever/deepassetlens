# 安全控制中心实施设计：新建功能（前端管理页 + 后端 API）

> 2026-08-24 · 设计窗口产出 · 《安全控制中心设计_五类控制模式v2》的实施细化
> 回答的问题：关闭/开启做成**新建功能**还是仅后台？--**新建功能**（前端 /security-controls 管理页 + 后端 /api/guards/* + guard_policies/guard_events 两表），理由与全量设计如下。

---

## 一、形态决策

| 方案 | 能否满足四诉求 | 评估 |
|---|---|---|
| 仅后台（API/DB/环境变量） | ❌ 「有按钮说明」「试探单一键验证」无法承载；每次操作要 curl | 否决 |
| 配置文件+重启 | ❌ 无热生效、无审计、无统计 | 否决 |
| **新建功能（管理页+API）** | ✅ 四诉求全是交互诉求，天然页面形态 | **采纳** |

工程成本可控的原因：前端已有 Manager 页面家族成熟模式（QaExamplesManager/SkillManagerV2/LLMConfigManager 同款），复用 `PageShell/StatusTag/DataTableShell/DrawerFooter` 组件族与 `services/api` 集中模块、antd 组件库，**零新依赖**，完全符合 YAGNI 分层（平台原生优先）。

## 二、后端设计

### 2.1 数据模型（新建迁移 0013_guard_policies.sql）

```sql
CREATE TABLE guard_policies (
  guard_id        VARCHAR(64)  PRIMARY KEY,   -- capability|sql_safety|template|engine_lock|output|approval_track
  title           VARCHAR(64)  NOT NULL,      -- 能力控制/SQL 安全控制/模板控制/引擎控制/输出控制/审批轨
  enabled         BOOLEAN      NOT NULL DEFAULT TRUE,
  mode            VARCHAR(16)  NOT NULL DEFAULT 'block',   -- block|warn|log（policy 级用）
  params          JSON         NULL,          -- {"limit_max":500,"func_blacklist":[...],"tools":[...] }
  risk_level      VARCHAR(8)   NOT NULL DEFAULT 'yellow',  -- red|yellow|green（决定前端确认强度）
  description     JSON         NULL,          -- {"what":"...","lose":"...","remain":"..."} 三段式说明
  confirm_required BOOLEAN     NOT NULL DEFAULT TRUE,
  updated_by      VARCHAR(64)  NULL, updated_at DATETIME NULL,
  close_reason    VARCHAR(500) NULL,          -- 红级关闭必填
  version         INT          NOT NULL DEFAULT 1          -- 配置版本号（热生效+审批轨重建依据）
);
INSERT INTO guard_policies (guard_id,title,risk_level,...) VALUES
  ('capability','能力控制','red',...),('sql_safety','SQL 安全控制','red',...),
  ('template','模板控制','yellow',...),('engine_lock','引擎控制','yellow',...),
  ('output','输出控制','yellow',...),('approval_track','审批轨','green',...);

CREATE TABLE guard_events (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  guard_id VARCHAR(64) NOT NULL, ts DATETIME NOT NULL,
  action VARCHAR(16) NOT NULL,               -- block|warn|pass|probe|toggle|reset
  question_digest VARCHAR(200) NULL,         -- 脱敏摘要（block/warn 记触发题）
  verdict VARCHAR(16) NULL,                  -- blocked|passed|probe_ok|probe_fail
  detail JSON NULL, updated_by VARCHAR(64) NULL
);
```

### 2.3 API 层 `app/api/guards.py`（新建路由，挂 main router）

| 端点 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/api/guards` | GET | - | `{items:[{guard_id,title,enabled,mode,params,risk_level,description,confirm_required,stats:{h24,h7d,last_block_at},version}],global_version}` |
| `/api/guards/{guard_id}` | PATCH | `{enabled?,mode?,params?,confirm:true,close_reason?}` | 更新后的 item；红级关闭缺 reason -> 400 `{detail:"需填写关闭理由"}` |
| `/api/guards/{guard_id}/probe` | POST | - | `{verdict:"probe_ok"\|"probe_fail", blocked_reason?, elapsed_ms}` |
| `/api/guards/events` | GET | `?guard_id=&range=24h\|7d&page=` | 分页事件表（含 toggle/probe/block） |
| `/api/guards/reset-defaults` | POST | - | `{items:[...]}` |

权限：所有端点经现有 `get_current_user`；非 admin 角色 -> GET 可读、PATCH/probe/reset 返回 403（前端对非 admin 禁用开关并 Tooltip 提示）。

### 2.5 与守卫管道接线

run_guards 每次执行读 `guard_config.get_policies()`（TTL 5s）；守卫被关闭 -> 跳过该守卫；每次 block/warn 写 guard_events（异步 fire-and-forget，不阻塞主链路）。批13-E 的六守卫 guard_id 归并为五类对外（capability 内含 whitelist/absolute_tools/stop_when 三个内部检查，共享一个开关，事件记录细分到内部 id）。

### 3.2 `services/api.ts` 扩展
```ts
export interface GuardItem { guard_id: string; title: string; enabled: boolean;
  mode: string; params: Record<string, unknown>; risk_level: 'red'|'yellow'|'green';
  description: { what: string; lose: string; remain: string };
  confirm_required: boolean; stats: { h24: number; h7d: number; last_block_at?: string }; version: number }
export const guardsApi = {
  list: () => request.get<GuardItem[]>('/api/guards'),
  update: (id, body) => request.patch(`/api/guards/${id}`, body),
  probe: (id) => request.post(`/api/guards/${id}/probe`),
  events: (params) => request.get('/api/guards/events', { params }),
  resetDefaults: () => request.post('/api/guards/reset-defaults'),
}
```

### 3.4 关闭确认流程（风险分级）

```
绿级（参数/审批轨开关）：Switch 直接切 -> PATCH
黄级：Switch off -> Modal（三段说明+「确认关闭」）-> PATCH
红级：Switch off -> Modal①（三段说明+红色警示+剩余防线）->「我已了解风险」
             -> Modal②（理由 textarea 必填，<10 字不让提交）-> PATCH(confirm,close_reason)
开启方向：一律直接切（开是回到安全态，无需仪式）
```

### 3.5 试探单交互
点击 -> 按钮 loading -> 结果 Banner（页面级 message + 卡片角标）：
- ✓「已拦截：UPDATE 语句被 SQL 安全控制拦截（1.2s）」绿色 -- 控制生效凭证；
- ✗「未拦截：探针通过！该控制当前未生效」红色 message.error + 卡片描红 -- 立即暴露摆设开关。
连续 ✗ 两次 -> 提示检查配置与 run_guards 接线。

## 四、关键时序（热生效链路）

```
管理页 Switch -> PATCH /api/guards/{id} -> guard_config.update_guard（version+1, 写 events）
-> TTL 缓存 5s 内自然过期 -> run_guards 下一次调用读到新配置
（审批轨例外：version 变化 -> agent 单例缓存键失配 -> 下一次请求按新 interrupt_on 重建）
```

## 五、e2e 验收（Playwright，`_pw_e2e.py` 串行纪律）

1. 打开 /security-controls：六张卡默认全开、统计可见、说明可展开；
2. 点 sql_safety 试探单 -> 页面出现 ✓已拦截，guard_events 有 probe_ok；
3. 黄级关闭模板控制（确认 Modal）-> 再点试探单 -> ✗未拦截 -> 重新开启 -> ✓恢复；
4. 红级关闭 sql_safety：不填理由提交被阻（400/表单校验），填理由后成功，尾部变更条显示理由；
5. 全部恢复默认 -> 六卡回到开启+基线参数；
6. 非 admin 账号：开关禁用+Tooltip，PATCH 返回 403。

## 六、边界与不做清单

- 不做守卫编排器 UI（顺序编辑）--固定管道顺序，YAGNI；
- 不做守卫代码热插拔--五类守卫是编译期函数注册表，页面只控开关/参数；
- guard_events 只留 30 天（定时清理任务，防止表膨胀）；
- 导出配置=JSON 快照下载，配置版本化入 git 由管理员手工执行（不做自动 git 集成）。
