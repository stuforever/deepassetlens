## 1. 系统总览

### 1.1 系统架构

```
┌─────────────────────────────────────────────────────────┐
│                    前端 (React + Antd)                    │
│  localhost:3000                                          │
├──────────────┬──────────────┬───────────────────────────┤
│ 数据智能对话  │ 向量管理 Tab │ 语义管理 / 图谱管理 ...    │
├──────────────┴──────────────┴───────────────────────────┤
│                    后端 (FastAPI :8100)                  │
│  ┌─────────────────────────────────────────────────┐   │
│  │  LangGraph StateGraph（11 节点）                 │   │
│  │  boss_router → {实体定位/属性定位/SQL拼装/       │   │
│  │                 SQL执行/分类查询/探索/兜底}      │   │
│  └─────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────┤
│  Neo4j (图谱)  │  MySQL (元数据)  │  Qdrant (向量库)    │
└────────────────┴──────────────────┴────────────────────┘
```

### 1.2 核心能力（5 大需求）

| # | 能力 | 实现方式 | 状态 |
|---|---|---|:---:|
| 1 | 灵活问元数据 | 分类查询任务（children/fields/relations/subtree） | ✅ |
| 2 | 灵活定位实体 | S1/S2/S3 三步漏斗 + 向量库召回 | ✅ |
| 3 | 灵活定位属性 | find_attribute + 属性向量库 | ✅ |
| 4 | 灵活形成 SQL | assemble_sql + llm_sql_filter（LLM 转 WHERE） | ✅ |
| 5 | 灵活执行 SQL | execute_sql SELECT-only + 表格化结果 | ✅ |

## 3. 场景一：灵活问元数据（分类查询）

### 3.1 用户意图

> "我想知道 L1-CUSTOMER 下面有哪些子分类"  
> "客户档案实体有哪些字段"  
> "客户和设备之间有什么跨链关系"

### 3.2 操作步骤

1. **进入数据智能对话**
   - 点击左侧菜单「扩展能力」→「数据智能对话（新版）」

2. **输入问句**（在底部输入框）
   ```
   L1-CUSTOMER 下有哪些子分类
   ```

3. **点击「发送」按钮**

4. **查看结果**
   - 系统返回「分类查询结果」卡片
   - 卡片含查询类型标签（蓝色=直接子分类）
   - 表格列出 4 个 L2 子分类：
     ```
     L2-CUSTOMER-ARCHIVE   客户档案   L2   主数据链
     L2-CUSTOMER-CONTRACT  客户合同   L2   主数据链
     L2-CUSTOMER-ORDER     客户订单   L2   主数据链
     L2-CUSTOMER-SERVICE   客户服务   L2   主数据链
     ```

> 📸 截图参考：`e2e/_screenshots/S1-03-after-send.png`

### 3.3 4 种查询模式关键词

| 查询类型 | 触发关键词 | 示例问句 |
|---|---|---|
| **children** | "下有哪些"、"子类"、"子分类"、"下属" | "L1-CUSTOMER 下有哪些 L2" |
| **fields** | "字段"、"属性"、"列名"、"有哪些列" | "L2X-CUSTOMER-ARCHIVE 有哪些字段" |
| **relations** | "关系"、"关联"、"跨链"、"RELATES_TO" | "L2X-CUSTOMER-ARCHIVE 的跨链关系" |
| **subtree** | "整棵"、"子树"、"全部"、"所有"、"树" | "L1-CUSTOMER 整棵子树" |

## 4. 场景二：灵活定位实体

### 4.1 用户意图

> "查下客户" / "看下客户档案" / "客户资料在哪"

### 4.2 操作步骤

1. 进入数据智能对话
2. 输入：`查客户`
3. 点击发送
4. **预期行为**（配了 MINIMAX_API_KEY 后）：
   - boss_router 路由到「实体定位」任务
   - S1 向量库召回 → 匹配 L1-CUSTOMER
   - 中断卡弹出：确认是否锁定"客户"链
5. **未配 LLM key 时**：
   - 返回 503 错误："老板路由技能失败（不降级）：MINIMAX_API_KEY 未配置"

### 4.3 显式任务切换（绕过 LLM）

如果未配 LLM key，可用显式任务切换：

- 在输入框输入 `查客户`
- 点击下方的「任务切换」按钮（或快捷选项）
- 选择「实体定位」
- 系统走最短路径，直接执行实体定位任务

> 💡 这是 boss_router 不可用时的降级操作路径

## 5. 场景三：灵活定位属性

### 5.1 用户意图

> "查询用电客户的用电客户标识、行业分类、重要性等级、联系电话"

### 5.2 操作步骤

1. 进入数据智能对话
2. 先锁定实体（通过实体定位任务）
3. 输入属性查询问句
4. 系统调 find_attribute 技能：
   - 向量库召回（Qdrant `attribute_embeddings` collection，5400 条属性）

5. 返回属性候选列表，用户确认锁定

### 5.3 数据依赖

属性向量库需先灌库（见场景七）：

```bash
curl -X POST "http://127.0.0.1:8100/api/v1/vector/sync-attributes?extract_first=true"
```

## 6. 场景四：灵活形成 SQL（含 LLM WHERE）

### 6.1 用户意图

> "查上海地区最近 30 天的客户"  
> → 自动生成 `SELECT ... FROM ... WHERE REGION='上海' AND CREATE_TIME >= '2026-05-23'`

### 6.2 工作流程

```
用户问句 + 已锁实体/属性
        ↓
   assemble_sql 技能
        ↓
   (无 filters 时) 调 llm_sql_filter 技能
        ↓
   LLM 解析自然语言 → 结构化 WHERE 条件
        ↓
   Pydantic 校验（op 必须 ∈ =,!=,>,>=,<,<=,LIKE,IN,IS NULL）
        ↓
   3 次重试（不合规自动重试）
        ↓
   生成完整 SQL
```

### 6.3 操作步骤

1. 先完成实体定位 + 属性定位（锁定 TEL 字段）
2. 进入 SQL 拼装任务
3. 输入自然语言条件：`上海地区客户编号=12345`
4. 系统生成 SQL：
   ```sql
   SELECT TEL FROM dim_cst_elec_cons_cust
   WHERE REGION = '上海' AND CUST_NO = '12345'
   LIMIT 100
   ```

### 6.4 LLM 不可用时

- llm_sql_filter 返回空 filters
- assemble_sql 走默认 SELECT（无 WHERE）
- 用户可手动在前端补 filters

## 7. 场景五：灵活执行 SQL（表格化结果）

### 7.1 操作步骤

1. SQL 拼装完成后，进入 SQL 执行任务
2. 点击「执行」按钮
3. 结果以表格形式展示：

### 7.2 结果卡片功能

```
┌─ SQL 执行结果 ───────────────── 5 行 | 120ms ─┐
│ [复制 SQL] [导出 CSV] [重跑]                  │
│ ┌──────────────────────────────────────────┐ │
│ │ SELECT TEL FROM ... WHERE ...            │ │
│ └──────────────────────────────────────────┘ │
│ ┌──────────┬──────────┬──────────┐          │
│ │ CUST_NO  │ TEL      │ REGION   │          │
│ ├──────────┼──────────┼──────────┤          │
│ │ 12345    │ 138xxxx  │ 上海     │          │
│ │ 12346    │ 139xxxx  │ 上海     │          │
│ └──────────┴──────────┴──────────┘          │
│ 共 2 行                       < 1 2 3 >     │
└──────────────────────────────────────────────┘
```

**功能按钮**：
- **复制 SQL**：一键复制 SQL 到剪贴板
- **导出 CSV**：下载 UTF-8 BOM 编码的 CSV（Excel 直接打开不乱码）
- **重跑**：重新执行相同 SQL

### 7.3 安全校验

- 仅允许 SELECT 语句
- 拒绝 DELETE/UPDATE/DROP/ALTER 等
- 结果超过 10000 行自动截断

## 10. 场景八：boss_router 路由（LLM 不可用 503）

### 10.1 设计原则（老板要求）

> **LLM 不可用就报错，不降级！**

### 10.2 测试步骤

1. 进入数据智能对话
2. 输入：`查客户`（不配 MINIMAX_API_KEY）
3. 点击发送
4. **预期结果**：
   - HTTP 503 错误
   - 错误信息：`调用失败: 老板路由技能失败（不降级）：MINIMAX-M3 调用失败: MINIMAX_API_KEY 未配置，无法调用 LLM`
   - antd `message.error` toast 弹出

### 10.3 控制台日志（Playwright 实采）

```
[error] Failed to load resource: the server responded with a status of 503 (Service Unavailable)
[error] data intelligence chat failed AxiosError: Request failed with status code 503
```

### 10.4 测试结果

```
[S3] ✓ boss_router 503 错误可见
[S3] ✓ 503 场景无崩溃
```

### 10.5 配置 LLM key 后

```bash
# 环境变量
export MINIMAX_API_KEY=your_key
export MINIMAX_ENDPOINT=https://api.minimaxi.com/v1/text/chatcompletion_v2
export TUPU_LLM_BASE_URL=https://api.minimaxi.com/v1
export TUPU_LLM_API_KEY=your_key
export TUPU_LLM_MODEL=MiniMax-M3

# 重启后端
```

配置后 boss_router 会正常路由，不再 503。

## 13. 常见问题排查

### Q1: 点击「数据智能对话」后看不到输入框

**原因**：页面未加载完  
**解决**：等待 2-3 秒，或刷新页面

### Q2: 发送消息后一直 loading

**原因**：后端未启动 / boss_router 调 LLM 超时  
**解决**：
```bash
curl http://127.0.0.1:8100/api/v1/vector/attribute-stats
# 不通则启动后端
cd backend && py __start_8100.py
```

### Q3: 提示 "MINIMAX_API_KEY 未配置"

**原因**：这是**预期行为**（老板要求 LLM 不可用就报错）  
**解决**（如需启用 LLM）：
```bash
# Windows PowerShell
$env:MINIMAX_API_KEY="your_key"
$env:TUPU_LLM_BASE_URL="https://api.minimaxi.com/v1"
$env:TUPU_LLM_API_KEY="your_key"
$env:TUPU_LLM_MODEL="MiniMax-M3"
# 重启后端
```

### Q4: 实体向量化 Tab 显示"总数: 0"

**原因**：未跑过提炼+向量化  
**解决**：点击「提炼 + 向量化」按钮

### Q5: 属性向量化 Tab 显示"总数: 0"

**原因**：未跑过属性提取  
**解决**：
```bash
curl -X POST "http://127.0.0.1:8100/api/v1/vector/sync-attributes?extract_first=true"
```

### Q6: 503 错误但想测试分类查询

**解决**：用显式任务切换绕过 boss_router
- 输入问句后，选择「分类查询」任务
- 系统走最短路径直接执行
