## 1. 概述

按《受控问答平台提升设计》实现代码。核心三原则落地：

1. **SKILL.md 是唯一业务来源** —— `SkillCatalog` 解析，不双维护；
2. **代码路由 + Policy 是唯一执行裁判** —— `SkillRouter` 确定性路由 + `SkillPolicyMiddleware` 硬校验，模型不拍板引擎/工具/是否终止；
3. **模型只在裁判允许范围内工作** —— 每次请求注入受控契约（SystemMessage + runtime.context），越权即拒绝，二次违规阻断。

## 4. 关键设计实现说明

1. **契约传递链**：`data_intelligence` 路由建契约 → `_ctx["contract"]` 注入 runtime.context（SkillPolicy 读取的唯一边界）+ SystemMessage 告知模型 → SSE `route`/`contract` 事件 + done 携带 → 前端渲染。
2. **引擎唯一选择**：`batch_entity_source_mode` 真实返回 → `query_engine_router.resolve_engine` 判定 → `contract.lock_engine` 收窄 allowed_tools（引擎确认后其他查询工具立即失效）。
   - **多引擎（批4 剩余项）**：技能声明 `multi_engine:true`（project-lifecycle-cost 预算 duckdb + 成本 doris）→ `resolve_engines_multi` 按 batch items 逐实体 source_mode 推导引擎集合 → `contract.confirm_engines` 并入集合、allowed_tools 收窄为已确认引擎工具并集（两源并存，禁跨源 JOIN）。
3. **模板校验的实体引用**：模板内 `⟦业务中文名⟧` 由 SKILL.md `x_tupu.entity_aliases` 解析为物理表名（运行时再叠加精确 entity_name 解析兜底），保证"候选 SQL 表集合 ⊆ 模板表集合"可比对。
4. **UNION 合规**：模板自身用 UNION ALL（用电户/发电户两段合并），故不一刀切拒绝 UNION；防绕过靠表集合校验（UNION 引入模板外表必然被拦截）。
5. **输出契约**：清洗由契约 `forbid_markdown_detail_table` 门控（distribution-overload=true 剥离答案明细表；project-lifecycle-cost=false 保留跨源汇总对比表），并记录 `output_scrubbed` 旗标。
6. **模板指纹（批4 剩余项）**：候选/模板各自规范化结构骨架（字面量→`?`、丢弃注释）后取 sha256 指纹比对 —— 模板派生（字面量级等价/仅参数注入差异）→ `structure_match=true` 高置信；同表集合但骨架不同（如擅改 GROUP BY/JOIN）→ 结构漂移审计信号（不硬拒，表集合仍是硬闸门）；残留 `/* {{param}} */` 未渲染 → 标记。

#### 9.7.3 P2 模板事件可等待派发（确定性顺序）

- 根因：`_record_template_bind` 用 `create_task` 后台派发 template.bound/drift → 顺序/必达性不稳、取消时丢事件。
- 修复：`_precheck` / `_check_sql_against_templates` / `_record_template_bind` 全部转 async，模板事件在 `await handler(request)` **之前** await 派发，保证确定性顺序 `template.bound/drift → tool.started → tool.completed`（与 `_do_reject` 同一 `_emit` 机制，运行上下文内可靠投递）。
