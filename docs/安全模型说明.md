## 一、exec 白名单威胁模型

### 1.1 设计前提（本平台采用）

```
威胁模型 = 可信作者 + 白名单 + 不可信输入隔离
```

- **可信作者**：技能（Skill）由平台管理员/受控作者创建与维护，`skill_governance` 对上线有审批流；技能代码不直接接受终端用户的任意脚本输入。
- **白名单**：技能代码只在受限命名空间内执行（见 1.2/1.3），内置函数/模块按需放行，网络与文件系统默认关。
- **不可信输入隔离**：终端用户的自然语言输入只作为**数据**传入技能 `run(inputs)`，不进入可执行代码路径；用户无法编写或注入代码。

### 1.2 沙箱执行器（`core/execution_engine_support.py::SandboxExecutor`）

- **允许的内置名**：数值/容器/函数式工具（abs/all/any/map/filter/sorted/zip/...）+ 常用异常类；白名单常量 `ALLOWED_BUILTIN_NAMES`。
- **按权限裁剪**：`permissions.network=false` → 剔除 `open/__import__`；`permissions.filesystem=false`（默认）→ 剔除 `open/file`。
- **I/O 重定向**：`print` 被替换为 `_sandbox_print`（写入日志缓冲）；`open` 被 `_forbidden_open` 拦截报错。
- **可用模块**：`json/re/datetime/traceback`（只读工具），其余模块不可 import。
- **资源护栏**：`execute(timeout=30, resource_limits)` 限时执行；编译结果缓存（5.3 依赖预热）。

### 1.3 Python 技能执行（`api/smart_skill_pipeline.py` `kind=="python"`）

- 受限命名空间 `__builtins__` 仅含：`len/min/max/sum/str/int/float/bool/dict/list/print/range/enumerate/json`（无 `open/__import__/eval/exec` 自身）。
- `exec(code, safe_globals, local_vars)` 后调用约定入口 `run(payload, context)` 或读取 `output`；技能代码为管理员写入，非用户输入。

### 1.4 边界（当前未覆盖，需明确认知）

- 本模型**不防恶意作者**：持有技能编辑权的作者可写出任意代码（含逃逸尝试）。这是"可信作者"前提下的刻意取舍。
- **若未来开放技能编辑权给不可信用户，必须先做**：
  1. 技能代码改为**声明式 DSL / 模板渲染**（如 SKILL.md + SQL 模板），移除自由 Python `exec`；
  2. 或引入进程级隔离（独立子进程 + OS 沙箱/容器 + 网络命名空间隔离），替换进程内 `exec` 白名单；
  3. 技能发布走强制审批 + 双人复核（已具备 `skill_governance` 审批流，需加代码审计步骤）；
  4. 所有技能执行落审计事件（`skill_governance` 事件流已有，需加代码执行类事件）。
- `SandboxExecutor` 为进程内白名单（非强隔离），`exec` 白名单用于防**误用/意外**，不构成对**恶意代码**的强边界。

## 二、scope_checker 与 SKILL.md 步骤覆盖核对

### 2.1 机制

`services/scope_checker.py`（v3.1 步骤3）从最终 SQL 提取 `cust_name` 过滤的客户集合（`IN` / `=`，跨 CTE/子查询并集），与判定单声明的结果范围比对，要求 `extracted ⊆ declared`（防越界检索"其他"）。仅 `cust_name` 列做严格校验（`cust_no/cust_id` 不校验——对齐 SKILL.md 三列区别，防反复试错）。

### 2.2 覆盖核对表（人工核对，结论见备注）

| SKILL.md 步骤/要求 | scope_checker 覆盖 | 结论 |
|---|---|---|
| 步骤1 台区/户表按客户锁定（"先锁目标客户/台区"） | ✅ 提取 CTE/子查询 `cust_name`（logical_source_scope 并入） | 已覆盖 |
| 步骤2/2b 聚合与连续天数（不新增客户过滤） | ✅ 主查询最外层 `cust_name`（result_scope） | 已覆盖 |
| 步骤3 负载率计算（沿用锁定的客户集合） | ✅ result+source 并集 ⊆ declared | 已覆盖 |
| 文档主推 `cust_name IN (...)` 写法 | ✅ `exp.In` 分支 | 已覆盖 |
| 单客户 `cust_name = '...'` 兼容 | ✅ `exp.EQ` 分支 | 已覆盖 |
| 表别名前缀（`c.cust_name`） | ✅ 自动剥离别名 | 已覆盖 |
| `cust_no/cust_id` 类范围 | ⚠️ 有意不校验（v1 收敛，防试错；SKILL.md 三列区别） | 保留偏差，v2 再收紧 |
| SQL 解析失败 | ✅ 放行不阻断（由调用方按"声明了却提取为空"判定） | 已覆盖 |
| 模型覆盖 user_input 来源范围 | ✅ decision_gate：`source=user_input` 不可被模型覆盖 | 已覆盖 |

### 2.3 结论

范围强校验与 SKILL.md 配电重过载场景步骤对齐；`cust_no/cust_id` 不校验为 v1 有意收敛（记录为保留偏差，升级需随 v3.1 后续版本）。
