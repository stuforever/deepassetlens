# 数据智能对话 前端测试操作手册

> 测试地址：http://localhost:3002 → 菜单选「数据智能对话」
> 后端地址：http://127.0.0.1:8100
> 数据源：MySQL（kg_concepts / kg_entities 表，不再依赖图数据库）

---

## 界面说明

```
┌──────────────────────────────────────────────────────┐
│ 顶部：[新建对话框] [会话切换▼] [目标标签] [大模型选择▼] │
├────────────────────┬─────────────────────────────────┤
│ 左 40% 对话框       │ 右 60% 定位信息                  │
│  ┌思考过程(折叠)┐   │  定位树(L1→L2→L2X→属性)          │
│  │ 第1轮 策略... │   │  关系(三色标签)                  │
│  └──────────────┘   │  溯源(实体→物理表→字段)          │
│  消息列表(确认卡)    │  SQL(确认后展示)                 │
│  输入框 + 发送       │                                 │
│  推荐下一步          │                                 │
└────────────────────┴─────────────────────────────────┘
```

## 场景1：默认路径 — 查实体（高置信直锁）

**目的**：验证 boss_router 的 goal=sql_assembly + locked_hint 高置信直锁。

**步骤**：
1. 顶部确认大模型下拉有值（应显示 minimax-m3 / 豆包 / GLM-4-Flash）
2. 输入框输入「查客户」，点发送
3. 观察左侧对话框「思考过程」区域

**预期**：
- 顶部出现蓝色标签「目标:出SQL」+「实体定位」
- 思考过程显示：调 find_l1_or_l3 向量召回+LLM → 高置信锁定大类客户
- 弹出确认卡：列出 L2 小类候选（如"用户接入点"等）
- 右侧定位树：L1 区域显示「客户」真实名称（不再是示例占位）

**关注点**：
- 思考流是否逐条展示策略和结果
- locked_hint 是否跳过了候选直接锁定大类
- 定位树是否填充了真实名称

## 场景2：选择确认 — 逐步定位实体

**目的**：验证逐步问答确认流程（选小类→选实体）。

**步骤**：
1. 接场景1，在确认卡中点选一个 L2 小类（如"用户接入点"）
2. 观察响应

**预期**：
- 右侧定位树：L2 节点填充为所选小类名称
- 弹出新确认卡：列出 L2X 实体候选
- 思考流增加新步骤

**步骤**：
3. 在实体确认卡中点选一个实体
4. 观察响应

**预期**：
- 右侧定位树：L2X 节点填充为实体名称（标记"主实体"）
- 顶部标签变为「属性定位」或出现「推荐下一步：查属性」
- entity_locked 旗标亮起

**关注点**：
- 每次选择后定位树是否逐步填充
- 推荐下一步是否出现

## 场景3：只问知识 — knowledge_only 路径

**目的**：验证 goal=knowledge_only 时不推荐 SQL。

**步骤**：
1. 点「新建对话框」开新会话
2. 输入「我就想知道客户有哪些字段」，发送

**预期**：
- 顶部标签显示「目标:只问知识」+「分类查询」
- 返回客户字段列表
- **不出现**「推荐下一步：拼SQL」
- 右侧定位树不变化（知识查询不锁定实体）

**关注点**：
- goal 标签是否为「只问知识」
- next_step 推荐是否为空

---

## 场景4：多会话切换

**目的**：验证多对话框独立状态。

**步骤**：
1. 在场景1的会话中查到一半（已锁定大类）
2. 点「新建对话框」开第二个会话
3. 第二个会话输入「查设备」，发送
4. 用顶部会话切换下拉，切回第一个会话

**预期**：
- 切回第一个会话时，之前的消息和定位树状态保留
- 切到第二个会话时，显示设备相关的消息和状态
- 两个会话的 confirmed/flags 互不干扰

**关注点**：
- 会话切换时定位树是否正确切换
- 消息历史是否保留

---

## 场景5：大模型切换

**目的**：验证不同大模型路由效果。

**步骤**：
1. 开新会话，大模型选「minimax-m3」
2. 输入「查客户电话」，发送，观察路由结果
3. 开新会话，大模型切「智谱GLM-4-Flash」
4. 输入同样「查客户电话」，发送，对比路由结果

**预期**：
- 两个模型都应路由到「实体定位」（因为提到实体客户+属性电话）
- locked_hint 可能不同（minimax 可能直接给 entity_name=客户）
- 思考流过程一致

**关注点**：
- 大模型下拉是否可选且有值
- 不同模型的路由准确性差异

## 场景6：歧义词 — 3次尝试才弹窗

**目的**：验证 Think-Act-Verify 3轮尝试机制（如果已实现）。

**步骤**：
1. 开新会话
2. 输入「查下主体」（"主体"是歧义词）
3. 观察

**预期**：
- 思考流显示多轮尝试（向量召回→LLM推理→图谱遍历）
- 多轮失败后弹反问卡「你说的主体是指客户、供应商还是组织？」
- 不是直接弹选择卡，而是先尝试3次

**关注点**：
- 是否有3轮思考流记录
- 弹窗是否在3次失败后才出现

---

## 场景7：推荐下一步链路

**目的**：验证 sql_assembly 目标下的推荐推进。

**步骤**：
1. 接场景2（实体已锁定）
2. 观察底部「推荐下一步」蓝色区域

**预期**：
- 出现「查属性」推荐按钮（主推）
- 点「查属性」或输入属性名继续
- 属性锁定后出现「拼SQL」推荐
- SQL 拼装后出现「执行SQL」推荐

**关注点**：
- 推荐按钮是否按链路顺序出现
- 点击推荐是否填入输入框

## 已知限制（当前版本）

1. **属性定位/关系定位/SQL拼装的思考流**：当前只有实体定位产出了 think_stream，其他任务的思考流待补
2. **溯源区**：目前只显示骨架占位，实体锁定后展示"待查询"，未实际调血缘查询
3. **关系线**：定位树的关系区目前只读 confirmed.relations，未在树上画连线
4. **SQL执行**：需后端配置数据源连接才能实际执行
5. **图数据库**：已切换为 MySQL 直查，Neo4j 不再作为数据源（启动仍同步但不依赖）
