## 〇、六条定调（不可逆决策，全文沿用）

1. **全部可配置，基准钉死代码**：管理页只能改「当前值」；默认值=代码常量（审计锚点）；reset-defaults 永远回到代码基准。不提供「改默认值」功能——避免两份真相。
2. **红线不入库**：物理锁定的工具（read_file/ls/task）不走配置面；危险操作恢复走 🔴 双 Modal+必填理由。
3. **探针是保险丝，不是可选项**：每个新配置项必须有生效凭证（probe），无探针的配置项不上线。
4. **两种失败两种哲学**：配置错误 fail-safe 回退上一版（tupu_deepagent.py L1067-1081 双层包装器）；闸门/代码错误 fail-closed 拒绝装配。
5. **数值参数必须带范围校验**：任何数值入 params 前先定边界（防「默认 170k 永不触发」同类故障）。
6. **验收一律 Playwright e2e**（AGENTS.md 铁律，串行执行，`backend/scripts/_pw_e2e.py`）。

## 二、W-1 工具白名单打勾制（反转语义）

### 2.1 现状（2026-09-04 实测）

- 落地的是**黑名单版**（856c7ac）：`capability_config.get_tool_exclusions()`（L136-152）返回 `{"excluded": [...], "locked": [...]}`，DB params 存 `excluded` 数组；
- 装配侧（tupu_deepagent.py L862-867）读 excluded 喂 `HarnessProfile(excluded_tools=...)` → 步7 压轴 `_ToolExclusionMiddleware`；
- fail-safe：读崩 → 默认 5 件（grep/glob/write_file/edit_file/execute）。

### 2.2 反转设计（用户 2026-08-24 定调，理由不变）

黑名单对「框架升级新增工具」漏网（新名字不在名单上自动放行）；白名单天生免疫（没打勾就是禁），且完全符合 fail-closed 定调。

**数据模型**（`tool_availability` params，黑名单版已有该能力项，只改 params 语义+迁移）：

```json
{
  "allowed": ["search_entities", "execute_sql", "read_file", "ls", "task", "...共17件"],
  "locked":  ["read_file", "ls", "task"]
}
```

**装配侧换算**（机制零新增）：`排除清单 = 已知工具全集（MCP 17+框架文件工具+task） - allowed`，喂同一个 `excluded_tools` 机制。**fail-safe 用代码内默认允许集**（=17 件全勾，读崩不能变成全禁把 Agent 弄残——黑名单版的 fail-safe 是默认排除 5 件，反转后语义对应变化，如实登记）。

**迁移**：启动时检测 params 含旧 `excluded` 键 → 换算 `allowed = 全集 - excluded`（锁定三件恒在）→ 写回 `allowed` 删 `excluded`，记 migration 事件（沿用 856c7ac 旧名 tool_exclusions→tool_availability 的增量补种管道）。迁移后默认勾选集=现状允许集，**零行为变化**。

**API 与校验**：
- allowed 内工具名必须在已知注册表内，未知名 400；
- locked 三件（read_file/ls/task——技能渐进披露/子代理/文件工具的命根子）物理锁定，前端灰显+原因说明；
- 风险分级：取消业务工具（execute_sql 等四查询工具）=🔴（双 Modal+必填理由）；取消其余 MCP 工具=🟡；
- **白名单探针**（双向）：勾了的必须在装配后 Agent 实际工具列表、没勾的必须不在——`tool_availability_installed` manifest 字段改记排除清单（换算结果），探针读它断言。

**连带效应**（写进按钮说明）：取消某业务工具后，若 entity_locator 子代理规格依赖它 → 交集护栏 spec_invalid → 自动回退串行（正确行为，需知晓）。

### 2.3 已知工具全集的维护

全集 = 装配时 MCP `get_tools()` 实际返回的 17 件 + 框架文件工具（read_file/ls/write_file/edit_file/grep/glob/execute...）+ task。**注册表以装配期实查为准**（防框架升级改名漂移），管理页加载时从 manifest 探针端点取当前全集渲染打勾清单——新工具出现时自动落入「未勾选」状态（白名单语义天然免疫）。

## 三、管理页十步 Tab 改版（用户 2026-09-04 定调，终版结构）

### 3.1 设计动机

现状 14 项能力卡堆一个 Tab，运维看不出「这项改了装配会怎样」。按**装配十步**组织：每项配置挂到它实际影响的装配步骤上，顺着流程就能看懂（教学即运维）。替代 2026-08-24 的旧四 Tab 方案。

### 3.2 结构：安全控制中心 → 十一步分区（1 全局+10 步）

```
/security-controls
├─ Tab0 全局·缓存与版本
│    ├─ 缓存键四成分实时显示：{连接}#g{守卫ver}#c{能力ver}#f{files_hash}
│    ├─ 缓存命中状态 + LRU 保留 2 版说明 + rebuild 事件流
│    ├─ approval_track（版本键成分，🟢）
│    └─ 装配 manifest 总览（summarization_mode/data_summary_mode/rubric_mode/backend_mode 四 mode 字段+探针总览+reset-defaults）
├─ Tab1 步1·模型与档案
│    ├─ 当前连接模型（只读，改连接走 LLM 配置页）
│    ├─ 档案注册状态（key 双保险：openai:DeepSeek-V4-Flash + 小写变体，只读）
│    └─ X-2 审计锚点说明（只读教学：改写栏三次消费点，当前空转，X-3 缓议）
├─ Tab2 步2·体检（只读教学）
│    └─ 保护名单 {FilesystemMiddleware, SubAgentMiddleware} 说明：为何不可排除（文件工具+权限的娘家/task 的娘家）
├─ Tab3 步3·工具说明书（只读教学）
│    └─ 改写栏三次消费点图示（调用者工具/文件工具/task 工具），当前无改写项
├─ Tab4 步4·文件柜
│    ├─ filesystem_tools（🟡：CompositeBackend+StoreBackend 路由开关；13-Y 后含 files_hash 新鲜度+种子文件数显示）
│    └─ store（🟢：长期记忆库）
├─ Tab5 步5·小弟
│    └─ subagents（🟡：enabled 总闸+entity_locator 规格编辑器+max_concurrent+四护栏说明；
│         13-Z 已点火——含 task_invoke/task_reject 实时计数观测）
├─ Tab6 步6·主栈
│    ├─ skills（🟡）/ memory（🟡）/ permissions（🟡：三规则只读展示）
│    └─ debug（🟢）/ patch_tool_calls+message_eviction（🔒灰显锁定：框架自动件恒装）
├─ Tab7 步7·筛与拼
│    ├─ summarization（🟡：排除栏条件化的执行器——开关关才排除）
│    ├─ tool_availability（W-1 白名单打勾制落此：17 工具分组+锁定区+双向探针）
│    └─ 检查站卡：SkillPolicy（🔒红线锁定）/ DecisionGate（W-4a 装卸开关迁入+W-4b 范围工具集 params）
├─ Tab8+9 步8·9·状态与查白（只读教学）
│    └─ 各站小抽屉收编示意 + 排除栏覆盖结算说明（步9 查「该撤的撤没撤」）
└─ Tab10 步10·出厂
     ├─ response_format（🟡）
     ├─ rubric（🟡：mode 切换 skill_prompt/middleware——skill_prompt 自检段就注入步10 系统提示词，归此名正言顺）
     └─ recursion_limit=9999 说明（只读）
```

**守卫 Tab 去向说明**：旧「安全守卫」Tab（13-V 五类守卫模式+审批轨）**保留独立**，不并入十步——守卫是运行期裁决（改配置热生效，不走重装配），与装配期开关分属两条生效链路（PATCH→version+1→TTL 5s vs PATCH→version+1→缓存键变→重装配）。入口并列于 /security-controls 首页。

### 3.3 每配置项五件套（既定纪律沿用）

作用说明 / 当前值 / 风险级别（🔴双 Modal+必填理由 🟡单 Modal 确认 🟢直切）/ 修改影响说明（写明影响哪一步装配）/ 试探单。

### 3.4 只读教学页的纪律

Tab1/2/3/8+9 无可配项，做成「装配说明书」——每页头部一句话教学（这步装了什么+真实值），底部「本步不可配置原因」。运维新人顺着十步读完一遍=看懂整个装配层（与教学线程同源知识，防口口相传）。

## 五、诚实登记的坏处与残留风险

1. **白名单固有代价**：误取消关键工具会 Agent 残废——🔴双确认+锁定区+双向探针三层缓解，无法归零。
2. **配置面膨胀**：十一步分区后单页项少，但总配置项不变——每项作用说明/校验/探针的维护成本在，缓解=五件套纪律。
3. **fail-safe 语义反转登记**：黑名单版读崩=默认排除 5 件；白名单版读崩=默认允许 17 件（全集）。两者都是「回到安全可用态」，但字面语义相反，切换说明里写清。
4. **只读教学页的漂移风险**：教学内容描述的是装配机制（框架 graph.py 十步），框架小版本升级后需人工核对——登记为低频维护项（框架升级时教学页核对入验收清单）。
5. **温度例外**（备忘沿用）：主模型 0.1/评分模型 0.0 为代码显式覆盖，配置化不覆盖温度。
