## 〇、六条定调（不可逆决策）

1. **全部可配置，基准钉死代码**：管理页只能改「当前值」；默认值=代码常量（审计锚点）；reset-defaults 永远回到代码基准。不提供「改默认值」功能——避免出现代码默认与数据库默认两份真相。
2. **红线不入库**：物理锁定的工具（read_file/ls）不走配置面；危险工具恢复走 🔴 双 Modal+必填理由。
3. **探针是保险丝，不是可选项**：每个新配置项必须有生效凭证（probe），无探针的配置项不上线。
4. **两种失败两种哲学**（沿用现有双层包装器）：配置错误 fail-safe 回退上一版（tupu_deepagent.py L1087-1113）；闸门/代码错误 fail-closed 拒绝装配。
5. **数值参数必须带范围校验**：摘要 trigger 必须小于当前模型窗口——防「默认 170k 永不触发」同类故障在我们自己身上复发。
6. **验收一律 Playwright e2e**（AGENTS.md 铁律，串行执行，`backend/scripts/_pw_e2e.py`）。

## 一、现状实测（2026-08-24 核对）

### 1.1 档案注册机制（已稳定运行）

- 注册代码：`backend/app/services/tupu_deepagent.py` L893-918。动态编号（从 model 对象抄 identifier/provider 拼 `厂商:型号`）+ 大小写双保险 + 无厂商兜底路。
- 模型事实（数据库 `kg_llm_connection_configs` 实查）：
  - 默认连接「4agent」：`DeepSeek-V4-Flash` @ 火山引擎方舟（OpenAI 兼容）→ 档案编号 `openai:DeepSeek-V4-Flash` 与 `openai:deepseek-v4-flash` 各放一份；
  - 备用连接：glm-flash（GLM-5.3-Flash）、deepseek官方（全小写 deepseek-v4-flash）、3agent——大小写双保险正是为覆盖这些变体。
- 档案内容：`excluded_tools={grep,glob,write_file,edit_file,execute}`（L897-903，grep 有实战案底）+ `excluded_middleware={"SummarizationMiddleware"}`（L907）。
- 合法性已验证：`SummarizationMiddleware` 不在框架保护名单（`_REQUIRED_MIDDLEWARE` 仅 FilesystemMiddleware/SubAgentMiddleware 两项）；排除按名字字符串逐字匹配，我们的子类 `_TupuSummarizationMiddleware` 站名牌不同而存活——此路径为框架明文设计的扩展点（`_apply_excluded_middleware` docstring：子类保留语义 + 站名牌改名支持）。

### 1.2 硬编码点（本设计要配置化的对象）

| 硬编码项 | 位置 | 当前值 |
|---|---|---|
| 工具黑名单 | L897-903 | 5 件：grep/glob/write_file/edit_file/execute |
| 摘要参数 | L969-971 | trigger 30k / keep 10 条 / truncate 15/15 |
| 观测钩子 | L974-986 | 常开（摘要触发即记治理事件） |

### 1.3 框架默认值对照（评估换回默认的依据，已实测）

框架无档案模型的默认：trigger=170k token / keep=6 条 / truncate=20/20。170k 超过我们模型真实窗口 → 永不主动摘要 → 撞墙后走 ContextOverflowError 紧急摘要兜底（延迟尖刺+缓存最坏时刻打碎）。**结论：不换回默认；参数配置化后由管理员按模型调。**

### 1.4 已知技术债

- **私有依赖**：L894 `from deepagents._models import get_model_identifier, get_model_provider`——两函数不在 deepagents 公开门面（已实测公开导出清单无此二名），框架小版本升级有改名风险。
- **审计锚点缺失**：未登记「当前模型审查过无需行为后缀」的结论（官方 sonnet 档案的工作习惯）。

## 二、批13-W：装配层配置化三件套

### W-1 工具黑名单配置化

**目标**：黑名单从硬编码迁入能力开关中心，管理页可增删可排除的工具；迁移后零行为变化（默认=现状）。

**数据模型**（capability_policies 新增能力项 `tool_availability`，params JSON）：

```json
{
  "excluded": ["grep", "glob", "write_file", "edit_file", "execute"],
  "locked":   ["read_file", "ls"]
}
```

**API 与校验**（capabilities.py 既有五端点扩展）：
- PATCH 校验：工具名必须在已知注册表内（MCP 业务工具全集 + 框架文件工具件），未知名 400；
- `locked` 区不可 PATCH（物理锁定，前端灰显，复用 CapabilityPanel 现有 locked 分组 L277-278）；
- 风险分级：恢复 write_file/edit_file/execute/grep/glob = 🔴（双 Modal+必填理由）；排除业务工具（execute_sql/search_entities 等）= 🟡；read_file/ls = 锁定不可动（技能渐进披露依赖）。

**装配侧改动**（一处）：`_build_agent` L897-903 的硬编码 frozenset 改读 `caps["tool_availability"].params.excluded`；**配置缺失/读取异常时 fail-safe 用代码内默认 5 件名单**（读崩不能变成全放开）。注册逻辑（编号拼装/大小写/兜底）零改动。

**探针**（必做，保险丝）：验证黑名单工具**确实不在装配后 Agent 的工具列表**（probe_ok 凭证）。同时可捕获框架升级改工具名导致拉黑落空的漂移。

**连带效应（写进按钮说明）**：拉黑某业务工具后，若 entity_locator 子代理规格依赖它 → 交集护栏触发 spec_invalid → 自动回退串行定位（正确行为，需用户知晓）。

**验收**：e2e 管理页拉黑一个工具 → 探针 probe_ok → 真实提问确认该工具不再被调用 → 恢复默认回到 5 件名单。

### W-2 摘要参数配置化

**目标**：trigger/keep/truncate 三参数迁入管理页；换模型时按窗口调参不再改代码。

**数据模型**（能力项 `summarization` 的 params 扩展）：

```json
{
  "trigger_tokens": 30000,
  "keep_messages": 10,
  "truncate_trigger_messages": 15,
  "truncate_keep_messages": 15
}
```

**校验（必做）**：
- trigger_tokens 范围：10k ≤ 值 ≤ 当前连接模型窗口 × 0.9（窗口大小维护进 LLM 连接配置或已知模型注册表；查不到窗口的连接按 64k 保守假设计算上限）；
- keep/truncate：1 ≤ 值 ≤ 100；
- 风险分级：🟡 单 Modal 确认（可逆，有 reset-defaults）。

**装配侧改动**：`_TupuSummarizationMiddleware.__init__`（L965-972）三参数改从 caps 注入，缺省回落代码默认。

**探针**：装配清单 manifest 增记 `summarization_params`；探针核对栈内实例参数与配置一致。

**诚实登记**：参数调大 → 摘要更晚 → 前缀缓存活更久但更贴近窗口风险；调小 → 缓存更早打碎。这是真实权衡，按钮说明里写明，不替用户隐藏。

### W-3 观测钩子开关

**目标**：摘要触发的治理事件记录可关（运维降噪/排障场景）。

**设计**：能力项 `summarization` params 增 `"observe_hook": true`；钩子（L974-986）读取后决定是否 record_policy。风险分级 🟢（纯观测，关了不影响功能行为）。

**诚实登记**：价值有限——钩子本身低频（仅摘要触发时写一条），开关收益约等于零；纳入仅为「全能力可开关」完备性。优先级最低，可与 W-1/W-2 同窗口顺手做。

## 四、诚实登记的坏处与残留风险

1. **工具名漂移**：框架未来改名（如 execute→shell_exec）会让旧名单静默落空。探针是唯一防线——故 W-1 探针必做。
2. **配置面膨胀**：可配项增加=文档/校验/探针都要跟上。本设计只纳入有真实调参需求的项（黑名单、摘要参数），DecisionGate 工具单、守卫参数等已有归属的不重复纳入。
3. **两份真相风险**：已由「默认钉死代码」定调化解（改默认=走代码评审）。
4. **钩子开关价值有限**：如实登记，为完备性而非需求。
5. **温度例外提醒**：主模型温度 0.1（L828）、评分模型 0.0（L1004）为代码显式覆盖，后台连接配置的温度对这两处不生效——配置化不覆盖温度（求稳/求判分一致的既定决策），此处仅登记备忘。
