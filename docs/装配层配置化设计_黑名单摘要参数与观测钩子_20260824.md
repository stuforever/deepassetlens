## 〇、六条定调（不可逆决策）

1. **全部可配置，基准钉死代码**：管理页只能改「当前值」；默认值=代码常量（审计锚点）；reset-defaults 永远回到代码基准。不提供「改默认值」功能——避免出现代码默认与数据库默认两份真相。
2. **红线不入库**：物理锁定的工具（read_file/ls）不走配置面；危险工具恢复走 🔴 双 Modal+必填理由。
3. **探针是保险丝，不是可选项**：每个新配置项必须有生效凭证（probe），无探针的配置项不上线。
4. **两种失败两种哲学**（沿用现有双层包装器）：配置错误 fail-safe 回退上一版（tupu_deepagent.py L1087-1113）；闸门/代码错误 fail-closed 拒绝装配。
5. **数值参数必须带范围校验**：摘要 trigger 必须小于当前模型窗口——防「默认 170k 永不触发」同类故障在我们自己身上复发。
6. **验收一律 Playwright e2e**（AGENTS.md 铁律，串行执行，`backend/scripts/_pw_e2e.py`）。

### 1.2 硬编码点（本设计要配置化的对象）

| 硬编码项 | 位置 | 当前值 |
|---|---|---|
| 工具黑名单 | L897-903 | 5 件：grep/glob/write_file/edit_file/execute |

### 1.3 框架默认值对照（评估换回默认的依据，已实测）

框架无档案模型的默认：trigger=170k token / keep=6 条 / truncate=20/20。170k 超过我们模型真实窗口 → 永不主动摘要 → 撞墙后走 ContextOverflowError 紧急摘要兜底（延迟尖刺+缓存最坏时刻打碎）。**结论：不换回默认；参数配置化后由管理员按模型调。**

### 1.4 已知技术债

- **私有依赖**：L894 `from deepagents._models import get_model_identifier, get_model_provider`——两函数不在 deepagents 公开门面（已实测公开导出清单无此二名），框架小版本升级有改名风险。
- **审计锚点缺失**：未登记「当前模型审查过无需行为后缀」的结论（官方 sonnet 档案的工作习惯）。

## 二、批13-W：装配层配置化四件套

### W-1 工具白名单（打勾制，用户定调替代原黑名单设计）

**目标**：工具管控从「黑名单点名禁」反转为「白名单打勾允」——默认全不允许，打勾的才允许。迁移后零行为变化（默认勾选集=现状允许集）。

**为什么白名单优于黑名单**（用户提议，设计采纳）：黑名单对「框架升级新增工具」漏网（新名字不在黑名单上自动放行）；白名单天生免疫（没打勾就是禁）——直接补掉 §四.1 的工具名漂移残留风险，且完全符合 fail-closed 定调。

**数据模型**（capability_policies 新增能力项 `tool_availability`，params JSON）：

```json
{
  "allowed": ["search_entities", "execute_sql", "read_file", "ls", "task", "...其余15个"],
  "locked":  ["read_file", "ls", "task"]
}
```

**装配侧换算**（机制零新增）：`排除清单 = 已知工具全集(MCP 17 件+框架文件工具+task) - allowed`，喂给框架同一个 `excluded_tools` 机制（注册代码 L897-903 改为读配置换算）。**配置缺失/读取异常时 fail-safe 用代码内默认允许集**（读崩不能变成全禁把 Agent 弄残）。

**API 与校验**：
- allowed 内工具名必须在已知注册表内，未知名 400；
- locked 三件（read_file/ls/task——技能渐进披露与子代理的命根子）物理锁定，前端灰显+原因说明；
- 风险分级：取消勾选业务工具（execute_sql 等）= 🔴（双 Modal+必填理由，Agent 可能残废）；取消其余 MCP 工具 = 🟡；
- 白名单探针（必做保险丝）：验证打勾状态与装配后 Agent 实际工具列表**双向一致**（勾了的必须在、没勾的必须不在）。

**连带效应（写进按钮说明）**：取消某业务工具后，若 entity_locator 子代理规格依赖它 → 交集护栏 spec_invalid → 自动回退串行（正确行为，需用户知晓）。

### W-2 摘要参数配置化（❌ 已取消，2026-08-24 用户定调摘要回退官方默认）

> 取消依据：13-AB 回退后无自定义参数可配（官方工厂默认 170k/6/20-20；实测 model.profile=None、摘要历史触发 0 次）。以下内容仅作历史存档，不再实施。将来若复盘触发条件命中（超限重试日志/长会话常态化），优先方案是为模型补 profile 使官方自适应 85%，而非恢复本项。

**目标**：trigger/keep/truncate 三参数迁入管理页；换模型时按窗口调参不再改代码。

**数据模型**（能力项 `summarization` 的 params 扩展）：

```json
{
  "trigger_tokens": 30000,
  "keep_messages": 10,
  "truncate_trigger_messages": 15,
  "truncate_keep_messages": 15
}
```

**校验（必做）**：
- trigger_tokens 范围：10k ≤ 值 ≤ 当前连接模型窗口 × 0.9（窗口大小维护进 LLM 连接配置或已知模型注册表；查不到窗口的连接按 64k 保守假设计算上限）；
- keep/truncate：1 ≤ 值 ≤ 100；
- 风险分级：🟡 单 Modal 确认（可逆，有 reset-defaults）。

**装配侧改动**：`_TupuSummarizationMiddleware.__init__`（L965-972）三参数改从 caps 注入，缺省回落代码默认。

**探针**：装配清单 manifest 增记 `summarization_params`；探针核对栈内实例参数与配置一致。

**诚实登记**：参数调大 → 摘要更晚 → 前缀缓存活更久但更贴近窗口风险；调小 → 缓存更早打碎。这是真实权衡，按钮说明里写明，不替用户隐藏。

### W-3 观测钩子开关

**目标**：摘要触发的治理事件记录可关（运维降噪/排障场景）。

**设计**：能力项 `summarization` params 增 `"observe_hook": true`；钩子（L974-986）读取后决定是否 record_policy。风险分级 🟢（纯观测，关了不影响功能行为）。

**诚实登记**：价值有限——钩子本身低频（仅摘要触发时写一条），开关收益约等于零；纳入仅为「全能力可开关」完备性。优先级最低，可与 W-1/W-2 同窗口顺手做。

### W-4 检查站配置三件（实测依据：三个映射点现状为代码常量）

| 配置项 | 现状（2026-08-24 实测） | 迁入后 |

## 四、诚实登记的坏处与残留风险

1. **工具名漂移**：~~框架未来改名会让旧名单静默落空~~ **已由 W-1 白名单语义化解**（没打勾=禁，新工具默认挡在外面）；白名单探针继续作为漂移的第二道防线。
2. **配置面膨胀**：可配项增加=文档/校验/探针都要跟上。缓解：四 Tab 分区+每项强制作用说明（§五）；守卫参数等已有归属的不重复纳入。
3. **两份真相风险**：已由「默认钉死代码」定调化解（改默认=走代码评审）。
4. **钩子开关价值有限**：如实登记，为完备性而非需求。
5. **白名单的固有代价**：误取消关键工具（execute_sql）会 Agent 残废——靠 🔴 双确认+锁定区+探针三层缓解，无法归零，如实登记。
6. **温度例外提醒**：主模型温度 0.1（L828）、评分模型 0.0（L1004）为代码显式覆盖，后台连接配置的温度对这两处不生效——配置化不覆盖温度（求稳/求判分一致的既定决策），此处仅登记备忘。

### 5.1 结构：安全控制中心 双 Tab → 四 Tab
