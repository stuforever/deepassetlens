> 2026-08-20 · 设计窗口产出（不动代码）

## 三、中间件栈终态装配（create_tupu_agent 内，代码级顺序）

```python
middleware_list = [
    PatchToolCallsMiddleware(),            # M1：悬空 tool_calls 修复（最先，修历史再进闸门）
    SkillPolicyMiddleware(),               # 既有：契约硬校验（最外层闸门；M2 扩展纠错指引）
    SkillEntityResolverMiddleware(),       # 既有：⟦中文名⟧ -> 物理表名
    DataSummaryMiddleware(),               # 既有：明细截断 10 行摘要
    RubricMiddleware(                      # M3：自评闸门（框架原生）
        model=_rubric_model(),             #   缺省=会话模型；TUPU_RUBRIC_CONNECTION_ID 可指轻量连接
        max_iterations=1,                  #   防循环铁律（P0 教训）
        on_evaluation=_sink_rubric_event,  #   RubricEvaluation -> run_event_sink -> SSE
    ),
]
if _DECISION_GATE_ENABLED:
    middleware_list.append(DecisionGateMiddleware(scope_gated=SCOPE_GATED_TOOLS))
# 框架按参数自动追加：Skills(skills=["/skills/"]) / Filesystem(permissions) /
#   Memory(memory=["/memory/AGENTS.md"]) / Summarization（M1 改为显式 SummarizationToolMiddleware 实例）
```

装配要点（源码实测依据）：
- RubricMiddleware「无 rubric 时零开销直通」（docstring 明示 safe to include unconditionally）--scenario 模式不传即不触发；
- 激活路径：`data_intelligence_stream.py:192` 调用点改为 `astream_events({"messages": input_messages, "rubric": _contract.rubric, ...}, context=_ctx)`（RubricState 经 state_schema 合并，input dict 直达）；
- MemoryMiddleware 构造 `(*, backend, sources)`，经 `create_deep_agent(memory=["/memory/AGENTS.md"])` 传参时用主 backend 解析路径，故 CompositeBackend 需新增 `/memory/` 路由；
- Summarization 技术债消除：删除 `compute_summarization_defaults` monkey-patch（:747-755/:776-778 的 try/finally 整段），改为 middleware_list 显式追加 `SummarizationToolMiddleware` 实例（构造参数对照现有阈值 30k/10 条；装配前以 0.6.12 源码核对一次参数名）。

## 四、M2 准确性核心（G1 + G3 + G2 + DA-3，~6 天）

### 4.1 G1 验证示例库与检索注入

**表结构**（启动自动建表，沿项目惯例）：

```sql
kg_verified_qa_examples (
  id BIGINT PK AUTO_INCREMENT,
  question_norm VARCHAR(500),   -- 归一化（停用词/同义词替换，复用 StandardSemanticTerm 管线）
  question_raw  VARCHAR(500),
  sql TEXT,
  entity_codes JSON,            -- 涉及实体，供漂移失效联动
  route_type VARCHAR(20),       -- generic | scenario
  engine VARCHAR(20),
  example_type VARCHAR(20),     -- user_confirmed | manual | golden（金标集种子）
  status VARCHAR(10) DEFAULT 'enabled',   -- enabled | disabled | review
  hit_count INT DEFAULT 0,
  last_used_at DATETIME,
  created_at DATETIME
)
```

**Qdrant**：集合 `tupu_qa_examples`，point id=示例 id，payload={question_raw, route_type, status}，向量=问题 embedding（复用 semantic_retrieval 既有 embedding 管线）。Qdrant 不可用时**静默跳过注入**（沿既有 `qdrant_unavailable` 降级模式，不阻断问答）。

**检索注入**（落点：`data_intelligence.py` 路由后、`_build_contract_system_message` 尾部追加）：

```
参考示例（历史已验证查询，仅供构造 SQL 参考，禁止照抄执行）：
[示例1] 问题：统计用电客户总数
        SQL：SELECT COUNT(*) FROM dim_cst_elec_cons_cust
[示例2] ...
```

- top-3，相似度阈值 0.75，仅 status=enabled；
- 命中写 `contract._runtime["example_hits"]`（SSE `examples.injected` 事件 + EngineQueryLog 可选关联）；
- **示例不进白名单语义**：示例 SQL 是提示参考，模型仍须自行构造并过模板守卫/引擎锁定。

**失效联动**：schema 漂移治理事件（已有）-> handler 按 entity_codes 反查置 disabled；管理页 `/qa-examples`（系统管理菜单，DataTableShell 列表 + Drawer 详情 + 启停/删除，复用既有管理页范式）。

### 4.2 G3 列值取样工具（MCP 第 17 个）

```python
@mcp.tool()
def sample_column_values(entity_code: str, column: str, limit: int = 50) -> dict:
    """取指定列 distinct 值+频次（对分类/状态/类型列写 WHERE 前必查，防枚举值猜测）。
    返回 {values: [{value, count}], null_count, total_rows}。结果缓存 10 分钟。"""
```

- 实现：`kg_action_handlers.py` 新分支 -> 按 source_mode 路由到三引擎执行 `SELECT {col}, COUNT(*) c FROM ... GROUP BY 1 ORDER BY 2 DESC LIMIT {n}`（引擎选择复用 query_engine_router；进程内 dict 缓存 10 分钟）；
- 白名单三处同步：`GENERIC_ALLOWED_TOOLS`、`GLOBAL_TOOL_REGISTRY`（skill_catalog）、系统提示词硬规则「分类列 WHERE 前必查」；
- 空结果诊断（G2 ④）依赖此工具。

### 4.3 G2 自纠错闭环（错误分类学驱动）

**纠错指引注入**（落点：`skill_policy.py` postcheck 错误路径，ToolMessage 附加结构化字段）：

| error_class | 注入指引（模板） |
|---|---|
| TABLE_MISSING / CATALOG_MISSING | 「表 {t} 不存在。调用 search_entities 重新定位实体，或 list_tables 查真实表名。」 |
| SYNTAX（含列名错） | 「SQL 报错：{msg 摘要}。调用 validate_attributes 校验列名后修正重试。」 |
| TIMEOUT | 「查询超时。移除 ORDER BY / 增加 LIMIT / 确认可否命中预聚合加速表。」 |
| 执行成功但 0 行 | 「结果为空。调用 sample_column_values 检查过滤值是否真实存在，复核时间范围与口径。」 |

- **计数闸门**：`contract._runtime["corrections"]` 上限 2 次，超限 SkillPolicy 直接终止并出失败卡（P0 死循环教训的制度化）；
- **EXPLAIN 预检**：`execute_doris_sql`/`execute_sql` handler 内执行前先 EXPLAIN（毫秒级，池上执行），SYNTAX/TABLE_MISSING 提前返回带 error_class--省一轮完整执行；DuckDB 联邦无 EXPLAIN 语义，跳过；
- 治理：每次纠错记 `correction.attempt` 事件（governance + run_event_sink 双落）。

### 4.4 DA-3 常驻纪律（AGENTS.md）

- 文件：`backend/data/memory/AGENTS.md`（限一屏 ~60 行，超了往 skills 迁）；
- 内容骨架：工具使用纪律（分类列先取样/表名必须 search_entities 确认/示例仅供参考）· 回答规范（口径披露/无数据不臆断/数字必须来自工具返回）· 表述规范（先结论后过程）；
- 装配：CompositeBackend 加路由 `"/memory/": FilesystemBackend(root_dir=data/memory, virtual_mode=True)` + `create_deep_agent(memory=["/memory/AGENTS.md"])`；
- 职责边界：AGENTS.md=全局长期纪律（运营可改文件）；`_build_dynamic_system_prompt` 动态部分（契约/技能提示/工具清单）保持现状不迁。

## 五、M3 自评与验证（DA-2 + G4 + G7，~4 天）

### 5.1 DA-2 RubricMiddleware 集成

**激活**：`QueryContract.rubric` 字段；generic 模式默认文案：

```
本回答必须满足：
1. 数字必须来自工具返回结果，禁止编造或心算；
2. 注明统计口径：实体表、时间范围、过滤条件；
3. 结果为空或验证失败时明示原因，不得给猜测值；
4. 直接回答用户问题本身的量词与维度（总数/ TopN/占比…）。
```

scenario 模式 rubric=None（模板已保证结构，省一轮 grader）。

**构造**（源码实测签名）：`RubricMiddleware(model=..., max_iterations=1, on_evaluation=...)`。
- grader 模型：缺省会话模型；`TUPU_RUBRIC_CONNECTION_ID` 环境变量可指轻量连接（LLMConnectionConfig 表已有连接管理）；
- `on_evaluation` 钩子 -> `run_event_sink` -> SSE `rubric_evaluation_end` 事件 `{status: satisfied|needs_revision|failed|max_iterations_reached|grader_error, iterations, feedback_summary}`；
- 终态观测：`_rubric_status`（grader 放弃时不改消息，前端按事件展示，不篡改答案）；
- 治理：评估结果落 governance（evaluation 事件），供金标集对照 Rubric 净收益。

### 5.2 G4 引擎侧结果验证

`execute_*` 三出口返回 dict 统一追加：

```json
"verification": {"row_count": 42, "null_rates": {"col_a": 0.02, "col_b": 0.83},
                 "warnings": ["列 col_b 空值率 83%，可能选错列"]}
```

- 计算：结果已在手，扫描 cheap；告警规则 v1 仅一条（关键输出列空值率 >80%）；
- 偏差预警（vs MetricQueryLog 历史 3σ）标 v2 缓做（需口径对齐，复杂度不值）；
- SSE：`query.verified` 事件 + 结果载荷透传（沿 data_snapshot_at 模式）。

### 5.3 G7 证据链卡（第六张业务卡）

- **SSE 聚合载荷**（final 事件新增 `evidence`）：

```json
{"route": {"skill": "__generic__", "route_type": "generic"},
 "tables": ["dim_cst_elec_cons_cust"],
 "examples_used": [{"q": "统计用电客户总数", "sim": 0.91}],
 "verification": {...}, "rubric": {"status": "satisfied", "iterations": 0},
 "corrections": 0}
```

- **前端**：`contractCards/EvidenceCard.tsx`（复用 ContractCardShell + StatusTag + tokens 规范，胶囊条增「证据」第 6 胶囊）；内容分区：路由/表清单/示例命中/验证结论/自评状态；
- **置信度三级**（答案头部小徽标，不装不说）：
  - 高：rubric=satisfied 且 verification 无 warning；
  - 中：无 rubric（scenario）或 verification 有 warning；
  - 低：corrections>0 或 rubric=failed/超限。

## 六、M4 学习与运营（G5 + G6，~3 天）

### 6.1 G5 反馈闭环

- **API**：`POST /api/v1/data-intelligence/feedback` `{run_id, message_id, verdict: up|down, corrected_sql?, comment?}`；
- **入库路由**：👍 且无修正 -> `user_confirmed` 直接入库 + Qdrant upsert；👎+修正 SQL -> `status=review` 进审核队列（管理页 `/qa-examples` 审核）；run_id -> EngineQueryLog 取实际执行 SQL 作存证；
- **前端**：SqlResultTable 工具栏 + 最终答案尾部 👍/👎（LikeOutlined/DislikeOutlined，token 色，hover 反馈）；修正入口 Modal（dal-mono SQL 编辑器，仅 👎 时展开）。

### 6.2 G6 金标评估集

- **表** `kg_golden_qa_set`：`id / question / expected_sql / expected_result_digest(JSON: row_count+首行 hash) / route_type / scenario_tag / enabled`；
- **种子**：50-100 条，来源=落地页示例问题 + distribution-overload 场景 + 历史成功查询抽样；**金标同时以 example_type=golden 灌入示例库**（G1 冷启动即有数据）；
- **评估脚本** `backend/scripts/eval_golden.py`：逐条走流式问答 -> 比对结果 digest（比结果不比 SQL 文本，同结果不同写法算对）-> 输出准确率 + 失败明细 JSON；
- **发布清单**：新增硬门槛「金标准确率 ≥90%（且环比不降）」；Rubric 开启/关闭各跑一次，度量自评闸门净收益；
- 前端趋势页**不做**（脚本产物存 `docs/eval/` 即可，YAGNI）。

### 7.2 G9 追问改写

- **机制**：thread_id 有历史时，新问题先经单轮改写（会话模型）：「结合会话上下文与上一轮口径（实体/时间/范围），把追问改写为独立完整问题」；
- **落点**：freeplan 流式入口，改写后问题进 SkillRouter；原问题保留在消息历史；
- **透明性**：SSE 输出「理解为：xxx」小字（textTertiary），用户可纠正；
- v1 边界：仅 free_plan 会话内启用；scenario 模式问题结构化强，不改写。

## 十一、风险与对策

| 风险 | 对策 |
|---|---|
| Rubric 增加 generic 延迟/成本 | max_iter=1 + 轻量 grader 可选 + 仅 generic 启用；金标集 A/B 度量净收益后再决定扩展 |
| 示例库冷启动空转 | 金标集 50-100 条以 golden 类型直接灌入（G6 兼任 G1 种子，设计内闭环） |
| 示例过时误导 | schema 漂移事件自动 disable + 相似度阈值 0.75 + 提示词明示「仅供参考禁止照抄」+ 管理页人工可禁 |
| 追问改写改错意图 | 改写结果透明展示（「理解为」小字）+ 原问题保留消息历史可纠正 |
| Qdrant 不可用 | 沿既有降级模式静默跳过，问答主链路零依赖 |
| SummarizationToolMiddleware 参数与 monkey-patch 行为差异 | M1 装配时以 0.6.12 源码逐参数核对（30k trigger/keep 10 条/truncate 15 条），行为回归用例护航 |
| 中间件栈层数增加的性能叠加 | 栈内全部为轻钩子（Rubric 无 rubric 零开销、Patch 仅修悬空调用）；EngineQueryLog 已有耗时观测可量化 |
