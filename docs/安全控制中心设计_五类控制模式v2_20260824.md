# 安全控制中心设计：五类控制模式 v2（全部可关、可验证、有说明）

> 2026-08-24 · 设计窗口产出 · **用户定调修订版**，取代批13-E v1 的「红线不可关」设计
> 用户诉求四要素：①每类都有控制点 ②可以关闭控制 ③有按钮说明 ④启用该安全后能验证控制生效。

---

## 一、五类控制模式定义（守卫映射）

| # | 控制模式 | 包含守卫 | 控制什么 |
|---|---|---|---|
| ① | **能力控制** | 工具白名单（whitelist）+ 绝对禁止工具（absolute_tools）+ 数据到手收窄（stop_when） | 模型能调用哪些工具；拿到数据后哪些工具自动停用 |
| ② | **SQL 安全控制** | validate_sql（sql_safety） | 只读强制（仅 SELECT）、函数黑名单、LIMIT 上限 |
| ③ | **模板控制** | template_fingerprint | 场景 SQL 的 AST 结构指纹校验，仅【动态】WHERE 片段可变 |
| ④ | **引擎控制** | engine_lock | 数据源一致性（同一问题不得跨引擎拼装） |
| ⑤ | **输出控制** | output_contract | 明细重复禁止、口径披露、答案结构清洗 |
| ➕ | 审批轨（附加开关，非第五类） | interrupt_on 静态策略轨（批13-F F3） | 指定工具调用前强制人工审批 |

（原「六道守卫」中 whitelist/absolute_tools/stop_when 归并为能力控制，其余一一对应。）

## 二、每类控制点的标准规格（五件套）

每个控制点统一包含五件套，缺一不可：

```
┌───────────────────────────────────────────────┐
│ ② SQL 安全控制                      [开 ●]_   │ ← 开关（控制点）
│ 只读强制·函数黑名单·LIMIT 500                   │ ← 一行说明
│ ▸ 这控制什么：拦截一切非 SELECT 语句、危险函数、 │ ← 按钮说明（展开）
│   无 LIMIT 全表扫描自动加 500 上限               │
│ ▸ 关闭后失去：模型可拼任意 SQL；仍有兜底：Doris  │
│   连接账号只读权限（数据库层防线仍在）            │
│ ▸ 近24h拦截 3 次 · 近7天 17 次 [拦截记录]        │ ← 触发统计
│ [试探单] [参数: LIMIT值/黑名单维护]              │ ← 验证按钮+参数
└───────────────────────────────────────────────┘
```

1. **开关**：即时切换，热生效（TTL 5s 缓存 + agent 单例缓存键纳入守卫配置版本号）；
2. **说明文案**：固定三段式--控制什么 / 关闭后失去什么 / 仍有什么兜底（诚实登记纵深防御剩余层）；
3. **触发统计**：近 24h/7d 拦截次数 + 最近拦截样例（脱敏后可展开）；
4. **试探单（验证「启用后能控制」）**：按一下发一个必被拦的探针请求，返回 ✓已拦截（控制生效）或 ✗未拦截（控制失效，红色告警+通知）；
5. **参数区**（有参数的控制才有）：LIMIT 值、函数黑名单、相似度阈值等。

### 五类试探单探针定义

| 控制模式 | 探针 | 预期 |
|---|---|---|
| ① 能力控制 | 尝试调用白名单外工具（task） | 拒绝+理由 |
| ② SQL 安全 | 提交 `UPDATE t SET x=1` | 拒绝（非 SELECT） |
| ③ 模板控制 | 对场景步骤提交结构变异 SQL（换表） | 拒绝（指纹不符） |
| ④ 引擎控制 | 用 B 引擎执行 A 引擎模板 SQL | 拒绝（引擎不一致） |
| ⑤ 输出控制 | 含 500 行明细的答案文本 | 明细被清洗 |

试探单独立于真实问答链路（管理页直调 run_guards，不走 LLM，毫秒级返回），每次试探写审计（含结果），作为「该控制当前确实在管事」的可导出凭证。

## 三、可关闭的分级确认设计（取代「不可关」）

| 风险等级 | 控制模式 | 关闭时的确认强度 |
|---|---|---|
| 🔴 高危 | ② SQL 安全（只读部分）、① 能力控制（绝对禁止工具部分） | 二次确认弹窗 + **必须填写关闭理由**（进审计）+ 24h 自动提醒复查 |
| 🟡 中危 | ③ 模板、④ 引擎、① 其余、⑤ 输出 | 二次确认弹窗（理由选填） |
| 🟢 低危 | ② 参数类（LIMIT 数值）、各阈值 | 直接生效 |

配套两个全局按钮：
- **[全部恢复默认]**：一键回到安全基线（所有控制开启+默认参数）；
- **[导出当前配置]**：JSON 快照（含变更人与时间），可入 git 做配置版本化。

**fail-closed 语义调整**：配置加载失败仍全启用（不变）；但管理员显式关闭=显式授权，记录在案。守卫管道按「关闭=跳过该守卫」执行，不再强制任何守卫必开。

## 四、每类控制关闭后的剩余防线（诚实清单，写入按钮说明）

| 关闭的控制 | 失去什么 | 仍剩什么 |
|---|---|---|
| ① 能力控制 | 契约外工具拦截 | MCP 服务端只注册了 17 个业务工具（无 shell/写文件类）；数据库账号权限 |
| ② SQL 安全 | 只读强制/黑名单/LIMIT | Doris 连接账号本身只读（数据库层）；执行超时上限 |
| ③ 模板控制 | 场景 SQL 结构锁定 | ② SQL 安全仍拦截非 SELECT；引擎锁仍限单引擎 |
| ④ 引擎控制 | 跨引擎一致性 | ② 仍管语句安全；数据源账号权限隔离 |
| ⑤ 输出控制 | 明细清洗/口径披露 | 前端表格本身只展示已返回数据；敏感字段脱敏（如有） |

> 设计原则：每一层关闭后系统**降级但仍有多层兜底**；说明文案必须如实写明剩余防线，不夸大也不隐瞒。

## 五、后端实现规格

**表结构**（扩展批13-E 的 guard_policies）：
```sql
guard_policies: guard_id PK / enabled / mode / params JSON
                / risk_level VARCHAR(8)          -- red|yellow|green（决定确认强度）
                / confirm_required BOOLEAN       -- 是否需二次确认
                / updated_by / updated_at / close_reason VARCHAR(500)  -- 关闭理由（红级必填）
guard_events:   id / guard_id / ts / action(block|warn|probe) / question_digest
                / verdict(passed|blocked|probe_ok|probe_fail) / detail JSON
```

**API**：
- `GET /guards`：五类+审批轨的开关态、说明、统计、参数、风险等级；
- `PATCH /guards/{guard_id}`：切换/改参（body 带 confirm=true 与 close_reason；红级缺理由 -> 400）；
- `POST /guards/{guard_id}/probe`：执行试探单，返回探针结果+写 guard_events；
- `GET /guards/events?guard_id=&range=`：拦截/试探记录分页；
- `POST /guards/reset-defaults`：恢复默认基线。

**生效链路**：PATCH -> 更新表 + 版本号+1 -> run_guards 的 TTL 缓存 5s 内刷新 -> 若涉及 agent 装配（审批轨）则按版本号重建单例。变更与试探全部写审计三本账之一（治理账）。

**接入点不变**：SkillPolicy 内部改调 run_guards（批13-E 既定），本设计只改「可配置面」与「管理页」。

## 七、与批13-E v1 的差异对照（修订声明）

| 项 | v1（批13-E 原文） | v2（本文，用户定调） |
|---|---|---|
| 红线守卫 | 只读展示+API 拒改（403） | **全部可关**：红级=二次确认+必填理由+审计 |
| 三级分层 | 决定「能否关闭」 | 降级为「确认强度」标签 |
| 验证机制 | 无 | **试探单**：按需证明每类控制生效 |
| 说明 | 守卫列表页 | 每控制点三段式说明（控制什么/失去什么/剩什么） |
| 兜底 | fail-closed | fail-closed 保留（加载失败全启用）；显式关闭=显式授权 |

## 八、验收标准

1. 五类+审批轨全部有开关且可关闭（红级走确认+理由流程）；
2. 每个开关有完整三段式说明文案；
3. 任一控制开启时，点试探单返回 ✓已拦截且 guard_events 有记录（证明「启用后能控制」）；
4. 任一控制关闭后，同类探针返回 ✗未拦截（证明关闭真实生效，开关不是摆设）；
5. 关闭 SQL 安全后提交 UPDATE 探针 -> 守卫层放行但数据库账号层拒绝（剩余防线验证）；
6. 全部恢复默认一键回到基线；导出配置 JSON 可 diff；
7. e2e：默认配置下行为与现状一致；变更后 5s 内热生效。

**量级**：后端 API+表 1d，试探单五枚 0.5d，管理页 1d，接入 run_guards 沿批13-E 已有工作 -- 合计 2.5d（在批13-E 3d 基础上 +0.5d 试探单与确认流）。
