## 1. 目标与范围

一句话：**修掉稳定性硬伤，补上三个高收益能力（API 缓存 / 类型推断 / 分页），加一层轻量观测**。不新建前端页面，不引新抽象层。

**做**：连接池、串行锁、超时、错误分类、查询日志、API 内存缓存、类型推断、分页、IN 下推、健康探测、既有页面增强。
**不做**（见 §9）：EngineAdapter SPI、ES catalog 管理、Profile 代理、加速层/物化视图、Pushdown 调试器、独立引擎工作台、Prometheus。

## 3. 后端设计

### 3.1 稳定性修复（批1，全部小改）

**Doris 连接池**（doris_engine.py）--复用已有 SQLAlchemy，零新依赖：

```python
# 模块级懒加载，替代 get_conn() 的裸 pymysql.connect
from sqlalchemy import create_engine
def _pool():
    global _ENGINE
    if _ENGINE is None:
        c = _load_config()
        _ENGINE = create_engine(
            f"mysql+pymysql://{c['user']}:{c['password']}@{c['host']}:{c['port']}/{c['database']}",
            pool_size=3, max_overflow=3, pool_pre_ping=True, pool_recycle=1800)
    return _ENGINE
# 保存 DorisConfig 后调 _ENGINE.dispose(); _ENGINE = None（挂到现有保存接口）
```

**查询超时**：
- Doris：execute 入口给 SQL 包一层 `SELECT /*+ SET_VAR(query_timeout=60) */ * FROM (原SQL) t`（仅当无 LIMIT 约束的查询；Doris 原生 kill 超时查询）；
- DuckDB：`asyncio.wait_for(to_thread(...), timeout=120)`。

**DuckDB 串行锁**（duckdb_engine.py）：

```python
_DUCKDB_LOCK = asyncio.Lock()
async def execute_federated_async(sql, ...):
    async with _DUCKDB_LOCK:                       # v1 串行即正确
        return await asyncio.to_thread(_execute_federated, sql, ...)
```

内存护栏一次性设置：`SET memory_limit='2GB'; SET threads=2;`；每 endpoint 拉取行数硬上限 20 万行，超限报错并明示。

**异步包装**：`execute_doris_sql / execute_api_sql / execute_entity_api / execute_sql` 四个 handler 入口改 `await asyncio.to_thread(...)`；API 拉取暂留 requests（批1 不换 httpx，to_thread 已消除阻塞，换库收益再评估）。

### 3.2 错误分类（批1，6 类够用）

```python
class EngineError(Exception):
    cls: str   # CONNECTION | AUTH | SYNTAX | TABLE_MISSING | TIMEOUT | UPSTREAM_API
```

- Doris：按 pymysql errno 映射（2003/2013→CONNECTION，1045→AUTH，1064→SYNTAX，1146→TABLE_MISSING，超时标记→TIMEOUT）；
- DuckDB：httpx/requests 网络错→CONNECTION，HTTP 401/403→AUTH，sqlglot/duckdb ParserException→SYNTAX，duckdb CatalogException→TABLE_MISSING；
- 用途：`{"ok": False, "error": "...", "error_class": "TABLE_MISSING"}` 随 ToolMessage 返回，供 SkillPolicy「表/catalog 不存在才允许一次受控降级」的结构化判定（替代字符串匹配）。

### 3.3 查询日志（批1，一张新表）

```
EngineQueryLog: id / run_id / engine / sql_hash / sql / rows_returned
               / duration_ms / status(ok|error) / error_class / created_at
```

写入点：两个引擎 execute 出口统一落库（try/finally，异常不影响主流程）；默认 30 天清理，挂 TaskWorker 低优先级任务。保留策略：先不做界面，SQL 直查即可（批3 给最简列表）。

### 3.4 DuckDB API 内存缓存（批2，收益最大）

```python
# duckdb_engine.py 内新增，约 40 行
_CACHE: dict[tuple[str, str], tuple[float, pd.DataFrame]] = {}   # (endpoint_id, params_hash) -> (fetched_at, df)
_CACHE_MAX = 50   # 条目上限，LRU 淘汰
```

- **键**：endpoint_id + 规范化下推参数（排序后 sha1 前 8 位）；
- **命中**：`now - fetched_at < endpoint.cache_ttl_seconds`（新列，默认 300，0=禁用）-> 直接用缓存 DataFrame register，**零 API 调用**；
- **失效**：endpoint 配置保存时清该 endpoint 全部条目（挂现有 api_mapping 保存接口）；TTL 过期自然失效；
- **观测**：每 endpoint hit/miss 计数（内存 Counter，批3 出一个只读端点）；
- **披露**：命中缓存时结果附 `"data_snapshot_at": "HH:MM"`，前端 DataAccessCard 展示「数据快照 HH:MM」。

不做 parquet 落盘（重启丢失可接受：TTL 本来就 5 分钟级）；缓存不跨进程（单 uvicorn 进程，无问题）。

### 3.5 类型推断（批2）

- **时机**：endpoint「测试连接/保存」时取一页样本，推断 dtype（int64/float64/bool/datetime64[ns]/object）；
- **存储**：写进 ApiEndpoint.columns JSON 每列 `"dtype"` 字段（界面可改，推断只做初值）；
- **生效**：register 前 `df = df.astype(dtypes)`--数值 SUM/MAX、日期比较从此正确；
- **兜底**：astype 失败的列回退 object 并告警日志，不阻断查询。

### 3.6 分页拉取（批2，只做页码型）

ApiEndpoint 新列 `pagination`（JSON，可空）：

```json
{"page_param": "page", "size_param": "pageSize", "page_size": 500, "max_pages": 40}
```

- 配置了 pagination 的 endpoint：循环逐页拉取合并 DataFrame，直到空页 / max_pages 封顶（封顶记 CAPACITY 警告日志并在结果明示「已截断」）；
- 不做 cursor 型（现有上游接口都是页码式，YAGNI）；
- 逐页之间沿用现有 30s 单请求超时；总耗时受外层 120s 联邦超时约束。

### 3.7 IN 下推（批2，一处增量）

现有 sqlglot 解析（WHERE 常量提取处）补一个分支：`col IN ('a','b')` -> 多值参数 `params[col] = ['a','b']`（endpoint params 模板按数组传参；不支持数组的 API 自动回退内存过滤，行为不变）。返回值附 `pushdown` 数组（表/参数/值/来源谓词），给前端展示用--现有解析代码已有 AST，增量约 30 行。

### 3.8 健康探测（批3，极简）

```python
# 新文件 backend/app/services/engine_health.py，约 60 行
_SNAP: dict[str, dict] = {}    # engine -> {status, latency_ms, checked_at, error}
def get_health(force=False):   # 60s 缓存；doris: SELECT 1(走池)；duckdb: SELECT 1；physical: PG SELECT 1
```

- `GET /api/engine/health` 返回三引擎快照（status: ok|down + 延迟 + 最近错误）；
- batch_entity_source_mode 返回体加 `"engine_health": {...}`（只提示不拦路：推荐引擎 down 时 reason 附「引擎不可用」，仍按原逻辑返回，失败提前可预期）；
- 不做状态机、不做后台轮询线程（懒探测 + 缓存足够；工作台刷新即触发）。

## 5. 前端设计（批3，只增强既有页面，不建新页）

**DorisConfig 页**：
- 顶部加一行三引擎健康徽标（StatusTag：ok=success / down=error，60s 自动刷新）；
- SQL 试跑区加「EXPLAIN」按钮（次要按钮，结果用 dal-mono 展示）。

**ApiMapping 页（endpoint 表格）**：
- 列增加：缓存命中率（近 1h hit/miss，次要文字）、TTL（秒，行内可编辑）；
- 行操作增加「失效缓存」；
- 编辑 Drawer：columns 表格加 dtype 下拉（自动/文本/整数/小数/日期/布尔）；新增「分页」折叠区（启用开关 + page_param/size_param/page_size/max_pages 四输入）。

**DataAccessCard**（对话卡片）：
- 命中缓存时标注「数据快照 HH:MM」（tertiary 色 caption）；
- DuckDB 结果附 pushdown 摘要时折叠展示「下推 N 个条件」。

全部沿用 tokens/StatusTag/DrawerFooter 既有规范，无新组件库用法。

## 8. 与受控平台/既有约束的衔接

- `ENGINE_TO_TOOLS`、引擎唯一裁判、空结果不换引擎：零变更；
- 交叉点仅一个：error_class 供 SkillPolicy 受控降级判定（结构化替代字符串匹配）；
- 端口铁律（9030/28000/…）零触碰；前端零硬编码端口；
- 完整版中被裁掉的能力（ES catalog、Profile、加速层、SPI、工作台）见完整版文档，后续按需逐项启用，本版不产生任何与之冲突的结构。
