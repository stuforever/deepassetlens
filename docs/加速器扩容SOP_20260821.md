# 加速器扩容 SOP

> 2026-08-21 · R5 运营轻量（按需）· 预聚合加速器（P5）新场景落地四步
> 前置：P5 预聚合加速器已上线（`engine_accelerator.py` + 引擎工作台「预聚合加速器」卡 + `kg_engine_accelerators` 表）。

---

## 适用场景

高频且**无过滤/无分组/单表**的单值聚合查询（`SELECT COUNT(*)/SUM(col)/AVG/MIN/MAX FROM <单表>`），
平台层 `try_serve` 拦截同形 SQL，用 Doris 预聚合表亚秒返回，并标注「数据截至」。

> 不适用：带 WHERE/GROUP BY/JOIN/LIMIT、多表、非单值聚合 —— 加速器不拦截，走原执行路径（`try_serve` 返回 None）。

---

## 四步流程

### 第 1 步 · 写物化 SQL 模板（agg_sql）

从目标高频查询提取**同形**单值聚合，确定：

| 字段 | 含义 | 示例 |
|---|---|---|
| `source_tables` | 被拦截的源表名（可多个，命中即拦） | `["dim_cst_elec_cons_cust"]` |
| `agg_expr` | 被拦截的聚合表达式（**规范化后大写比对**，如 `COUNT(*)` / `SUM(energy)`） | `COUNT(*)` |
| `agg_col` | 预聚合表里存该聚合值的列名 | `cnt` |
| `refresh_sql` | 物化 SQL（建表/覆盖用），一般形如 `SELECT COUNT(*) AS cnt FROM dim_cst_elec_cons_cust` | `SELECT COUNT(*) AS cnt FROM dim_cst_elec_cons_cust` |
| `target_table` / `target_db` / `target_catalog` | 预聚合落点（Doris internal/test_db，默认） | `acc_cust_count` / `test_db` / `internal` |

### 第 2 步 · 注册加速器

工作台查看（`引擎工作台 → 预聚合加速器`卡，列表 + 刷新 + 刷新全部到期）；**注册走 API**：

```python
POST /api/engine/accelerators
{
  "name": "客户总数(count)",
  "description": "用电客户总数预聚合（P0 高频锚点）",
  "source_tables": ["dim_cst_elec_cons_cust"],
  "agg_expr": "COUNT(*)",
  "agg_col": "cnt",
  "target_catalog": "internal",
  "target_db": "test_db",
  "target_table": "acc_cust_count",
  "refresh_sql": "SELECT COUNT(*) AS cnt FROM dim_cst_elec_cons_cust",
  "refresh_minutes": 60,
  "staleness_note": true,
  "enabled": true
}
```

注册后**立即手动刷新一次**建表：`POST /api/engine/accelerators/{id}/refresh`（表不存在 → `CREATE TABLE AS`；存在 → `INSERT OVERWRITE`）。
到期自动刷新由 TaskWorker 每 5 分钟检查（`main.py` startup 注册 `register_refresh_job`）。

### 第 3 步 · 验证 try_serve 命中

对同形查询执行并断言命中标注：

```sql
-- 直接经引擎执行端点（如 /api/v1/api-endpoints/execute）
SELECT COUNT(*) FROM dim_cst_elec_cons_cust
```

命中特征（返回体）：
- `accelerated = true`
- `accelerator = {name, target_table, agg_expr, staleness_note}`
- `data_as_of = <最近刷新 HH:MM>`（新鲜度披露）

未命中自查：
| 现象 | 原因 | 处理 |
|---|---|---|
| 返回 `accelerated` 缺失 | 形状不符（WHERE/GROUP/JOIN/LIMIT/多 FROM/多聚合列） | 核对第 1 步形状 |
| `agg_expr` 比不中 | 规范化差异（大小写/空格/`*`） | `try_serve` 用 `str(agg_expr).upper().strip()` 与 SQL 的 `sql(dialect=duckdb).upper().strip()` 比对，注册时照填 |
| 源表名不中 | `source_tables` 未含该表 | 补表名 |
| 一直未命中且 `data_as_of` 旧 | `_is_fresh` 判定过期（age > refresh_minutes） | 手动刷新 或 缩短 refresh_minutes |
| 查询显式带 catalog | 跨 catalog 防护：查询 catalog ≠ target_catalog 不拦 | 不加 catalog 或对齐 target_catalog |

### 第 4 步 · 新鲜度披露确认

- `staleness_note=true` 时命中结果标注「数据截至 HH:MM（预聚合，TTL N 分钟）」；
- 以 `refresh_minutes` 为准承诺新鲜度（默认 60 分钟）；
- **上线前抽查**：对刚刷新表再查一次，确认 `data_as_of` 与 `last_refresh_at` 一致、结果与源表直查一致（口径锚点）。

---

## 已知护栏（勿动）

1. **跨 catalog 防护**：查询显式带 catalog 且与加速器 `target_catalog` 不一致 → 不拦截（基表同名跨 catalog 是不同实体，避免用错目录的预聚合值）。
2. **Doris 复制因子=1 护栏**：预聚合表依赖 Doris internal 表复制因子=1（单 BE 约束）；扩 BE 时需去掉该属性（遗留观察项）。
3. **分组加速器**：`agg_expr` 为空的分组加速器目标表可直接查（命中目标表时标注 `data_as_of`），与单值拦截是两条路径。

## 验收清单（新场景上线）

- [ ] 同形查询返回 `accelerated=true` 且带 `data_as_of`
- [ ] 手动刷新后 `last_refresh_at` 更新、结果与源表一致
- [ ] 新鲜度标注在命中结果中可见
- [ ] 非形状查询仍走原路径（`accelerated` 缺失 = 未拦截，正常）
- [ ] 跨 catalog 显式查询未被错误拦截
