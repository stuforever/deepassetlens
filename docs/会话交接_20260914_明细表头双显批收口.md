## 四、环境/陷阱（新窗口必读）

- **pytest 30s timeout 当日误杀**：机器重启后 AV 节流首导（~1s/文件×数百 langchain 模块），collection 超 30s 被 pytest-timeout 杀（marker「+++ Timeout +++」+importlib `get_data` 栈）——门禁加 `-o timeout=600`（CLI 非侵入，pytest.ini 未动）；环境恢复后回归默认口径。
- **jest 入口**：必须 `npm test -- --watchAll=false`（react-scripts）；`npx jest` 绕过其 TS 变换 → 全套件伪失败（`import type` 解析错）。
- **pydantic 导入悬挂窗口**：经 `app.api.freeplan` 包 `__init__` 导入会拉起全 FastAPI 栈，Python 3.13+pydantic v2 有导入期 `copy(annotation)` 递归悬挂风险（单跑侥幸过/组合挂）；`backend/tests/test_sql_columns_cn.py` 已用 importlib 直载 delivery.py 规避；REPL 导入长时无响应先疑此窗口。
- **后端无 reload**：改任何后端码必须重启 28000 进程。
- **WBS 题**「查询所有WBS及下属层级的对象状态信息」可卡 15+ 轮不定=红灯批已知方差形态（跨库 FeatureNotSupported 未修），**勿误判为其他批回归**；表头/裸列验证改用「查询台区台账前5条明细数据」。
- **诊断库**：MySQL **33066**（root/root tupu）数据窗停在 ~14:00，与主库 3306 **不同步**；`kg_agent_runs` 无 run_id 列（主键 id/run_code），排序用 created_at。
