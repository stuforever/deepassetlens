# M09 向量化与混合检索 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M09（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

语义管理域的**向量执行层**：Qdrant 客户端基座与集合族（词条/实体/属性向量）、向量同步与检索、**双后端架构**（Qdrant 集合 + MySQL 意图 embedding 表混合评分）、混合检索（分词/停用词/同义词扩展/域短语）、嵌入引擎（本地模型与 OpenAI 兼容 API 双模式）。为问数定位（M18/M16）与技能语义匹配（M13）提供检索底座。

**边界**：词条生命周期状态机归 M08（本模块是其执行体）；金标集合 tupu_golden_qa 归 M20（共享本模块客户端基座）；触发端点归 M06（data_sync）。

## 三、双后端架构（核心语义，全模块必须知道）

```
后端 A：Qdrant（外部向量库，docker tupu_qdrant 6333）
  集合族：tupu_standard_terms（词条，M08）
         entity_embeddings / attribute_embeddings（实体/属性，本模块）
         tupu_golden_qa（金标，M20）
  开关：TUPU_VECTOR_BACKEND=qdrant（启动期健康检查后切换——M01 钩子⑧）

后端 B：MySQL kg_semantic_embeddings 表（object_type/object_id/text_content/embedding JSON/
         model_name/content_hash/extra_meta）
  用途：意图→实体/源关系 语义打分（score_entities_semantic/score_source_relations_semantic），
       与关键词分混合（hybrid_score 按配置权重融合）——技能语义匹配（M13）消费
```

**为什么两个后端**：Qdrant 服务大规模近邻检索（词条/实体/金标）；MySQL 表服务小规模意图资产（意图向量数量级小，Python 内余弦足够，免外部依赖）。

## 四、Qdrant 基座契约（tupu_qdrant_client.py）

- env：QDRANT_URL（get_qdrant_url）、QDRANT_API_KEY（可选）、**TUPU_VECTOR_BACKEND**（is_qdrant_backend_enabled）；
- `QdrantClientError` 统一错误类型（上层据此降级）；`_to_filter`（must 条件 dict→Qdrant Filter）；
- TupuQdrantClient 封装：集合确保（按向量维度）/upsert/search/健康检查——所有集合操作经由封装，禁止散落裸 client。

## 五、三组向量集合语义

**tupu_standard_terms**（standard_semantic_qdrant.py）：集合名可按模型名分（get_standard_semantic_collection）；point 构建含 L2 归一化（_l2_normalize）+ 实体上下文（_entity_context 回链）；upsert（批量）/sync（全量，含删除失效）/query（top-k 相似）。启动钩子⑧ 同步。

**entity_embeddings / attribute_embeddings**（entity_attr_vector_service.py）：`sync_entity_vectors(db, force)` / `sync_attribute_vectors(db, force)`（force 重建集合；增量按 content hash）；`get_*_vector_stats`（计数）；`search_entity_vectors(query, top_k=15)` / `search_attribute_vectors`（问数定位链消费）。启动钩子⑩ **后台 daemon 线程**同步（不阻塞启动）。

**向量维度**：`_get_vector_size(db)` 从配置取（默认 1024，bge-large-zh-v1.5）；集合创建按维度。

## 六、嵌入引擎双模式（semantic_retrieval.py）

- **本地模型模式**：`_resolve_local_model_path`（仓库内模型目录）+ `_EmbeddingEngine`（本地推理）；
- **OpenAI 兼容 API 模式**：`_call_openai_compatible_embeddings`（按连接配置调远端 embeddings API——复用 M11 LLM 连接配置）；
- **模型注册表**：`get_vector_model_registry`（可用模型清单，M08 /vector-models 端点的数据源）；
- **配置**：`get_or_init_retrieval_config`（默认模型/混合权重，DB 持久化——M08 model-config 面）；
- **索引**：`rebuild_semantic_index(db)`（重建 MySQL 意图语义索引）+ `semantic_status`（状态——M13 smart-skills/semantic/status 消费）；
- **打分**：`hybrid_score(keyword_score, semantic_score, cfg)`（配置权重融合）、`score_entities_semantic(intent)`、`score_source_relations_semantic(intent)`、`_ensure_intent_vector`（意图向量缓存）。

## 七、混合检索（hybrid_retrieval.py）

查询侧词法管线：**停用词**（静态 `_STOP_WORDS` + M08 停用词表）→ **域短语优先**（`_DOMAIN_PHRASES` 静态 + `_DOMAIN_PHRASE_SET`）→ **同义词扩展**（静态 `_SYNONYM_MAP` 兜底 + `load_synonyms_from_db`（SynonymGroup enabled 组）→ `expand_synonyms_for_query(text, max_variants=6)`）→ **jieba 分词**（_ensure_jieba 惰性加载）→ **数字/单位过滤**（`_DIGIT_UNIT_RE`：纯数字+号年月日个户块元度千瓦瓦安伏兆 后缀不参与检索）→ `hybrid_search`（词法+语义融合，_normalize_score 归一）。

**同义词双源契约**：DB 组优先加载（load 后覆盖静态兜底）；无 DB 时静态表可用（冷启动不空转）。

## 八、设计原则（本模块特有）

1. **双后端各司其职**：大规模近邻→Qdrant 集合；小规模意图→MySQL 表；新需求先判规模再选后端；
2. **一切经封装**：集合操作只走 TupuQdrantClient，裸 client 禁止出现在业务层；
3. **同步幂等+增量**：force 重建、按 content_hash 增量跳过——重启/重触发零重复向量；
4. **降级不致命**：Qdrant 不可用→开关不切换/检索降级词法（不 500）；
5. **检索过滤纪律**：数字/单位 token 剔除、停用词剔除——防「2023年」这类 token 污染相似度；
6. **双源同义词**：DB 优先、静态兜底——冷启动可用。

## 九、验收标准

1. Qdrant 基座：集合按维度自动创建；filter 转换正确；不可用时上层降级路径有单测；
2. 词条集合：sync 后计数=enabled 词条数；查询 top-k 含 score；content_hash 未变重复 sync 零写入；
3. 实体/属性向量：force 重建后 stats 一致；search top_k 夹取；启动后台同步完成（日志）；
4. 意图语义：本地/API 双模式各出向量（维度一致）；rebuild 后 status 就绪；hybrid_score 权重融合正确；
5. 混合检索：同义词扩展（DB 组生效）；停用词/数字 token 剔除；域短语整词保留；
6. 与 M20 联测：金标集合经同一客户端基座工作。
