## 一、定位与背景（R2 重写）

**现状（亲证）**：tupu **已有轻量文档 KB（m15）**——上传→分块→向量化→检索全链在跑：每 KB 一个 Qdrant collection（`kb_` 前缀）、`embed_texts` 嵌入、原文落盘 `backend/data/kb_documents/{kb_id}/`、级联删除。**缺的是四纪律**：①索引/指针二分（只有索引型）；②四方法引擎协议（vectorize 逻辑未抽协议层）；③增量对账（无嵌入签名——何时该重嵌无依据）；④状态报告持有内容（状态有计数无对账细节）。

→ **④=m15 演进批**：加维度（type/指针）、抽协议、补对账、强报告。**不建第二套 KB 系统**（YAGNI 红线）。R1 的 KB 管理页/端点/表名（`kg_knowledge_bases`/`kg_kb_documents`）全部作废，改演进 m15 既有资产。

## 二、目标与非目标

**目标**：①KB 表加 6 列（type/rag_provider/pointer_params/embedding_signature/enabled/version）+文档表加 3 列（checksum/parse_cache_key/status 扩 stale）；②`kb_engines/` 引擎协议层（四方法）；③connected_es 指针族（不建不存，检索透传）；④reconcile/reembed 增量对账；⑤状态报告增强；⑥接入①（`knowledge_sources` 扩 `kb:{id}` + MCP 工具 `search_kb`）。

**非目标**（维持 R1）：云引擎（GraphRAG/LightRAG/PageIndex/IMA）；图谱型 KB；KB 评估回归门禁；多模态；跨 KB 联合检索；**m15 工单域（同 spec 另一半）零触碰**。

## 四、数据模型（M00：0 新表 +2 表加列）

**`kg_knowledge_base`**（既有：name/description/collection_name unique/storage_dir/doc_count/vector_count/status/error_msg）+ 新列：`type`/`rag_provider`/`pointer_params`/`embedding_signature`/`enabled`/`version`。

**`kg_knowledge_document`**（既有：filename/file_path/file_size/chunk_count/status/error_msg）+ 新列：`checksum`/`parse_cache_key`，`status` 枚举扩 `stale`。

**状态机扩展**：Doc：pending→(vectorize)→vectorized|error **+ stale**（reconcile 标记）；KB：ready⇄processing→error **+ degraded**（存在 stale/failed 文档——状态报告可见）。

## 五、服务层

```
services/kb_engines/
  base.py           # 四方法协议（RuntimeCheckable，hasattr 容忍部分实现）
  qdrant_family.py  # indexed：现 vectorize 流程协议化封装（复用 TupuQdrantClient/embed_texts）
  connected_es.py   # connected：外部 ES 检索透传（不建索引不存储，删除零触碰）
services/parsing/   # factory（格式→解析器）+ cache（checksum→解析结果）
```

**对账流水**（reconcile）：扫文档行签名 vs KB 级签名（模型/维度/分块参数任一变）→ 不一致标 `stale` → 状态报告列出 → reembed 按批处理（**未重嵌时检索照常**——旧索引不破坏）。**状态报告**（`GET /{kb_id}` 详情增强）：+type/签名一致性/stale 与 failed 文档清单/最后对账时间——「KB 报告持有内容」纪律。

## 六、API 与前端

既有 8 端点全保留（L108-357：GET 列表/POST 建/GET 详情/DELETE 删/POST upload/DELETE 文档/POST vectorize/POST search）。**新增**：`POST /{kb_id}/reconcile`、`POST /{kb_id}/reembed`；`POST /{kb_id}/search` 加 type 分路（connected→connected_es 透传）。建库端点表单扩 type/rag_provider/pointer_params（Pydantic 白名单校验，indexed 的 pointer_params 必空）。

**MCP 工具**（进①注册表）：`search_kb(query, kb_ids)`——检索面给专家；大结果 `_with_result_ref` 沉降。**前端**：VectorManagePanel 知识宝区增强（D10 四件套），选择器零改动。

## 七、错误处理与 Runbook

| 故障面 | 处理（沿 R1 判定，载体改 m15 端点/列） |
|---|---|
| Qdrant 不可用 | vectorize 失败→文档行 error+error_msg；search 返回可读错误（不静默空结果） |
| 解析失败 | 文档行 failed；不阻同批其他文档 |
| 指针型目标失联 | 状态报告标 unreachable+最后探测时间；不自动删注册 |
| 嵌入模型下线 | reconcile 标 stale 全量；管理页明示；不自动换模型 |

**Runbook**：0 无手工前置 → 1 上线后端（启动序列：**ALTER 两表加列**+存量回填 D2 默认值，幂等；m15 spec 变更记录已回写本批）→ 2 前端（知识宝区增强）→ 3 验证（对既有 indexed KB reconcile→报告清洁；建 connected mock→删除零触碰外部）。**回退**：git revert；新列无害保留；m15 工单域零触碰（回归底线）。

## 九、诚实账（R2 更新）

1. **升级路线工作量≈R1**（新建改演进），但零双系统零迁移零前端新页；
2. KB 状态机加 `degraded` 态——状态报告纪律的最小代价；
3. pdf/docx 解析器依赖实施先查、没有的格式 **422 明示**（维持 R1）；
4. 单文档删除的按 filter delete 考点（维持 R1——实施时验证 Qdrant filter 删除语义）；
5. `connected_es` 仍是指针族唯一实现——价值=**验证指针语义**（不复制不重建删除零触碰），更多指针目标等真实需求（维持 R1）；
6. R1 的表名/端点/页面设计与 m15 的关系已在 R2 彻底修正——附件一判定行同步更正（「无文档 KB」→「已有轻量文档 KB（m15），缺四纪律」）。
