# M20 金标锚定与直通 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M20（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

问数智能体域的**金标准答案资产层**：金标库（已验证问题-SQL 对，kg_golden_qa_set + Qdrant tupu_golden_qa 集合）、两级检索（Tier1 确定性规范化保底 + Tier2 语义增强）、检索单调用化与短窗缓存（bundle 一次 embedding 双集合）、锚定注入（契约金标块+实体提示块）、**直通判定**（首选计划 0.90 / rubric 0.85——编排与装配层的判定阈值，本模块供命中数据）、种子提炼（成功查询日志→候选→审核入库）、命中计数与反馈记录。批13-C 题库移除后，金标是唯一示例资产（qa_example_service 已退役）。

**边界**：注入调用点与直通执行指令在 M16（编排）；rubric 自评中间件在 M17（装配）；Qdrant 基座在 M09；种子数据源 MetricQueryLog 归 M10；直通豁免判定用 M18 意图族。

## 三、两级检索（核心）

```
Tier1 确定性保底：DB 全量金标（≤百行级）Python 规范化比对
  question_norm == 规范化输入（含计数同义归一口径：「数量/多少个/多少」→「总数」）
  命中 score=1.0 —— 弱 embedding 环境下「同类问题二问」确定性命中
Tier2 语义增强：问题向量 → Qdrant tupu_golden_qa（阈值默认 0.75）
  payload.enabled 快照可能与 DB 漂移（启用态先落 DB）——以 DB 复核为准
Qdrant/向量不可用 → 静默降级仅 Tier1（不阻断问答）
top 默认 3（_MAX_TOP）
```

**规范化族**：_norm_question（空白/标点规整）+ _CORE_SUFFIX_RE（剥「主数据/业务数据/台账/拉链表」等核心词后缀）+ _count_normalize（计数同义归一）；_infer_engine（从 SQL 推断引擎兜底）。

## 四、检索单调用化与短窗缓存（retrieve_golden_bundle）

**一次 embedding 双集合并搜**（批13-C）：金标集合 + 实体向量集合（实体提示 build_entity_hint_block 同产出）——直通判定/自评豁免共享同一份 golden_hits（不重复检索）。
**短窗缓存**（E2）：_bundle_cache OrderedDict（TUPU_BUNDLE_CACHE_TTL 60s / SIZE 128）——同问题 60s 内二次提问零远程检索；clear_bundle_cache 管理/测试用。

## 五、锚定注入与直通判定（判定阈在消费层）

**锚定块**（build_golden_payload）：「金标锚定（已验证查询，仅供构造参考，禁止照抄执行）」+[金标N] 问题+SQL 列表——注入 M16 契约 SystemMessage；无命中/降级时 block 空串 hits 空（不阻断）。
**首选计划直通**（M16 编排层判定，本模块供数据）：top score ≥ **TUPU_DIRECT_PLAN_SIM（0.90）** 且带 SQL → lock_engine + 直执行指令（金标 SQL 仍过 validate_sql 与 SkillPolicy 全链——写错有纠错兜底）；
**Rubric 直通**（M17 装配层判定）：阈值 **0.85**（展示 0.75 < rubric 0.85 < 首选计划 0.90 三级递进）；
**直通豁免**：has_dynamic_condition（最新/当前）/has_negation（否定）——M18 意图族；动态条件与否定语义禁止直通（答案会随时间/口径变）。

## 六、种子提炼与生命周期

**seed_golden**（SEED_MAX 60）：从 kg_metric_query_logs 种子——query_status=="success" 的成功查询（M10 联动）按热度/时长筛选入库；**reseed**：向量重建（Qdrant 集合重灌）。
**候选推荐**（list_candidate_recommendations，days=7 top_m=10）：近 7 天成功查询提炼候选清单——前端审核后入库（人机协同扩金标）。
**生命周期**：add（人工录入）/set_status（启停）/delete（DB+Qdrant 双删）/hit_count 计数（bump_golden_hit——命中热度）/record_feedback（run_id+verdict 反馈记录）。
**同步纪律**：add/update/delete 即时同步 Qdrant（_sync_golden_qdrant upsert/_delete_golden_qdrant）——payload enabled 快照漂移以 DB 复核为准。

## 七、设计原则（本模块特有）

1. **确定性优先语义增强**：Tier1 规范化精确命中永远先于向量检索——弱 embedding 环境不瞎；
2. **金标只供构造参考**：锚定块明示「禁止照抄执行」——直通另走严格阈值+全链校验；
3. **三级阈值递进**：展示 0.75 < rubric 0.85 < 首选计划 0.90——越接近自动执行越严格；
4. **动态条件与否定豁免直通**：时间敏感/否定语义的金标 SQL 会给出过时答案——宁可重走定位；
5. **双存一致性以 DB 为准**：Qdrant payload 是快照，启用态以 DB 复核；
6. **检索单调用化**：一次 embedding 双集合+bundle 共享（直通判定/自评豁免/锚定注入零重复检索）。

## 八、验收标准

1. 两级检索：Tier1 规范化命中 score=1.0（含计数归一）；Tier2 阈值过滤；Qdrant 挂时降级仅 Tier1 不阻断；
2. 规范化：核心词后缀剥离（「用电客户主数据」≈「用电客户」）；计数同义归一；
3. bundle：一次调用双集合（golden+entity_hint 块）；60s 内同问题缓存命中零远程；
4. 直通三阈值：0.75 展示锚定/0.85 rubric/0.90 首选计划（M16/M17 联测）；动态条件与否定豁免生效；
5. 种子：seed 从 success 日志入库 ≤60 条；reseed 向量重建后检索仍命中；
6. 候选：近 7 天推荐清单；审核入库流程可用；
7. CRUD 双存同步：启停后 Tier2 立即不再命中（DB 复核）；删除后两存皆无；hit_count 递增；
8. 反馈：record_feedback 落表（M22 观测联测）。
