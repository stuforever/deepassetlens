# 教学引擎⑤d 教材引擎——分批实施 spec（承接⑤spec §六）

> **定位**：⑤d=教材→课程块的编译特化，挂④（m15 演进后）文档 KB。供 writing-plans 出该批计划；不修改已过审⑤总 spec 与④ R2。
> **依赖**：④ R2（parsing factory+`kg_knowledge_document` 加列）。

## 一、设计边界（对④的全部修改点，两项）

1. **parsing factory 白名单扩 `book` 族**：`services/parsing/factory.py` 注册 `book` 解析器（md/txt/pdf/docx 教材文件→块结构）；
2. **文档表加 `blocks_json` 列**：`kg_knowledge_document.blocks_json`（MySQL，解析产物缓存语义——省第五张 PG 表，⑤spec §二口径）。

## 二、块结构与编译流程

**`book` 解析器输出（`blocks_json`）**：

```json
[{"seq": 1, "type": "text",     "title": "…", "content": "…"},
 {"seq": 2, "type": "quiz",     "title": "…", "items": [{"q": "…", "options": ["…"], "answer": 0}]},
 {"seq": 3, "type": "flash_card", "front": "…", "back": "…"},
 {"seq": 4, "type": "animation", "spec": {"…动画描述，H5 渲染…"}}]
```

**编译流水**（教材上传→④ vectorize 之外新增一步）：解析（book 族）→ 块结构写 `blocks_json` → 正文仍走④分块嵌入（collection 检索面）→ H5 页面按 `seq` 读 `blocks_json` 渲染课程。**块=结构面（MySQL 行），嵌入=检索面（Qdrant）——两面一次编译同时产出**。

**DeepTutor 纪律源**：`book/` 8 py（compiler/engine/streaming/models）——块类型三起步（text/quiz/flash_card；animation 的 spec 先留接口）。**本会话未深读 book/**：块 schema 字段以 DeepTutor `book/models.py` 为准，实施第一步=亲读 8 文件后对本 spec 的块 schema 做一次校准回写（设计窗口纪律：引用不悬空→实施时校准）。

## 三、教材 KB 实例流程（⑤f 前完成）

1. 管理页（向量管理页知识宝区）建 KB：`type=indexed`，命名「教材库」；
2. 上传教材文件（格式校验：`book` 族支持的格式白名单，其余 422）；
3. 编译：blocks_json 落列+嵌入入 collection（同一 vectorize 流程扩展）；
4. ⑤c 卡 `knowledge_sources` PATCH 为 `["ontology_graph", "kb:{id}"]`（卡版本+1→缓存重建）。

## 四、验收（对齐⑤spec A3 部分+④ A5 联动）

- [ ] 教材上传→`blocks_json` 有块（seq 连续/type 合法）+collection 有向量（检索命中正文）；
- [ ] 同一文件重复 vectorize→不重复解析（④ checksum 缓存纪律在本族生效）；
- [ ] ④既有 KB（非 book 格式）行为零变化（factory 分族隔离）；
- [ ] H5 消费预检：`GET /{kb_id}` 详情含 blocks 概要（块数/类型分布——状态报告扩展一行）。

## 五、诚实账

①`book/` 8 py 未亲读——本 spec 定**边界与接口**（两项④修改点+块类型集），块 schema 实施时校准（防照抄不适用字段）；②animation 块先留接口不实现渲染（H5 动画成本高，等真实教材需要）；③教材与「题目资产」的关系（母题→图谱）不在本批——教材是**课程载体**，母题是**练习资产**，两轨在⑤b 工具面汇合（select_exercises 同时查图谱与教材变式）。


## 六、校准回写（⑤批3.1 实测：book/ 9 py 亲读——models 18545B/blocks 子包 19 文件/compiler 12638B）

**DeepTutor Block 实测形状**（models.py L326-345，pydantic extra=allow）：`{id(blk_xxx), type, status, title, params, payload, source_anchors, metadata, error, created_at, updated_at}`；`BlockType` 实测 **18 种**（text/callout/quiz/user_note/figure/interactive/animation/code/timeline/**flash_cards**/deep_dive/section/concept_graph/diagnostic/pretest/retrieval_practice/error_diagnosis/module_test/progress_dashboard）；`Page`=有序 Block 序列（L363-381）。三起步块校正：

1. **`flash_cards`（复数）**——本 spec §二样例写作 `flash_card`，与源码枚举不符，**以源码 `flash_cards` 为准**（H5 渲染侧同名词对齐）；
2. **两个形状分层**：DeepTutor Block=引擎内存模型（含 status/anchors/params 运行态字段）；tupu `blocks_json` 列=**精简消费行**（本 spec §二样例形状保留：`{seq,type,title,content|items|front/back|spec}`）——不照搬 Block 全字段（运行态字段在 tupu 无承载语义）；
3. **animation 只留接口**：BlockType.ANIMATION 存在于枚举，book 解析器不产 animation 块（诚实账②不变）。

**tupu `blocks_json` 行形状（校准定稿）**：type ∈ {text, quiz, flash_cards, animation(仅接口)}；行字段=§二样例（seq 连续从 1；text→content；quiz→items[{q,options,answer}]；flash_cards→front/back）。
