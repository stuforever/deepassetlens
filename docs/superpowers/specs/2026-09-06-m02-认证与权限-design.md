# M02 认证与权限 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M02（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

平台统一鉴权面：**Authentik OIDC 验签（RS256）+ RBAC 三角色 + 资源级 ACL + 前端 OIDC 客户端**。开发/生产双模式（`ENABLE_AUTH` 开关），SSE 流式链路不断流（纯 ASGI 中间件）。

**组件清单**：

| 组件 | 文件 | 职责 |
|---|---|---|
| 权限核心 | `app/core/auth.py`（626 行） | JWT 验签（JWKS 缓存 600s）、AuthUser、用户 upsert 镜像、AuthMiddleware（纯 ASGI）、权限判定链 |
| 认证 API | `app/api/auth.py`（194 行） | 6 端点：config/me/dev-login/users/grant/grant 撤销 |
| 权限模型 | `app/models/auth.py` | 4 表（见 §三） |
| 前端 OIDC 客户端 | `frontend/src/auth/oidc.ts` | 拉配置、授权码流换 token、/me 身份、静默续期 |
| 前端注入 | `frontend/src/services/http.ts` | axios 拦截器自动塞 Bearer |

## 二、设计原则（本模块特有）

1. **双模式一把闸**：`ENABLE_AUTH=0`（默认，开发）——中间件短路，请求塞匿名 user，`/auth/dev-login` 可直连签发；`ENABLE_AUTH=1`（生产）——所有非公开路径要求 Bearer JWT；生产安全三件套（`ENABLE_AUTH=1` 必须配 `CORS_ORIGINS`+`AUTHENTIK_JWKS_URL`）在启动期 **fail-fast**（main.py L47-59，先于任何 DB 初始化）。
2. **纯 ASGI 中间件，SSE 不断流**：AuthMiddleware 直接操作 scope/send/receive 透传（main.py L248-250 注释明示：BaseHTTPMiddleware 会断 StreamingResponse）——问数域 SSE 依赖此性质，**禁改回 BaseHTTPMiddleware**。
3. **用户是镜像不是账户**：auth_users 不存密码；登录时按 JWT claims 自动 upsert（`_upsert_user`），groups 快照留 JSON 列供调试与角色刷新；角色基线由 Authentik group claim 映射（`GROUP_ROLE_MAP`：tupu-admin→admin / tupu-operator→operator / tupu-viewer→viewer）。
4. **路径白名单三档**：`_PUBLIC_PATHS`（/ /docs /openapi.json /redoc /auth/config /auth/dev-login 前缀放行）；`_OPTIONAL_AUTH_PATHS`（/auth/me 有 token 就解析、无则匿名）；`_MCP_INTERNAL_PATHS`（/mcp 走内部服务身份：`X-Internal-Service: tupu-agent` 头，不要求 OIDC——P3-a，Agent 自身调 MCP 的通道）。
5. **验签容错**：JWKS 拉取失败回退旧缓存（600s TTL + 锁）；access_token 缺 username/groups 时补调 userinfo 端点取完整 profile。

## 三、数据模型（4 表，models/auth.py）

| 表 | 关键列 | 语义 |
|---|---|---|
| `auth_users` | sub(String64 PK, Authentik UUID)、username(index)、groups_snapshot(JSON)、last_login_at | 登录镜像 |
| `auth_roles` | code PK（admin/operator/viewer/custom）、default_permissions(JSON，如 `{"skill":["read","write","execute"]}`)、is_system | 角色定义 |
| `auth_user_roles` | user_sub FK + role_code FK、uq_user_role 唯一、granted_by/at | 用户-角色 N:N |
| `auth_resource_acl` | resource_type + resource_id（`*`=全量）+ principal_type(user/role) + principal_id、actions(JSON)、expires_at、uq 四元组唯一 + 双索引 | 资源级授权（「把 skill_x 的 read 授给 user_y」） |

## 四、权限判定链（五级，任一命中即放行）

```
1. 用户绑 admin 角色 → 全部允许
2. ResourceACL(principal=user, type, id) 命中 actions
3. ResourceACL(principal=role, type, id) 命中（用户任一角色）
4. ResourceACL(principal=role, type, id='*') 命中
5. Role.default_permissions[type] 含 action
```

两个使用面（core/auth.py L20-27 用法示例）：
- **路由级**：`Depends(require_permission("skill", "read"))`——装饰进 FastAPI 依赖；
- **资源级**：`check_resource_permission(request, "skill", code, "read")`——资源 id 在路径里时。

## 五、API 面（api/auth.py，prefix=/api/v1/auth）

| 端点 | 权限 | 说明 |
|---|---|---|
| GET `/config` | 公开 | OIDC discovery（issuer/client_id/redirect_uri/三个 endpoint/scopes），前端登录跳转用 |
| GET `/me` | 可选 token | 当前身份（无 token=匿名） |
| POST `/dev-login` | 仅 ENABLE_AUTH=0 | 开发模式直连签发 |
| GET `/users` | require_permission("auth","read") | 用户列表含角色与 groups 快照 |
| POST `/grant` | require_permission("auth","write") | 授权（principal user/role + actions + expires_at；四元组存在则改写） |
| DELETE `/grant/{id}` | require_permission("auth","write") | 撤销授权 |

## 六、前端侧

`frontend/src/auth/oidc.ts`：启动拉 `/api/v1/auth/config` → enable_auth=1 时走授权码流（redirect 回调页换 token，token_type Bearer）；`/auth/me` 校验身份；`services/http.ts` axios 拦截器对所有 `/api/**` 自动注入 `Authorization: Bearer <token>`。enable_auth=0 时前端预置匿名态（登录入口隐藏）。

## 七、与其他模块的契约

- M01：启动 fail-fast 三件套检查 + `add_middleware(AuthMiddleware)`（main.py L250）；
- M16：SSE 流式端点必须在 AuthMiddleware 之后仍透传（纯 ASGI 保证）；
- M17/M08：MCP `/mcp` 路径走内部服务身份头，Agent 工具加载不受生产鉴权影响；
- 各管理域 API：按 `require_permission(<域>, <action>)` 声明（skill/workflow/data_source/metric/auth…）。

## 八、验收标准

1. ENABLE_AUTH=0：全平台可用（匿名 user 贯穿），dev-login 可签发；
2. ENABLE_AUTH=1：无 token 访问非公开路径 → 401 JSON；伪造/过期/错误 aud token → 401；合法 token → 验签通过 + 用户 upsert（last_login_at 更新）；
3. 权限链五级各有单测（admin 直通/user ACL/role ACL/role 通配/默认模板）；
4. grant→撤销 全流程（含 expires_at 过期失效）；
5. SSE 长流在鉴权开启时不中断（e2e：流式问答完整送达）；
6. `/mcp` + `X-Internal-Service: tupu-agent` 在 ENABLE_AUTH=1 下可访问。

## 九、风险与偏差登记

| 项 | 说明 |
|---|---|
| dev-login 仅限开发 | ENABLE_AUTH=1 时端点自动 403（实现须自证） |
| JWKS 旧缓存窗口 | 拉取失败回退旧 key（最长 600s 窗口内轮换的 key 不生效）——登记可接受 |
| 角色→资源映射粒度 | 资源级 ACL 目前由 grant API/管理面维护，无自动过期清理任务（expires_at 判定在查询时）——YAGNI 不加清理 job |
