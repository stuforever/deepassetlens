# M05 图谱引擎与同步 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M05（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

图谱建模域的**引擎层**：MySQL 概念/实体/关系到 Neo4j 的投射与同步、图查询服务（树/子图/邻居展开）、面向 Agent 工具的 kg_api HTTP 面、图可视化数据端点、图谱辅助资产（schema 字典/Cypher 模板/本体度量）。

**边界**：概念/实体/关系建模 CRUD 归 M03/M04（本模块消费其表）；kg_api 被 M08 的 MCP kg 工具调用（HTTP 面）；execute_sql/validate_safe_sql 的执行安全与 M21 安全执行器协同；前端画布归 M03（消费 graph/data、graph/neo4j-data）。

## 三、Neo4j 投射模型（新体系，权威）

**单一 Category+ChainRoot 体系**（`sync_all_to_neo4j` L261-393）：

```
节点：ChainRoot{code: ROOT_MD 主数据链根 | ROOT_BZ 业务链根}
     Category{code}——概念: code=f"{L{level}}-{concept_id[:8]}"，level/chain_type/entity_type=category
                    实体: 仅挂 L2/L4 概念下的实体；level=L2X(MD)/L4X(BZ)，code=entity_code，entity_type=leaf，
                          附 entity_en_name/is_main_table/data_layer
关系：HAS_PARENT（概念→父概念；实体→所属概念）
     BELONGS_TO_CHAIN（L1/L2/L2X→ROOT_MD；L3/L4/L4X→ROOT_BZ）
     RELATES_TO（实体关系：relation_id/label=关系名/category/cardinality/join_expr 属性）
幂等：全部 MERGE on code；force=True 先 MATCH (n) DETACH DELETE n 全库清空
返回：{ok, concepts_synced, entities_synced, relations_synced, total_nodes, total_relations, took_ms}
```

**跳过规则**：实体只投射 L2/L4 概念下者（其余 continue，L321）；Neo4j 不健康直接 `{"ok": False, "error": "neo4j_unavailable"}`（静默降级，不抛）。

**辅助同步**：`sync_entities_and_relations_from_mysql(force)`（L70-165，实体/关系面刷新）；`expand_entity_neighbors(entity_ids, max_hop=1~3 夹取, limit≤200)`（L165-243，返回邻居+路径关系类型+hop——问数定位链消费）；`fetch_l1_l3`/`fetch_children_by_parent`（树查询）；`wipe_neo4j`/`_count_all`。

## 八、设计原则（本模块特有）

1. **投射单向**：MySQL 是唯一事实源，Neo4j 是投射视图（force 重建幂等）——Neo4j 上不做业务写；
2. **连接隐藏**：LLM/前端永远经 HTTP 面（kg_api）访问图谱，连接串不出后端；
3. **健康降级**：Neo4j 不可用→同步返回 ok:False、邻居展开返回 []、启动 warning 继续（不阻断平台）；
4. **参数夹取**：hop 1-3、limit 1-200、字段裁剪（expand L200-201）——工具层防滥用；
5. **code 即幂等键**：概念 code=`L{n}-{id前8}`、实体 code=entity_code——MERGE 语义依赖此约定，改码=破坏幂等。

## 九、验收标准

1. 空库→sync_all(force)：节点/关系统计与 MySQL 计数一致（L2X/L4X 投射规则、RELATES_TO 属性完整）；重复执行零增长（幂等）；
2. 实体改挂概念→重同步后 HAS_PARENT 更新；非 L2/L4 概念下实体不投射；
3. expand_entity_neighbors：1~3 hop 结果含 rel_type/label/hop，越界参数被夹取；
4. kg_api 9 端点：非法输入 4xx；execute_sql 走安全校验链（与 M21 联测）；
5. Neo4j 停机：启动成功（warning）、kg_api 图查询降级不 500；
6. /graph/data、/graph/neo4j-data、subgraph-by-l1 三端点形状满足 M03 画布渲染。
