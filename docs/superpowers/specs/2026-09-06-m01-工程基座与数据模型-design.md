## 一、模块定位

全后端的**地基**：进程入口、启动生命周期编排、数据库连接核心、83 张表的数据模型全景、幂等种子初始化、后台任务工作线程、环境变量与端口纪律。所有上层域（图谱/资产/语义/指标/问数……）的模型与服务都挂在这块地基上。

## 二、设计原则（本模块特有）

1. **单进程纪律**：workers=1 是硬约束（Agent 单例缓存、内存观测单值、会话锁都以单进程为前提）；扩容走多实例前的架构评审，不许改 workers 数绕过。
2. **启动钩子失败语义分级**：
   - **fail-fast**（阻断启动）：生产安全检查（`ENABLE_AUTH=1` 时缺 `CORS_ORIGINS`/`AUTHENTIK_JWKS_URL` 即 RuntimeError，且必须在任何 DB/外部初始化**之前**——F3-fix 铁律）；
   - **静默降级**（记 warning 继续）：Qdrant/Neo4j/向量同步、事件清理、周期任务注册、MCP 检查、Agent 预热——外部依赖不可用时平台核心功能（MySQL 上的管理域）必须能起来。
3. **幂等种子**：init_db 全部「表空才插」或「存在才补列」，重复启动零副作用；图谱概念/实体**不做内部种子**（由建模页面维护，init_db L317-319 明示）。
4. **轻量兼容迁移**：不用 Alembic，用 `ensure_schema_compatibility()`——INFORMATION_SCHEMA 查列存在性→缺列 ALTER ADD（如 kg_entities 7 列补齐 + source_mode 值迁移 L46-70）；新表交给 `Base.metadata.create_all`。
5. **模型约定**：`String(36)` UUID 主键（`_uuid_str` 默认）、`created_at server_default func.now()`、JSON 列存结构化数据、遗留源表保留 camelCase 列名（sysName/enName——外部导入数据的原貌，不强改）。

## 五、TaskWorker 设计

- 单守护线程顺序消费：`status=="pending"` 按 `priority asc, created_at asc` `with_for_update` 取任务→标 running→**expunge 后独立 session 执行**（避免长事务）；
- 执行体：`ExecutionEngineV2(db).execute(skill_id, input_payload, created_via="schedule")`——调度触发的技能执行；
- 失败重试：`retry_count < max_retries` 则回 pending 并计数；
- 周期钩子：`register_periodic(interval, fn)` 低优先级（查询日志 30 天清理、加速器 300s 刷新到期检查），异常隔离不影响队列消费；
- 管理器：TaskWorkerManager.start/stop（优雅停止 Event）。

## 六、环境变量与端口纪律（AGENTS.md 铁律摘录+实施）

- 后端 28000（`__start_8000.py`，文件名历史遗留）、前端 dev 23000、前端禁硬编码端口（setupProxy 统一转发）；
- Docker 端口表固定（MySQL 3306/PG 25432/ES 11200/Doris 9030·18030·18040/Neo4j 7474·7687/Qdrant 6333-6334/Authentik 9100·9143/Sandbox 9385）；
- `DATABASE_URL`（database.py L8-11，含 dev 兜底值；生产用 backend/.env 注入）；`ENABLE_AUTH`/`CORS_ORIGINS`/`AUTHENTIK_JWKS_URL`（生产安全三件套）；`TUPU_VECTOR_BACKEND`（启动时按 Qdrant 健康自动切）；
- 后端重启必设 `PYTHONUTF8=1`（Windows GBK 遇 ⟦⟧ 字符崩流）。

## 七、验收标准（本模块金标准判据）

1. 冷启动（空库）：create_all 建 83 表 + 5 类种子就位 + 平台可登录可管理；重启（已有库）：零重复种子、兼容迁移幂等；
2. 外部依赖全断（Qdrant/Neo4j/LLM）：启动成功（warning 日志在案），MySQL 管理域功能可用；
3. ENABLE_AUTH=1 且缺安全三件套：启动被阻断（fail-fast 先于任何 DB 写）；
4. TaskWorker：优先级顺序、重试上限、周期钩子按间隔执行（单测覆盖）；
5. 全部表模型可 `Base.metadata.create_all` 无冲突（模型注册集中在 main.py L26-35，防循环导入）。

## 八、风险与偏差登记

| 项 | 说明 |
|---|---|
| 无 Alembic 迁移框架 | 刻意取舍：轻量列级兼容迁移够用；重大 schema 变更走批次设计（如批13-C _ensure_golden_columns 模式）；若未来表结构变更频繁再评估引入（YAGNI） |

| 遗留 camelCase 列 | 外部导入数据原貌保留；新表一律 snake_case |
