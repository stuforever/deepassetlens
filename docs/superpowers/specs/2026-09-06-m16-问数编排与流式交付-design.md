# M16 问数编排与流式交付 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M16（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

问数智能体域的**编排与流式交付层**：freeplan 流式问答主链路（SSE 帧管线）、HITL 恢复、会话锁、think 流双通道分流、收尾交付纯函数族、编排期契约注入调用点、辅助端点（路由预览/技能目录/记忆清理）、前端对话组件族。**「数据资产探查」页是 e2e 验收标准页**（AGENTS.md 铁律）。

**边界**：契约对象/路由决策归 M18（本模块在编排期调用注入）；Agent 装配与工具注册归 M17；金标检索与直通判定归 M20（本模块消费 bundle）；引擎执行归 M21；SkillPolicy 守卫归 M19。

## 三、请求/响应与 SSE 契约

**ChatRequest**：thread_id（默认 uuid4）/user_input/**user_selection**（用户点选的实体/属性/层级上下文：label/value/name/code/level/entity_code/attribute_code/is_main_table）/format（default|card）/llm_connection_id（显式选连接——M11 by-id 路径）/mode（free_plan）。
**ChatResponse 字段族**：current_task/goal/pending_clarification/confirmed/completed_tasks/flags/trace/think_stream/recommended_next/next_step_recommendation/message_card。

**SSE 事件面**（文件头契约 L6）：`think / token / final / recommend / sql_result / trace / done`（另有 decision_draft·answer_draft 增量帧——见 §五分流器）。

**HITL**：POST /chat/freeplan/resume（挂起-恢复：等待用户确认后续跑，HITLResumeRequest）。

## 四、编排主链（chat_freeplan_stream）

```
会话锁（同 thread 串行；锁池上限 200 清已解锁旧锁）
→ run_prep（准备段：路由/契约/状态读取/检索预取【批13-N5：与锁/路由并行】）
→ Agent 执行（M17 装配的 DeepAgent 实例；llm_connection_id 透传 M11）
→ think 流分流（translator 状态机逐 token 分帧）
→ 工具结果捕获（sql_result 等）
→ 收尾段（delivery 纯函数族）
→ done 帧（完整载荷收口）
```

## 五、think 流双通道分流（ThinkRoundClassifier）

前缀状态机六状态：`WAIT`（前缀未定攒 token）→ `DECISION_FIRST/ANSWER_FIRST`（首帧冲刷积压）→ `DECISION_DELTA/ANSWER_DELTA`（增量帧）→ `SKIP`（notes 不推帧）。识别标记：`【下一步判断】`（决策/答案分界）与 `## SESSION INTENT / ## SUMMARY / ## ARTIFACTS / ## NEXT STEPS`（工具注释类跳过）。**语义**：模型思考流被拆成「决策草稿」与「答案草稿」双通道增量推帧——前端可区分显示过程与结论。

## 六、收尾交付（delivery.py 纯函数族）

| 函数 | 语义 |
|---|---|
| extract_final_answer_from_state | 从消息态提取最终答案 |
| **apply_output_contract(forbid_md=True)** | 输出契约：**禁 Markdown 明细表**（完整明细由前端查询结果表唯一展示——与契约常量 _CONTRACT_OUTPUT_SUFFIX 同规） |
| build_sql_result_payload | 查询结果载荷（含 assembled_sql） |
| build_confirmed | 已确认事实集 |
| build_evidence | **证据链**（contract+tool_results+final_answer——可追溯性交付） |
| build_recommendations | 推荐下一问（默认三连：「统计用电客户总数/查客户的联系电话/什么是变压器」） |
| build_done_payload | done 帧完整载荷 |

## 七、编排期契约注入调用点（_build_contract_system_message）

构造器属本模块（data_intelligence.py L105-263），消费 M18/M20 能力：契约骨架行（场景/步骤/允许禁止工具/模板/范围/引擎/终止/输出模式——固定文案逐字节一致，**批5-C1 前缀缓存纪律**）；条件段（locate_first 定位四步序/COUNT 极简/场景 COUNT 模板指路/S1 聚合/S2 澄清）；**金标锚定注入**（retrieve_golden_bundle——M20；**首选计划直通**：top score≥TUPU_DIRECT_PLAN_SIM（0.90）且带 SQL→contract.lock_engine+直执行指令，省定位与确认轮）；指引预载（query_contract.build_guidance_block——M18）；**剧本手册预载**（批13-G：scenario 契约嵌 SKILL.md 正文+SQL 模板原文，免 read_file 轮次）。注入失败一律**静默降级**（warning 不阻断）。

## 八、辅助端点（misc）

`POST /route/preview`（路由预览——M18 决策只读展示）；`GET /health`；`GET /skills/catalog`+`/skills/metrics`（技能目录与指标）；`POST /skills/simulate-route`（路由模拟）；`DELETE /chat/freeplan/threads/{thread_id}/memory`（会话记忆清理）。

## 九、设计原则（本模块特有）

1. **编排与能力分离**：endpoint 只做编排（锁/准备/分流/收尾），一切能力经注入消费（路由 M18/装配 M17/金标 M20/引擎 M21/守卫 M19）；
2. **纯函数收尾**：delivery/sse/translator 全纯函数（无副作用）——编排器可测性前提；
3. **同 thread 串行**：会话锁保证同会话不并发（e2e 串行铁律的后端镜像）；
4. **SSE 帧契约稳定**：帧名与载荷形态是前端契约——变更须过设计；
5. **注入静默降级**：契约注入任何子段失败不阻断问答（warning 留痕）；
6. **机械拆分行为等价**：六件套为批13-D 拆分产物（SSE 字节一致约束）——重构须保持帧流逐字节等价。

## 十、验收标准

1. 主链：提问→think 双通道增量→工具结果→final→done 全帧序完整（e2e 以数据资产探查页串行验证——AGENTS.md 铁律）；
2. 分流器：【下一步判断】前后分别推 decision/answer 帧；notes 类零推帧；
3. 输出契约：final 无 Markdown 明细表（明细走 sql_result 前端表）；
4. HITL：挂起→resume 续跑一致；
5. 会话锁：同 thread 并发请求串行化；锁池超 200 回收；
6. user_selection 上下文透传（点选实体影响路由——M18 联测）；llm_connection_id 显式连接生效（M11 联测）；
7. 注入调用点：金标命中注入直通指令（M20 联测）；剧本预载后 read_file 可禁（M18 场景联测）；任一注入失败问答不中断；
8. 辅助端点五组可用。
