> 套件：DeepAssetLens 全量金标准 M08（总纲见 m00）。as-if-greenfield 视角。

## 一、模块定位

语义管理域的**词法资产面**：标准语义词条（图谱抽取→向量化→语义查询全生命周期）、同义词组、停用词、标准字典（非标→标准）、四族归一化规则（时间词/时间-Cypher/意图/炸开）、nl2cypher 模板与 graph schema 管理面、字段级溯源分析。这些资产是问数语义理解（M18 路由/意图、M09 混合检索）的数据底座。

**边界**：向量库客户端与混合检索归 M09（本模块词条生命周期含向量化状态机，执行写读 Qdrant 的细节在 M09）；IntentSemanticAsset 为意图语义资产存储（消费方 M18）；本文件内 sql/execute 转发 M21 受控执行。

## 三、标准语义词条生命周期（核心语义）

**StandardSemanticTerm**（L446-464）：term / term_type / **source（默认 graph_extract）** / ontology_ref_type+id（图谱回链）/ **canonical_text**（向量化文本）/ text_payload JSON / model_name / vector_dim / **vector_status（默认 pending）** / **retry_count / last_error**（失败重试态）/ **content_hash**（内容变更检测）/ enabled。

**状态机**：`pending →（vectorize 任务）→ done | failed(retry_count++, last_error)`；content_hash 变更→重新向量化。**StandardSemanticVectorTask**（L467-484）：task_code / status / total/success/failed/skipped / progress / request_config / task_logs——批量向量化进度追踪（前端任务列表轮询）。

**端点组**：`POST /standard-semantics/extract-from-graph`（从图谱抽词条，reset_existing/extract_mode 参数）、`POST /vectorize`（批量）、`POST /query`（语义匹配查询——M13 技能 API 绑定 standard_semantic_query 复用此函数）、`POST /export`、`GET /terms`（分页过滤）、`DELETE /terms/{id}`、`POST /vectorize-task`、`GET /vector-tasks`、`GET/PUT /model-config`（向量模型选择）、`GET /vector-models`（可选模型清单）。

## 七、设计原则（本模块特有）

1. **词条是资产不是缓存**：content_hash 变更驱动重向量化（防脏向量）；失败可重试（retry_count 上限熔断由任务层控制）；
2. **图谱是词条之源**：extract-from-graph 从本体（实体/属性/关系）抽词条，ontology_ref 双列回链——词条不凭空手造；
3. **双同义面分工**：检索改写用 SynonymGroup、口径映射用 StandardDict——新需求先判语义再选表；
4. **归一化规则数据化**：时间/意图/炸开归一全部表驱动（enabled 开关即时生效），不写死代码；
5. **模型配置可视化**：vector-models 清单+model-config 可改，切换模型=全量重向量化决策交给人。

## 八、验收标准

1. 词条生命周期：extract→terms 列表→vectorize（任务进度 total/success/failed/progress 推进）→query 语义命中→export；
2. content_hash 变更词条重新向量化；失败记 retry_count/last_error；
3. 同义词组 CRUD；重复 standard_term 400；enabled 过滤供检索（与 M09 联测改写生效）；
4. 停用词三端点；标准字典 CRUD+关键词检索；
5. nl2cypher 模板/schema 三端点写入 M05 辅助表；
6. traceability/analyze：32 位 UUID 自动归一；空 entity_ids 400；
7. 归一化四族服务层函数可用（list/create/update/delete 幂等）。
