# M03 概念体系与四区建模 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M03（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

图谱建模域的**概念层**：业务分层概念体系（L0-L4 + L2X/L4X 双链）、概念/实体/实体关系的建模 CRUD、实体英文名治理、Excel 批量导入导出、资产矩阵（L2×L4 打点）、前端四视图建模画布。是整个平台的**语义骨架**——实体挂概念、矩阵打点、问数路由都依赖这套层级。

**边界**：Neo4j 投射与图查询（sync/sync-hierarchy/graph/neo4j-data、graph_query_neo4j）归 M05；实体数据运营页（主数据/活动数据/实体关系/血缘）归 M04（消费本模块 CRUD）；字段级映射归 M07。

## 二、概念层级体系（核心语义，全平台共享词汇）

```
L0  业务域（level=0，不进图谱，仅矩阵/筛选分类；area_index=业务域索引）
主数据链 ROOT_MD：L1 主数据分组 → L2 主数据 → L2X（L2 概念下挂载的主数据实体）
业务链  ROOT_BZ：L3 业务活动分组 → L4 业务活动 → L4X（L4 概念下挂载的业务活动实体）
跨链：L2X ——打点维护——> L4X（资产矩阵的格子；relation_category="打点维护"）
     L2X ——RELATES_TO→ L2X（跨主数据域，M05 传递闭包派生）
```

- **area_index（业务域索引）**：L0 分域排序；新建概念自动分配（同级 max+1）或继承父概念（concept_entity.py L71-78）；
- **打点维护 vs 手工维护**：实体关系两类 relation_category；「打点维护」= 矩阵上点格子维护的 L2↔L4 关系（与资产矩阵打点同义），「手工维护」= 表单直建；启动期统一迁移（M01 钩子⑥：L2/L4 手工→打点去重）；
- 概念间抽象关系（kg_concept_relations，CROSS_CHAIN/derived_from）记录跨链派生来源。

## 四、API 面（prefix=/api/v1）

**concept_entity.py（建模 CRUD）**：
| 端点 | 说明 |
|---|---|
| POST/PUT/DELETE `/concepts[/{id}]` | 概念增删改（area_index 自动分配/继承；system_names 归一化） |
| GET `/concepts` | 全量概念树（含 area_index/level/parent_id） |
| POST/PUT/DELETE `/entities[/{id}]` | 实体增删改（维护 entity_concept_links 挂接） |
| GET `/entities` | 实体列表（挂载过滤） |
| POST `/entities/explanation-suggestions` | LLM 辅助实体解释建议（拆分/扩词/属性关键词） |
| GET `/entities/en-name-integrity-check` | 英文名完整性体检 |
| POST `/entities/en-name-autofill` | 英文名自动补全 |
| GET/POST/PUT/DELETE `/entity-relations[/{id}]` | 实体关系 CRUD（relation_category/direction/cardinality/join_expr） |

**concept_admin.py（批量与矩阵）**：GET `/export/excel`（含中文列头「业务域索引」等）、POST `/import/excel`（存在则改写 area_index 等）、POST `/concepts/clear`、GET `/graph/matrix`、POST `/entities/{id}/matrix/toggle`。

**资产矩阵语义**（get_graph_matrix L504-563）：左侧=业务域/L3/L4 及下属实体、顶部=L1/L2 及下属实体；只统计挂接过的实体（kg_entity_concept_links）；打点关系=EntityRelation 中 `relation_category=="打点维护"` 且 source 概念 level==2、target 概念 level==4 的行；输出格子含 join_expr/cardinality 等明细。

## 六、设计原则（本模块特有）

1. **聚合器拆分契约**：concept.py 只聚合不实现；三兄弟模块按主题分（graph/entity/admin）；路由路径与行为零变更（后续演进遵守同一拆分注释 L38-43）；
2. **打点是数据不是图**：矩阵格子背后是 EntityRelation 行（relation_category 区分来源），启动迁移统一语义（M01 钩子⑥）——矩阵渲染与关系表始终一致；
3. **英文名是一等公民**：实体英文标识供代码生成/SQL 引用；integrity-check+autofill+explanation-suggestions 三件套治理（LLM 仅建议，落库人工确认）；
4. **Excel 列头中文即接口**：导入导出列名（「业务域索引」等）是外部契约，改名=破坏兼容；
5. **level=0 业务域不进图谱**：仅矩阵分类与筛选用途，图谱同步（M05）跳过。

## 七、验收标准

1. 概念 CRUD：L0-L4+L2X/L4X 层级合法构建；area_index 自动分配（同级 max+1）/继承父；删除概念级联处理挂接；
2. 实体挂接：概念下挂/摘实体即时反映在矩阵与四区画布；
3. 矩阵：L2×L4 格子 toggle 打点→EntityRelation 行增删；格子明细含 join_expr/cardinality；「打点维护」过滤正确（level 2→4 方向）；
4. Excel 导出→清空→导入 往返一致（含 area_index/system_names）；
5. 英文名治理：integrity-check 报缺失清单；autofill 补全不覆盖已填；
6. 四视图：四模式切换数据正确（力导向=全量、四区=级联、矩阵=打点、图库=Neo4j）；
7. 层级数据变更后 M05 同步可增量重投射（边界联测）。
