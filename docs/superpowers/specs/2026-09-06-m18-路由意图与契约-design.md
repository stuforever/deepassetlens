# M18 路由意图与契约 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M18（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

问数智能体域的**决策层**：场景路由（用户输入→技能/步骤命中）、规则意图分类（轻量正则族——聚合/含糊/计数/动态条件/否定）、技能目录解析（SKILL.md frontmatter→StepDefinition 契约输入）、**QueryContract 受控契约**（每次运行的权限边界对象）、引擎路由（source_mode→引擎决策）、输出契约执行体（Markdown 明细表禁令）、问属性链（属性目录构建/召回打分/校验管线）。本模块是所有「让模型在受控范围内做判断」的决策产地。

**边界**：契约 SystemMessage 构造与注入调用点归 M16（本模块供契约对象与指引块）；守卫执行（SkillPolicy 拦截）归 M19（本模块供裁决数据：allowed/forbidden/templates/engine）；金标检索归 M20；装配归 M17。

## 三、QueryContract 契约对象（核心）

> docstring（L70）：「字段一旦建立即不可由模型改写；仅 _runtime 由代码更新。」

**字段面**（L72-100）：run_id/skill_id/skill_version/workflow_step/**allowed_tools·forbidden_tools**（白黑名单）/**template_ids**（`"skill:step/模板名"`）/**scope{customer_names,commitment,source}**（范围与承诺级别）/**selected_engine**（doris|duckdb|physical）/output_mode（默认 single_result_table）/stop_when/**route_type（scenario|generic）**/rubric（generic 默认文案）/**aggregate_intent（S1：聚合分布意图标记）**/**clarify_required（S2：歧义→澄清模式）**/multi_engine/forbid_markdown_detail_table/**entity_engine_map（实体→引擎真实映射）**/required_entities（多引擎必达数据源，终止按实体/角色判断——评审 P1-1）/allow_subagents（护栏1 复合条件：契约 AND caps 双放行）/locate_first（批13-M 定位优先）/**_runtime{engine_locked,result_obtained,violations,confirmed_engines,confirmed_entities,completed_entities,terminal}**。

**两构造器**：
- `from_step`（场景契约）：step.allowed_tools + read_file 恒允（只读 /skills/**）；**场景路径禁 read_file**（批13-G 收口：剧本手册已随契约预载，读技能文件=纯浪费轮——SkillPolicy 硬拦+文案双保险）；ABSOLUTE_FORBIDDEN_TOOLS 只加不减；task 复合条件（allow_subagents 时入白名单、守卫层仍校验 caps）；terminal=无后继步骤即拿到结果即终止；
- `generic`（低权限只读通用）：GENERIC_ALLOWED_TOOLS 全集（**clarify_required 时 allowed_tools=[]——澄清模式零工具**，模型只能问不能查）；GENERIC_RUBRIC；aggregate_intent 注入受控指令+结果层硬校验钩子。

**指引预载**（build_guidance_block L421）：规则意图分类注入 sql-query 写法指引（省 read_file 技能轮——M16 调用点）；**rubric 分层**（apply_rubric_tier L459——金标直通判定阈值分层，M20 联动）。

## 四、路由与意图

**场景路由**（skill_router.py）：SkillRouter.route_user_input(user_input, ...)→RouteResult（技能+步骤+route_reason）；技能目录 match_any_keywords/match_all_groups 关键词原语；route_preview/simulate_route 端点（M16 misc）消费本决策体只读展示。

**规则意图族**（intent_classifier.py——**非 LLM，轻量正则/关键词**）：
| 函数 | 语义 | 消费点 |
|---|---|---|
| detect_aggregate_intent | 分布/占比/构成类触发词→{dimension_hint, required_shape} | S1 契约注入 |
| detect_vague_intent | 歧义提问（未指明维度/指标） | S2 澄清模式 |
| is_count_intent | 计数型（多少户/多少台） | CountAnswer 极简+场景模板指路（批13-L/批14-A） |
| has_dynamic_condition | 动态条件（最新/当前） | 直通判定豁免（M20） |
| classify_intent | 总分类 | guidance 预载 |
| guidance_labels_for | 写法指引标签 | build_guidance_block |
| has_negation | 否定检测 | 直通豁免（M20） |

**引擎路由**（query_engine_router.py）：resolve_engine/resolve_engines_multi（source_mode_result→EngineDecision：physical/sql_integration/api_integration→doris|duckdb|physical；多源逐源分发 multi_engine）——M07 source_mode 三模式的运行时出口。

## 六、问属性链（query_attribute）

**目录簇**（query_attribute_catalog.py）：实体简报/关系简报/范围目录/属性目录/**校验目录**（_build_attribute_validation_catalog）→属性召回打分（_score_attribute_hit_from_catalog→_recall_attribute_hits_from_validation_catalog→_resolve_entity_candidates_from_attribute_hits——问属性定位：先属性命中再解实体候选）→示例元数据。**管线簇**（query_attribute_pipeline.py）：build_attribute_metadata_from_system（系统级元数据构建）/_validate_query_attribute_result（LLM 结果校验）/_build_attribute_result_panels（结果面板）。兼容门面 query_attribute_service.py（re-export 机械拆分）。消费方：metadata_service（M06 元数据视图联动）。

## 七、设计原则（本模块特有）

1. **决策与执行分离**：本模块只产裁决数据（路由/意图/契约/引擎），执行拦截在守卫（M19）——契约字段模型不可改写；
2. **意图分类零 LLM**：规则族（正则/关键词）先行——快、确定、可测；LLM 只在契约范围内判断；
3. **澄清优于乱查**：clarify_required 收缩工具集为空——宁可问一句，不可猜一表；
4. **场景契约禁 read_file**：剧本手册预载使读文件轮纯浪费——硬拦+文案双保险；
5. **引擎决策数据源真实映射**：entity_engine_map 以源模式工具返回为准——禁止模型臆想引擎；
6. **前缀缓存纪律**（契约文案逐字节一致）详见 M16/M17——本模块产出的指引块/规则族是固定文案成分。

## 八、验收标准

1. 场景路由：命中剧本→from_step 契约（步骤字段齐/template_ids 前缀/read_file 场景禁）；未命中→generic 低权限；
2. 澄清模式：detect_vague_intent 命中→generic(clarify_required=True)→allowed_tools 为空；
3. 计数型：is_count_intent→场景有 count 模板时指路注入（批14-A），否则 CountAnswer 极简段；
4. 引擎路由：三 source_mode→引擎决策正确；multi_engine 逐源分发；entity_engine_map 写入契约；
5. 输出契约：含明细表的 final 被 scrub；结果已推 UI 时校验禁表；
6. 指引预载：规则意图→guidance 块非空；聚合意图→S1 契约指令；
7. 问属性链：属性召回→实体候选解析（校验目录打分排序）；管线校验拒非法 LLM 结果；
8. route_preview/simulate_route 与实际路由一致（只读展示忠实）。
