# M06 数据源与源表 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M06（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

数据资产域的**资产登记与元数据面**：外部数据源连接配置（含 Doris 联邦 catalog）、来源表三类登记（主数据表/业务表/参考数据表）、源表间关系、字段级元数据 Excel 导入、元数据视图层（快照/分类/实体/属性/关系 + 问数视角视图）、同步触发面（Neo4j/向量的运维触发入口）。

**边界**：实体映射规则归 M07；向量执行体与 Qdrant 客户端归 M09（本模块只提供触发端点）；Neo4j 同步执行体归 M05；Doris 连接单例配置归 M12（本模块的 doris_catalog_name 引用其 catalog）。

## 三、数据源配置（DataSourceConfig）

**模型**（L586-601）：name/db_type(默认 mysql)/host/port/database/username/**password 明文列**/description/is_default/enabled/**doris_catalog_name**（跨源联邦时 Doris catalog 三段命名前缀，catalog 在 Doris 配置页建好——M12 协同）。

**API**：GET 列表（脱敏要点见风险）、GET/PUT/DELETE 单条、POST 创建、**POST /{id}/test 连接探活**（db_type 分派驱动连接测试，前端配置页即时反馈）。

**消费方**：M04 树管理器 per-entity 数据源绑定（取 enabled 列表）；M21 引擎路由按数据源取连接；M12 联邦前缀。

## 四、来源表三类登记（全量替换语义）

- **三模型**：SourceMasterTable（major/deploy/sysName/sysCode/l1/l2/enName/cnName/type——外部 camelCase 原貌）、SourceBusinessTable、SourceReferenceTable；
- **bulk_save**（source_tables.py L83-112）：**全量替换契约**——delete 三表→按 master_data/business_data/reference_data 三数组整批插入（简单处理，前端整表保存模式）；
- **all**：三表全量返回 `{master, business, reference}`；
- **源表关系**：SourceTableRelation（relation_scope/l1-l4/main_table_en/related_table_en/relation_category/**relation_expr**）——relations/all + relations/bulk_save；
- **SourceTable**（kg_source_tables）：table_name/schema_name/column_metadata JSON/connection_info JSON——物理表注册（连接信息内嵌 JSON，供映射/查询取列）。

## 五、字段元数据导入（kg_source_field_imports）

- **Excel 导入**：POST /source_fields/import（upload.py L67+）——外部字段级元数据批量入库；
- **模型 20+ 列**：seq_no/table_cn/table_en/sys_code/table_def/field_cn/field_en/field_desc/data_type/length_precision/scale/pk_fk/is_ref_data/ref_data_desc/ref_table_en/ref_data_usage_desc/is_history/mod_status/mod_time/mod_reason/app_scope（L156-181）；
- **查询与维护**：GET /source_tables/{sys_code}/{table_en}/fields（按系统+表聚合字段）；/source_fields CRUD；
- 兼容列（ref_table_en/ref_data_usage_desc）由启动期 `ensure_schema_compatibility` 补齐（M01 §二.4）。

## 六、元数据视图层（metadata.py + metadata_service）

只读视图，供治理观测与问数侧消费：
- **GET /metadata/snapshot**：资源 bundle 快照 + counts 统计（build_metadata_resource_bundle）；
- **GET /metadata/{categories,entities,attributes,relations}**：分域清单（CSV 过滤参数 `_parse_csv`、分页 page_size 夹取 ≤500、compact/include_stats 开关）；
- **POST /metadata/views/query-entity**、**views/query-attribute**：问数视角视图（build_query_entity/attribute_metadata_view）；
- **GET /metadata/diagnostics/query-entity**：问数实体元数据诊断（缺英文名/缺挂接等体检）。

## 七、同步触发面（data_sync.py）

| 端点 | 执行体 | 说明 |
|---|---|---|
| POST /neo4j-all、/neo4j-wipe | M05 sync_all_to_neo4j / wipe | 图谱全量重建/清库触发 |
| POST /entity-vectors、/attribute-vectors、/query-vectors | M09 向量服务 | 实体/属性/问数向量重建触发 |
| GET /entity-vector-stats、/attribute-vector-stats | M09 | 向量统计 |

**契约**：触发与执行分离——本模块只做运维入口（向量管理页消费），执行语义与幂等性由 M05/M09 保证。

## 八、设计原则（本模块特有）

1. **全量替换即契约**：三类源表 bulk_save 是整表替换（非增量）——前端按「编辑全集→保存」交互设计，禁止悄悄做局部 merge；
2. **外部数据原貌保留**：导入列名 camelCase/中文字段名不改写（对齐 M03 Excel 原则）；
3. **视图只读**：metadata.py 无写端点——写路径唯一走导入/CRUD；
4. **触发/执行分离**：同步触发面不复制执行逻辑；
5. **探活即时**：数据源 test 端点独立于 CRUD（配置错误早发现）。

## 九、验收标准

1. 数据源 CRUD + test：错配置 test 失败返回明确错误；enabled 过滤供绑定消费；
2. bulk_save 全量替换后 all 三类计数一致；关系 bulk 同理；
3. Excel 字段导入：列映射完整（20+ 列）+ 重复导入幂等策略明确（覆盖语义）；
4. 按表查字段：sys_code+table_en 聚合正确；
5. metadata 视图：snapshot counts 与库内计数一致；分页夹取 500；CSV 过滤生效；
6. 同步触发：neo4j-all 调用后 M05 统计返回；向量触发与 stats 一致（与 M09 联测）。

## 十、风险与偏差登记

| 项 | 说明 |
|---|---|
| password 明文列 | DataSourceConfig.password 明文落库（现状）——生产化方向：加密列/凭据托管；改动须过设计批次 |
| bulk_save 删全量 | 无事务快照回滚（delete+insert 中途失败→rollback 整体回退 L110-112，可接受）；大数据量分批优化 YAGNI |
| 全量替换竞态 | 并发 bulk_save 可能交错（单管理员操作场景可接受）——登记不处理 |
