> 套件：DeepAssetLens 全量金标准（M00-M23）补全件——2026-09-07 新增变更设计（走 M00 §七 两技能管线）。
> **as-if-greenfield 声明**：本篇按「假如从零设计该平台、此前无任何代码」的视角撰写——§三 的设计语义是**应然标准**（平台应当具备什么、契约如何），现有代码仅作取证参考（§九），不构成设计依据；代码与本篇不一致之处，按 M00 §八 偏差登记制处置，以本篇为准绳。
> **欠账标注规约**：凡当前套件尚未达成本篇要求之处，以【欠账-XX】标注——共 **32 项**（A 补锚 20 / B 休眠裁定 3 / C 回写 3 / D 处置 2 / E 前端 4），总账见 §四。

## 一、模块定位

**是什么**：套件全量评审后的**补全设计**。评审（2026-09-07）证实 M00-M23 功能域级覆盖 100%——五大能力域与支撑面无遗漏；但组件级存在 32 项欠账：20 个后端生产件不在任何 spec 的组件清单中（「代码有而标准无」）、3 项休眠/死代码未如实登记、3 项基线漂移未回写、2 项草稿处置待定、4 个前端面未锚定。本篇以 greenfield 设计规格补齐这些缺口，并规定每项欠账回写进对应模块 spec 的归属、动作与验收判据。

**为什么**：金标准的完整性承诺（M00 §一「假如重写这个工程，按这套文档做」+ §四模块地图为全工程权威）要求组件级无死角。一个照套件重建的实施者，读完 M05/M13/M16-M22 后应当能找齐问数链路全部支撑件——目前会漏掉 20 件，其中含问数主链的核心分发器与两个八百行级服务。

**范围**：

1. **功能补全设计**（§三）：六域——问数链路支撑件（7 件）/执行引擎内件（6 件）/探针观测（1 件）/问实体语义支撑（5 件）/休眠裁定（4 项）/前端基座（4 面）——每件给出设计语义（应然）与归属模块；
2. **文档治理面**（§三 3.7）：M00 基线回写/批16-A 回写/数字勘误/test_cov 草稿处置/脚本沉积登记；
3. **欠账总账与验收**（§四/§六）：32 项逐条映射到目标 spec 与可 grep 复验判据。

**非目标**：

- 不重锚已达标项（§二 基线清单防误伤）；
- 不动生产代码——本批次为**纯文档收口**（D1 测试草稿处置除外，且处置仅涉 tests/ 未跟踪件）；
- 不写实施步骤——实施归 plan 与执行会话（本篇为需求文档）；
- 不新增表/端点设计——M01-M23 已含全量，本篇只补遗漏件的语义与归属。
