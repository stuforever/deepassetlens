# M21 引擎执行与结果治理 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M21（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

问数智能体域的**执行底座**：四路引擎执行（Doris 池化/物理表直连/DuckDB API 联邦/安全执行器）、**错误分类体系**（error_class 产地——M19 纠错闸门的输入）、**单值聚合加速器**（预聚合表拦截）、查询日志（观测数据源）、SQL 改写服务（ai_rewrite）。一切 SQL 落地的最终关口。

**边界**：引擎决策在 M18（query_engine_router）；守卫校验在 M19（先拦截后执行）；Doris/Catalog 配置面在 M12（本模块消费配置）；观测端点在 M22（本模块写日志）；source_mode 数据面在 M06/M07。

## 三、四路执行协议

| 路 | 入口 | 适用 | 关键机制 |
|---|---|---|---|
| Doris | doris_engine.execute_sql(sql, limit, catalog) | sql_integration 源/联邦 | 池化（_pool/reset_pool）；_with_query_timeout；_check_ident 标识符校验防注入；build_sql_with_filters 过滤注入 |
| 物理 | sql_executor.build_execute_query_fn(data_source_id) | physical_table 源 | 按 M06 数据源建引擎直查业务库 |
| API 联邦 | duckdb_engine.execute_sql(sql, endpoints_by_table) | api_integration 源 | 见 §五 |
| 安全执行器 | secure_query_executor.validate_sql | **一切模型 SQL 的底座校验** | SELECT-only/表白名单/强制 LIMIT（DEFAULT_MAX_LIMIT）——M20 直通 SQL 也过此关 |

**日志纪律**：每路执行落 kg_engine_query_logs（engine/sql_hash/rows/duration/error——M22 观测与 M20 种子双消费）。

## 四、错误分类体系（engine_errors——M19 纠错闸门输入）

`EngineError` + 四分类器（classify_pymysql_error/classify_requests_error/classify_duckdb_error/classify_by_message——按驱动分派，消息兜底）→ **error_class**：TABLE_MISSING/CATALOG_MISSING/SYNTAX/TIMEOUT/SECURITY_VALIDATION 等；`apply_error_class(result)`（执行结果补 error_class）+ `wrap_engine_exception`（异常→结构化结果）。**契约**：error_class 是跨模块信号——M19 据此选纠错指引/HITL 触发/禁重试路径，新增错误类须过设计（守卫联动评审）。

## 五、DuckDB API 联邦（duckdb_engine）

**链路**：SQL 解析表清单（_parse_sql_tables_and_filters）→表→API 端点映射（load_endpoints_from_db——M07 ApiEndpoint）→按端点拉数（_fetch_with_pagination 分页）→Parquet 缓存（TTL/_cache_key 端点+参数指纹/invalidate_endpoint_cache）→DuckDB 内存表注册→联邦 SQL 执行。
**防护**：per-endpoint **熔断器**（_check_circuit/_record_failure·success/circuit_status——连续失败开路）+**限流**（_enforce_rate_limit）；dtype 推断与套用（infer_dtypes/_apply_dtypes）；test_endpoint（端点探活——M07 集成测试联动）。

## 六、单值聚合加速器（engine_accelerator）

**try_serve 拦截条件**（全须满足）：AST 为纯 SELECT / 无 WHERE·JOIN·GROUP BY·LIMIT / 单 FROM 单表 / 单表达式且为 COUNT|SUM|AVG|MIN|MAX / 命中启用且**新鲜**（_is_fresh TTL）的加速器（agg_expr 匹配+source_tables 含源表）。
**跨 catalog 防护**（L207-210）：查询显式带 catalog 且与加速器目标 catalog 不一致→不拦截（基表同名跨 catalog 是不同实体——防 pg_tupu 的 COUNT 被 internal 值顶替）。
**服务**：命中→预聚合表查询（Doris 亚秒）→结果附 accelerated/accelerator{name,target_table,agg_expr,staleness_note}/**data_as_of**（数据时点标注——结果治理：加速数据带新鲜度说明）。
**刷新**：refresh_accelerator（存在→INSERT OVERWRITE/不存在→CREATE TABLE AS）+refresh_due_all+register_refresh_job（M14 周期钩子 300s）。

## 七、结果治理

- **安全底座**：validate_sql 是模型 SQL 的最终关口（SELECT-only/表集合/强制 LIMIT）——直通/常规/纠错路径全过；
- **新鲜度标注**：加速器结果必须带 data_as_of/staleness_note（用户知情取舍）；
- **错误结构化**：一切执行失败走 wrap_engine_exception→error_class（不裸抛）；
- **输出形态治理**在 M18 output_contract（明细表禁令）——本模块供执行结果与标注。

## 八、设计原则（本模块特有）

1. **先校验后执行**：validate_sql 在一切引擎路径之前（守卫模板校验之后）——双闸门不冗余（模板=结构派生、安全底座=语义边界）；
2. **error_class 是唯一错误契约**：驱动异常一律分类封装——守卫/编排只认 error_class 不认原始异常；
3. **加速器只拦单值聚合**：条件不满足一律放行原路径（宁慢勿错）；跨 catalog 不拦（宁慢勿错）；
4. **联邦防护三件套**：熔断+限流+缓存——外部 API 不稳定性不传导到问数主链；
5. **日志即观测**：每路执行落日志——观测与种子提炼共享同一数据源。

## 九、验收标准

1. Doris：池化复用；超时注入生效；标识符非法拒；catalog 显式路由；
2. 物理：按数据源直查；引擎缓存按 data_source_id；
3. API 联邦：分页拉全；熔断开路后拒绝快返；Parquet 缓存 TTL 命中零请求；invalidate 后重拉；
4. 安全底座：非 SELECT 拒/表白名单外拒/无 LIMIT 强制注入；
5. 错误分类：三类驱动异常→正确 error_class；未知消息兜底类；
6. 加速器：单值聚合命中带 data_as_of 标注；带 WHERE 的聚合不拦；跨 catalog 不拦；refresh 存在覆写/不存在建表；
7. 日志：每路执行落行（engine/duration/rows）；30d 清理生效（M14 钩子）；
8. ai_rewrite：integration-sql 改写联测（M07）。
