## 一、定位与判定总则（照附件二）

教学域=专有能力。分界线：**纯算法层=算法库搬运**（fsrs.py 亲证 "pure Python, no external deps"；grading/exercise_selector/mastery 同类）｜**交互/协议层=重造 on deepagents**（LoopCapability 的 solve/mastery turn → tupu MCP 工具+中间件）｜**H5=React 重写**（15 篇设计文档=需求源）｜提示词资产=文案级继承。

## 二、数据模型（M00：PG +4 表，域数据分工）

**分工判定（D1，对附件二「PG 载体」的精确化）**：PG 存**域状态机数据**（掌握度/错题/复习记录/母题——工具面读写）；记忆槽维持 MD（L3 learning_profile 由 consolidator 写，见②）——**⑤不新增槽位载体类型**，记忆=画像/摘要（注入），域数据=状态机（查询/更新）。知识结构仍归本体图谱（Neo4j）。

PG `pg_tupu` schema 新表（PG 25432，「项目域实体业务数据」正是它的职责）：

| 表 | 列（要点） | 语义 |
|---|---|---|
| `learning_review_cards` | card_id PK/kind(mother_question\|knowledge_point)/item_id/user_id/stability/difficulty/reps/lapses/due/last_review | FSRS 卡状态（fsrs.py 的 dict 结构迁列） |
| `learning_review_records` | id PK/card_id FK/user_id/rating(1-4)/scheduled_interval/reviewed_at | 复习流水（对账+周报原料） |
| `learning_wrong_questions` | wq_id PK/user_id/mother_question_id FK/variant_text/error_context/status(open\|resolved)/wrong_at/resolved_at | 错题（H5 全链路的数据面） |
| `learning_mother_questions` | mq_id PK/title/archetype_text/knowledge_point_id/variant_count/enabled | 母题（`knowledge_point_id`=**本体图谱节点 id**——结构关系在图谱，内容状态在 PG） |

掌握度不单独建表（D2）：`learning_mastery` **并入 review cards**（kind=knowledge_point 的卡即掌握度载体——stability/retention 就是掌握度度量，与 DeepTutor「母题挂知识点复用 scheduler」同构，少一张表少一处同步 bug）。

**表数口径（修单 P1-⑤b 落点）**：PG 恒 **+4 表**——⑤d 课程块结构**不建第五表**：块存教材文档行 `blocks_json` 列（MySQL `kg_knowledge_document` 随④演进加列，解析产物缓存语义）。M00 口径=PG +4 表 + MySQL 一列。

## 四、⑤b MCP 工具族（交互层重造）

| 工具 | 语义 | 写入者臂（②三分离） |
|---|---|---|
| `fsrs_due(user, kind?)` | 到期复习清单 | 读 |
| `fsrs_review(item_id, rating)` | 提交评分→算下个间隔 | engine 直写（算法结果不许模型编） |
| `mastery_query(knowledge_point_id)` | 掌握度+证据（复习史） | 读 |
| `grade_answer(question, user_answer)` | 判分（LLM 提示词=文案级继承 grading prompts） | LLM |
| `select_exercises(knowledge_point_id, n)` | 选题（**图谱邻居扩展**：前置/后继知识点变式——tupu 强项落点，D4） | 算法 |
| `generate_practice(knowledge_point_id, band)` | 三档难度变式生成（LLM，DeepTutor practice prompts 继承） | LLM |
| `wrong_question_add/query(...)` | 错题录入/查询 | engine/读 |
| `export_wrong_book(format)` | 错题本 docx/pdf（tab_export 纪律） | engine |

**接线**：全部进①工具注册表（grep 实测计数）；走守卫链；大结果 `_with_result_ref` 沉降（判分详情/错题列表）。**②的一处小扩展（D5）**：`ChatRequest` +可选 `surface` 字段（校验∈卡 L1 槽声明）——练习判分请求走 agent run 但 L1 记到 `quiz` surface（教学专家双 surface：chat/quiz）。

## 六、⑤d 教材引擎（挂④）

教材=④（m15 演进后）的 indexed 型 KB 实例（qdrant 族，collection 语义不变）+ **课程块编译特化**：`book` 解析器（④ parsing factory 的一族）把教材编译为课程块（动画/quiz/flash_cards 块结构——DeepTutor book/compiler.py 纪律）；**块结构存教材文档行 `blocks_json` 列**（MySQL，解析产物缓存语义——省第五张 PG 表，见 §二口径）——检索走④ collection，结构走 blocks_json，页面走⑤e。**本件对④的全部修改点：parsing 白名单扩 `book` 类型 + 文档表加 `blocks_json` 列。

## 七、⑤e H5 React 页面组（`/e/tutor/*`——EXPERT_PAGES 首战）

| 页 | 路由 | 数据源 |
|---|---|---|
| 练习页 | `/e/tutor/practice` | agent run（判分/生成走⑤b 工具，surface=quiz）+ 知识点选择（图谱） |
| 错题本 | `/e/tutor/wrong-book` | `/api/tutor/wrong-questions`（分页/筛选/导出） |
| 复习页 | `/e/tutor/review` | `/api/tutor/due` + 评分提交→`fsrs_review` 工具 |
| 学情页 | `/e/tutor/progress` | `/api/tutor/mastery`（掌握度仪表盘：图谱知识点着色） |

新 router `/api/tutor`（页面数据端点，登录态；user 域隔离沿①②的 {expert}/{user}）。页面注册进①的 `EXPERT_PAGES`（自定义页路由表——首个真实用户，验证①预留的扩展点）。React+antd 同栈，15 篇 H5 设计文档为交互需求源（**按篇映射页面**：错题全链路→错题本页、三档难度→练习页、全局关联→学情页）。

## 八、错误处理

| 故障面 | 处理 |
|---|---|
| PG 不可用 | 教学工具返回可读错误（不静默空）；L1/L2/L3 记忆不受影响（MD 独立） |
| FSRS 状态损坏 | `learning_review_cards` 行级重建（从 review_records 重放——流水表是恢复锚） |
| 教材 KB 缺失 | 卡校验 422（kb:{id} 有效性在①CRUD 拦） |
| 判分 LLM 超时 | 工具错误上屏，练习页可重试（无状态半成品） |

## 十一、诚实账

1. **⑤是最大件**——但按层拆开后：算法搬运小、工具包装中、React 重写大（量在⑤e 四页）；
2. **PG 直连驱动未验证**（Doris catalog 是另一条路）——Runbook 步骤 0 先验证，可能加一个依赖（决策优先级允许）；
3. 掌握度并入 review cards（D2）是**简化设计**——若实施中发现知识点级与母题级状态冲突，再拆表（判据：出现同一 knowledge_point 双 kind 冲突）；
4. H5 15 篇是需求源**不是照抄清单**——React 重写按页面域重组，交互细节以篇为参考；
5. capabilities/ 的 solve/mastery turn 协议映射仍**未深读**——⑤b 工具语义以本 spec 表格为准（重造不必对齐原协议）；如实施中发现 DeepTutor 有未覆盖的关键 turn 行为，按 422「未实现」纪律显式暴露。
