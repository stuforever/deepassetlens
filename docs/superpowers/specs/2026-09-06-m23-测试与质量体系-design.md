横切治理域的**质量保障体系**：后端 pytest 套件（65 测试文件/736 测试函数，回归基线 680 passed）、pytest.ini 运行纪律（超时/集成标记默认排除）、轻量 conftest 约定、批次测试文化（改动-测试可追溯）、**Playwright e2e 铁律**（AGENTS.md 长期记忆：真实前端模拟唯一验收）、前端 vitest 小组件套件（7 文件）。本模块是全部 M01-M22 模块 plan 内嵌 TDD 任务的体系底座。

## 三、运行纪律（pytest.ini 契约）

- **超时保护**：单测 30s（thread 方法）——防外部依赖卡死拖垮全量回归；
- **集成默认排除**：`addopts = -m "not integration"`——依赖外部服务（MySQL/ES/Qdrant/Neo4j/LLM/后端 API）的测试标记 `@pytest.mark.integration`，手动 `-m integration` 才跑——**默认回归零外部依赖**（设计前提：单测可离线全量跑）；
- 收集路径 tests/。

## 四、conftest 轻量约定

conftest 只做两件事：sys.path 注入 backend/ + 三个样例 fixture（sample_select_sql/sample_with_sql/sample_domain_query）。**测试自包含原则**：各测试文件自管临时库/桩（tmp_session 模式贯穿本套件 plan——不依赖共享 DB fixture 的隐式状态）；`sys.path.insert(0, backend)` 是单测直接 import app.* 的统一前提（所有模块 plan 测试文件头三行模板）。

## 六、Playwright e2e 铁律（AGENTS.md 长期记忆）

- **唯一验收路径**：Playwright headless 驱动真实浏览器访问前端 23000——**后端直连/流式脚本禁作验收**（用户定调「后端测试没毛用」）；
- **主入口**：`backend/scripts/_pw_e2e.py <问题> <截图名> <超时秒>`——探查页提问→等流式→抓 `.ant-table`（thead th/tbody tr>td）+回答文本→截图 `scripts/_pw_<名>.png`；
- **选择器契约**：输入框 `textarea.ant-input`（placeholder「想问什么数据？」）、发送 `button.ant-btn-primary`；
- **串行铁律**：一次只跑一个 e2e（并发串扰后端会话）；
- **专项脚本族**：_pw_smoke（环境冒烟）/_pw_probe_dom（DOM dump）/_pw_guards_e2e/_pw_caps_e2e（守卫/能力页）/_pw_goldenqa_e2e（金标页）/_pw_w1v3_e2e（白名单系列）/_pw_t4_all/_pw_14a_verify；
- **截图证据制**：每次 e2e 落截图——验收以截图为证。

## 八、质量门（与模块体系联动）

1. **每模块 plan 内嵌 TDD**：写失败测试→实现→通过→commit（M01-M22 全部 plan 的固定骨架）；
2. **每模块 spec 验收标准=测试清单**：验收条目逐条对应测试用例；
3. **回归基线**：全量 `pytest`（backend/tests）须保持 680 passed 不下降；新模块交付即新基线；
4. **e2e 验收**：问数链改动必须过 _pw_e2e 探查页截图验收（AGENTS.md 铁律）；
5. **集成测试**：真实服务依赖测试打 integration 标记，发版前手动全量。

## 九、验收标准

1. 默认全量回归：`cd backend && pytest` 零外部依赖跑通（integration 排除）；30s 超时生效；
2. 集成手动：`pytest -m integration` 路径可用；
3. 新批次纪律：批次测试文件命名与断言密度符合本 spec §五；
4. e2e：_pw_e2e 串行跑通（截图落盘）；专项脚本族各页面可用；
5. 前端套件：7 文件 vitest 通过；
6. 680 基线保持或上升（任何下降=回归缺陷，先修后合并）。
