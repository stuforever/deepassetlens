# M11 LLM 连接与客户端 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M11（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

系统配置域的 LLM 面：**多连接配置池**（数据库驱动的 LLM 连接管理）、统一客户端入口（LangChain ChatOpenAI 构建与裸 OpenAI 兼容调用双形态）、密钥环境变量占位符、缓存命中观测、管理页（CRUD/复制/测试/对话试验场/planner 配置）。全平台一切 LLM 调用（Agent 主循环 M17、意图分类 M18、语义嵌入 M09、技能工作流 M13）都经本模块取连接。

**边界**：Agent 装配层用连接构建实例（M17）；嵌入调用的 OpenAI 兼容模式复用本模块连接池（M09）；GLM 降级等应用级故障切换策略在装配层（M17），本模块只提供连接与调用原语。

## 三、连接配置池（kg_llm_connection_configs）

**列契约**：name unique / provider（默认 openai_compatible）/ **capability（chat|embedding——按能力分池）** / description / base_url / api_path（默认 /chat/completions）/ **api_key（支持 `${ENV_VAR}` 占位符——密钥可不落库）** / model_name / **is_default**（同 capability 唯一默认语义靠查询排序保证）/ enabled / temperature（字符串存储默认 "0.2"）/ max_tokens（512）/ timeout_seconds（60）/ extra_config JSON。

## 四、连接选择契约（客户端核心）

```
get_default_llm_connection(capability)：
    enabled==True AND capability 匹配 → order_by(is_default desc) → first()
    失败/未找到 → None（调用方自行降级，本函数只 warning 不抛）

get_llm_connection_by_id(connection_id, capability)：
    显式选模型（用户指定连接）；enabled+capability 双过滤

resolve_connection_api_key(api_key)：
    "${ENV_NAME}" → os.environ 取值；明文原样返回；空→空
```

## 五、客户端双形态

**LangChain 形态**（Agent 主循环消费）：`get_chat_model(capability, temperature, timeout, streaming, extra_payload, connection_id)`——统一入口，DB 读配置构建 ChatOpenAI；`build_chat_model`（完整构建器，_build_base_url 拼接 base_url+api_path）。

**裸调用形态**（非 Agent 场景：意图分类/试验场/轻量调用）：
- `call_openai_compatible_chat`（单轮）；`call_openai_compatible_messages`（消息列表）；`call_openai_compatible_chat_stream`（流式）；
- `_extract_usage`（从响应提取 token 用量）+ `_log_cache_usage`（缓存命中日志——**缓存观测**：LLM 网关侧 prompt cache 命中率落日志）。

**观测**：`_CacheCollectorHandler`（LangChain 回调收集缓存命中）+ `get_last_llm_cache()`（最近一次调用缓存快照——诊断口径）。

**Planner 配置**：`get_active_planner_config(db)`（技能规划器用的模型配置——kg_smart_planner_configs 表，M13 联动；管理端点 GET/PUT /planner-config）。

## 七、设计原则（本模块特有）

1. **配置池唯一入口**：任何代码不得散落硬编码 LLM 连接——一律走连接池（默认/显式两路选择）；
2. **密钥不落库选项**：api_key 支持 `${ENV}` 占位——生产推荐环境变量注入，DB 只存引用；
3. **capability 分池**：chat 与 embedding 分开配置（不同模型不同端点）；
4. **选择函数静默降级**：查不到返回 None+warning，不抛——上层降级策略（M17 GLM 兜底等）统一在装配层收口；
5. **观测内建**：用量提取与缓存命中观测是调用原语的一部分（不是外挂）。

## 八、验收标准

1. 连接 CRUD+复制：副本改名不冲突；默认连接切换后 get_default 立即反映（无进程缓存）；
2. `${ENV}` 密钥：占位符从环境变量解析；明文直传；环境缺失解析为空串；
3. test/chat 试验场：坏连接返回结构化错误（不 500）；好连接返回内容+用量；
4. get_chat_model：streaming/temperature/timeout/extra_payload 参数全量透传 ChatOpenAI；
5. 裸调用三族：单轮/消息/流式结果一致；usage 提取正确；缓存命中观测日志落盘；
6. planner-config 读写一致（M13 联测规划器实际取用）。
