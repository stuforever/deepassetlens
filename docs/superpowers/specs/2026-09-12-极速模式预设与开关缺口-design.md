# 极速模式预设与开关缺口补全设计（关站提速落地）

> **批准记录（2026-09-12）**：头脑风暴会话定调三件——A 一键极速预设+切换后预热；B 补两处关不掉的站（定位预算/工具内模式锁）的开关接线；C 风险账与预设组合。用户已批准（「落地spec吧」）。
> **取证基线**：同题「查询所有WBS及下属层级的对象状态信息」五跑实测 + 全站关闭实验（零代码，纯守卫 PATCH）；本 spec 全程无代码改动即验证了开关系统 80% 已存在。

## 一、定位与背景（实测证据）

**五跑对照**（同题、同模型连接）：

| 配置 | 耗时 | 被拒次数 | 结果 |
|---|---|---|---|
| 全站开（09-10 A） | 293s | 5 | ❌ Union 六轮试错 |
| 全站开（09-10 B） | 136s | 0 | ✅ |
| 全站开（09-11 15:41） | 152s | 7 | ❌ 模式锁死局 |
| 仅关决策门（09-12 09:54，用户自测） | 83s | 0 | ✅ |
| **六守卫+决策门全关（09-12 10:01 实验）** | **63s** | **0** | ✅ 2 行正确结果 |

三个结论：
1. **提速 2.2~2.4 倍，来源是「零拒绝=零浪费轮」**——站本身是毫秒级进程内检查，CPU 节省≈0；死局全部来自「拒绝→重发→再拒」循环；
2. **「初始化 20 秒」实测抓到**：e2e 墙钟 82s − Agent 运行 63s = **19s = 页面加载 + Agent 重建 + prep + 渲染**。根源：每次守卫/能力 PATCH → 版本+1 → 下一问触发整个 Agent 重装配（MCP 拉工具 2~5s）——逐站点击的切换税；
3. **开关系统 80% 已存在**（实验全程零代码：安全控制中心 6 守卫 + 能力开关中心）。缺口三个：①无一键预设；②两站关不掉——**定位预算**（skill_policy.py L217 注释明写「不受 capability 开关影响」，仅环境变量）与**工具内模式锁**（kg_action_handlers.py L200-205 硬编码，不读 engine_lock 守卫）；③切换后无预热。

## 二、目标与非目标

**目标**：①一键极速/安全模式切换（单次版本变更=单次重建）+ 切换后后台预热（19s 切换税→0）；②定位预算与工具内模式锁接入开关体系（可配置可关）；③turbo 模式下 WBS 类题 63~90s 稳定成功、零拒绝。

**非目标**：不动决策门/守卫的**检查逻辑本身**（只接开关与预设，不重写规则）；不解决 MCP 2.4s/次协议税与 LLM 轮耗时（另行立项）；不做逐站自定义组合 UI（先两档固定预设，YAGNI）。

## 三、设计件（三件）

### 件 A 一键极速模式（预设 API + 切换后预热）

**预设端点**：`POST /api/guards/preset`，body `{"mode": "turbo" | "safe"}`，admin 鉴权同守卫 PATCH。

| 站 | turbo | safe |
|---|---|---|
| capability `decision_gate` | **关** | 开 |
| guard `template` | **关** | 开 |
| guard `output` | **关** | 开 |
| guard `engine_lock` | **关** | 开 |
| guard `approval_track` | **关** | 开 |
| guard `capability`（工具白名单） | **关** | 开 |
| guard `sql_safety` | **保留开**（只读保护：SELECT-only+强制 LIMIT，零成本高价值） | 开 |
| capability `locate_budget`（件 B-1 新增） | **保留开**（死循环防护，非权限类） | 开 |
| 工具内模式锁（件 B-2） | 降级警告不拦截 | 拦截（现状） |

- 实现走既有 `guard_config.update_guard` / `capability_config` 更新链（逐站调用但版本连续 bump，中间无请求 → 实际只重建一次）；
- **切换后预热**：preset 生效后 `asyncio.create_task`（复用 main.py L205-215 启动预热模式：sleep 1.5s → `get_tupu_agent("")` 建默认连接 Agent），失败静默（首问按原逻辑重建）；
- **诚实边界**：预热只覆盖默认连接——非默认连接（如 deepseek官方）首问仍背 2~5s 重建，登记接受。

### 件 B 两处开关缺口接线

**B-1 定位预算接能力开关**：新增 capability 行 `locate_budget`（种子：enabled=True，params `{generic: 8, scenario: 14}`，环境变量保留为缺省兜底）；`skill_policy._locate_budget_check`（L281）读取该行——enabled=False 时跳过 L1 去重+L2 预算；params 覆盖默认阈值；**读失败 fail-safe 回落环境变量默认（预算保持开）**。

**B-2 工具内模式锁接 engine_lock 守卫**：`kg_action_handlers` L200-205 在返回模式锁错误卡前查 `guard_config.guard_enabled("engine_lock")`——守卫关时记 warning 日志后**放行**（走既有 execute 路径，实体 data_source_id 缺失自然 TABLE_MISSING 纠错）；守卫开时行为与现状逐字节一致；**读守卫失败保持拦截（正确性 fail-closed）**。

### 件 C 风险账（turbo 模式语义，写入管理页文案与套例）

- turbo 下 SQL **不再过模板校验**（错表/错口径 SQL 会真执行）、输出契约不校验、无范围声明/一轮单工具纪律、无工具白名单；
- 数据破坏风险≈0（引擎只读：duckdb/Doris 外部 catalog，且 sql_safety 保留 SELECT-only+LIMIT）；
- 主要风险=**查询质量**与**行为不确定性**：零拒绝依赖模型自律（实验 2/2 成功，样本小，验收须多跑取中位）；
- 管理页极速模式开关旁展示上述文案（前端：能力管理页加「极速/安全」两按钮+当前模式显示）。

## 四、数据流（前后对比）

```
现状：用户逐站点 6+1 个开关 → 每次版本+1 → 第一问背 19s 重建税
      （或根本不知道能关 → 全站开 → 同题 136~293s 且 2/3 失败于拒绝循环）

设计后：管理页点「极速」→ POST /api/guards/preset {turbo}
        → 7 站一次切换（单次重建）→ 后台 1.5s 后预热默认 Agent
        → 用户下一问直接 63~90s 成功（零拒绝）
        → 点「安全」→ 全站回位 + 预热 → 金标直通/守卫行为回归现状
```

## 五、错误处理

| 面 | 行为 |
|---|---|
| preset mode 非法 | 400（未知模式） |
| 预设逐站应用失败 | 逐站幂等重试一次，仍败则返回分站结果清单（部分生效如实上报） |
| 预热任务失败 | 静默+warning（首问按原逻辑重建，不阻断） |
| locate_budget 策略读失败 | fail-safe 回落环境变量默认（预算开） |
| engine_lock 守卫读失败 | 保持拦截（正确性 fail-closed） |
| turbo 下 SQL 越界执行 | 无模板拦截（风险已声明）；sql_safety 仍拦非 SELECT/无 LIMIT |

## 六、测试与验收

**单测**：preset turbo/safe 后 GET /api/guards + /api/capabilities 状态断言（turbo 组合=上表）；locate_budget 参数生效（预算 8→2 后第 3 次定位拒）；模式锁 engine_lock 关时不拦（mock api_integration 实体+守卫关 → execute_sql 放行+warning 日志）；预热任务启动断言。

**e2e（Playwright headless 串行，唯一验收）**：
1. turbo 模式跑「查询所有WBS及下属层级的对象状态信息」：成功、`.ant-table` 2 行结果、run_events 零拒绝、总时长 ≤90s（同题跑 3 次取中位，样本对付行为方差）；
2. preset 切换后**紧接着**提问：e2e 墙钟 − run 时长 ≤10s（19s 重建税被预热吸收）；
3. 切回 safe：GET 断言全站回位；金标直通回归（「统计重过载台区数量」~1.5s 不受影响）；全站开守卫行为回归（模式锁照拦）。

**grep 判据**：`preset` 命中 guards.py；`locate_budget` 命中 skill_policy.py/init_db.py；`guard_enabled("engine_lock")` 命中 kg_action_handlers.py；管理页极速按钮文案可 grep。

## 七、风险与诚实账

1. **行为方差是最大噪声**：同题历史 63~293s，验收必须多跑取中位，单跑不作数；
2. **turbo 查询质量无模板护栏**——错口径 SQL 真执行（已声明，sql_safety 保底只读）；
3. **预热覆盖默认连接**，非默认连接首问 2~5s 重建（登记接受）；
4. **定位预算在 turbo 保留**：用户诉求是关「权限安全」，死循环防护不在其列——若实测出现定位死循环再议。
