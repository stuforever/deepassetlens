## 一、模块定位

平台后台执行域：**TaskWorker 单线程任务队列消费**（优先级/重试/独立 session）、任务队列模型（TaskQueue）、技能定时调度（**声明面完整、投递器未实现**——见 §四重大登记）、调试会话存储（表在此、消费在 M13）、周期任务挂载机制（周期钩子注册的两个实际作业）。

**边界**：技能执行引擎与任务提交端点归 M13（本模块是消费体）；查询日志清理与加速器刷新的业务逻辑归 M21/M22（本模块提供周期挂载点）；worker 控制端点在 M13 声明、操作本模块管理器。

## 三、TaskQueue 与消费协议（核心）

**TaskQueue 列**：task_code unique(index)/task_type/task_ref_id/**status(pending→running→completed|failed)**/**priority（默认 1，复合索引 idx_task_queue_status_priority：status+priority 查询面）**/input·output_payload JSON/error_message/**retry_count/max_retries（默认 3）**/timeout_seconds/started·completed_at。

**消费协议**（TaskWorker.run→_process_next_task→_execute_task）：
1. 轮询 `poll_interval`（启动传 2.0s）；
2. 取队：`status=="pending"` 按 `priority asc, created_at asc` **with_for_update** → 标 running → **expunge 后关 session**（独立 session 执行，防长事务——task_worker.py L102-105）；
3. 执行：按 task_code 重查（防过期）→ SkillService 取技能 → **ExecutionEngineV2(db).execute(skill_id, input_payload, created_via="schedule")**；
4. 结果：success→completed+output；失败且 `retry_count < max_retries`→回 pending 计数；否则 failed+error；
5. 周期钩子：`register_periodic(interval, fn)` 列表在轮询循环里按间隔执行（异常隔离 try/except 不影响队列）；
6. 停止：Event 优雅停止（Manager.stop）。

**单线程纪律**：daemon 单线程顺序消费——与 M01 workers=1 同根（内存态一致性前提）。

## 四、技能定时调度（重大现状登记）

**声明面**（完整可用）：SkillSchedule 表（schedule_code unique/skill_id+code/**cron_expression**/input_payload/status active·paused/**last_run_at/next_run_at**/last_run_status/run_count/fail_count/created_by + 复合索引 status+next_run_at）；M13 五端点（创建/列表/暂停/恢复/删除）；技能删除前引用检查（v2_skills_crud L106-113：active 调度阻止删除）。

**投递器（未实现）**：全仓**无 cron 解析/next_run_at 计算/到点投递 TaskQueue 的循环**（无 croniter；创建端点仅存 cron 表达式与描述，next_run_at 只透传展示）。**金标准如实登记：定时技能当前不会自动执行**；投递器实现须过设计批次（含 croniter 依赖评估、到点扫描间隔、错过补偿策略）。

## 七、设计原则（本模块特有）

1. **单线程顺序消费**：并发消费=顺序性破坏（同技能状态互踩）；提吞吐先过设计；
2. **独立 session 执行**：执行期不持有取队事务——长任务不锁队列；
3. **重试有界**：max_retries 硬上限，防毒任务无限循环；
4. **声明与执行分离**：调度声明（表+端点）与投递执行（worker）解耦——投递器缺位是**登记的未完成面**，不是隐含行为；
5. **周期作业统一挂载**：register_periodic 唯一入口。

## 八、验收标准

1. 消费协议：优先级顺序（低值先跑）；同优先级按创建时间；with_for_update 不双消费（并发桩）；
2. 重试：失败回 pending 且 retry_count 递增；达 max_retries 终态 failed；error_message 保留末次；
3. 执行隔离：执行中任务与队列 session 分离（长执行不阻塞下一取队观察）；
4. 周期钩子：按间隔执行；钩子抛异常不影响队列消费（日志留痕）；
5. worker 控制：start/stop 幂等；停止后 pending 保留（不丢任务）；
6. 调度声明面：五端点 CRUD + 暂停恢复状态流转；active 调度阻止技能删除；
7. **投递器缺位如实**：无任何路径自动按 cron 执行（回归验证防误解）。
