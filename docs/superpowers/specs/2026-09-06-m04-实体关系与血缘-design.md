# M04 实体关系与血缘 设计规格（金标准）

## 一、模块定位

图谱建模域的**实体数据运营层**：主数据/活动数据两类实体的日常维护界面（共享一套树管理器）、实体关系的管理面（分组校验+Excel 批量）、实体级数据来源配置（三种 source_mode）、血缘页（占位）。

**边界**：概念/实体/关系 CRUD API 由 M03 定义（本模块是主要消费方）；映射页（跳转目标）归 M07；数据源配置面归 M06；Neo4j 投射归 M05。

## 三、实体关系分组体系（核心语义）

**三组关系**（`_validate_group_entities` L256-274，层级硬校验）：

| relation_group | 标签 | 源/目标概念层级 | 特殊规则 |
|---|---|---|---|
| `master_master` | 主数据-主数据 | L2 ↔ L2 | |
| `master_activity` | 主数据-业务活动 | L2 → L4 | **relation_category 强制「打点维护」**（与资产矩阵打点同义）；唯一性=实体对+类别（一对实体一条） |
| `activity_activity` | 业务活动-业务活动 | L4 ↔ L4 | 唯一性=实体对+关系名+类别 |

- 关系名缺省 `f"{源实体名}关联{目标实体名}"`；类别缺省「手工维护」；
- 源/目标层级自动推断 relation_group（L149，从实体概念 level 推导）；
- 字段校验 `_validate_relation_fields`：source/target_field_name 与 join_expr 一致性；
- 重复创建 → 400（中文提示「该主数据-业务活动关系已存在，请直接编辑」）；
- 列表筛选：relation_group / relation_category / keyword / entity_id / source_entity_id / target_entity_id（L401-420）；
- Excel 导入导出与 CRUD 同一套校验（L574+ 导入循环内复用校验与唯一性判断 L614-621）。

## 四、实体数据来源三模式（ModelTreeManager 数据来源配置 Tab）

实体 `source_mode`（kg_entities 列，M01 兼容迁移已列）：

| 模式 | 语义 | 配置面 |
|---|---|---|
| `physical_table` 物理数据表 | 实体绑物理表（含 Doris catalog） | per-entity 数据源绑定（dataSourceApi.list 取 enabled，静默失败不阻塞 L519-523） |
| `sql_integration` 多源SQL整合 | 实体=SQL 整合视图 | integration_sql 编辑保存 |
| `api_integration` 多源API整合 | 实体=API 整合 | 映射跳转 API Tab |

- 切换模式走 `entityApi.updateEntity(id, {source_mode})`，**就地更新该实体字段避免整树刷新转圈+折叠**（L538-548——体验契约）；
- **配置映射跳转**：按 source_mode 直跳映射管理页对应 Tab（physical_table→Tab1 / sql_integration→Tab2 / api_integration→Tab3），自动过滤当前实体（store 联动，L484-492）；
- 数据预览：previewRows/previewColumns 弹窗（L501-506）。

## 五、页面形态与联动契约

- **主数据管理/活动数据管理**：同一 ModelTreeManager，左树（概念分类→数据实体→属性），右面板按区维护；清空重置需 Popconfirm 二次确认（「确认清空当前【X】的全部概念、实体及关系？」L674）；
- **实体关系管理页**：组/类别/关键词多维筛选 + 行内编辑 + Excel 双向；
- **跨页联动**（store 契约）：关系高亮（从关系页点行→树页高亮对应关系）、建模定位（modelingInitialKey 变化→自动选中+展开目标节点 L85-97）、映射跳转（过滤实体+指定 Tab+onOpenTarget('mapping')）；
- **血缘**：占位（Empty + 「待开发」），规划中的智能溯源大盘——任何血缘实现先过设计管线。

## 六、辅助表语义（kg_entity_modelings / kg_entity_init_data）

- **kg_entity_modelings**：实体建模目标（model_target 默认 database / model_table_en / model_columns JSON / model_ddl / entity_code）；
- **kg_entity_init_data**：实体初始化（init_mode manual/sql / init_sql / init_data JSON / source_table_en）；
- **治理行为**（concept_admin.py L224-268）：清空前统计引用数（modeling/initdata/rules）；**entity_id 重链**——按 EntityModeling/EntityInitData 的 (旧 entity_id, entity_code) 桥接重链到新实体（无 entity_code 列的 EntityMappingRule 借道桥接）；
- 现状登记：两表暂无独立 CRUD 端点（仅清空统计+重链引用）——维护面走通用实体流程，**偏差登记跟踪**（若建模页需要完整 CRUD，先补设计）。

## 七、设计原则（本模块特有）

1. **关系组即层级契约**：三组关系由概念层级硬校验（L2/L4），不允许跨组层级非法数据入表；
2. **打点语义单一来源**：master_activity 组在 API 层强制归一为「打点维护」（L434-436/L479-481/L616-618 三处一致）——矩阵（M03）与管理页看到的是同一语义；
3. **薄壳+共享组件**：主数据/活动数据是同一组件的两个模式实例；差异只允许通过 props/模式参数表达，禁止复制分叉；
4. **就地更新体验契约**：字段保存不触发整树刷新（防转圈+折叠），跨页跳转用 store 不用 URL 参数堆砌；
5. **静默降级**：辅助数据（数据源列表）加载失败静默，不阻塞主流程。

## 八、验收标准

1. 三组关系 CRUD 层级校验全绿（非法层级 400）；master_activity 创建/编辑/导入三路都强制打点+实体对唯一；
2. Excel 导出→导入往返一致（复用同一套校验）；
3. source_mode 三模式切换保存后就地生效（树不刷新不折叠）；映射跳转 Tab 正确+实体过滤生效；
4. 跨页联动：关系高亮/建模定位/映射跳转三条链路 e2e 冒烟；
5. 清空重置：Popconfirm 后清空并重链/清理 modeling/initdata/rules 引用；
6. 血缘页呈现占位文案（如实）。
