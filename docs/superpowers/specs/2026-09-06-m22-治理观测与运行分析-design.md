# M22 治理观测与运行分析 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M22（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

横切治理域的**观测与诊断面**：引擎健康快照、缓存命中率观测与管理、查询日志列表、熔断状态、**Pushdown 调试器**（SQL 下推树不真实执行）、Doris EXPLAIN 执行计划、**Profile 查询画像代理**（Doris FE HTTP）、加速器管理面。前端引擎工作台（EngineWorkbench）+ API 映射页熔断徽标。治理数据源统一消费 M10/M17/M19/M21 的日志与事件（本模块是呈现与诊断层，不产新数据）。

**边界**：被观测对象产地在各域（健康 M12/缓存·熔断·加速器·日志 M21/能力·守卫事件 M17·M19/指标使用统计 M10）——本模块只做读取面与诊断工具；治理动作（PATCH 开关）归各域 API。

## 三、观测面四读（只读）

| 端点 | 数据源 | 语义 |
|---|---|---|
| GET /health | engine_health.snapshot（M12） | 三引擎健康快照（60s 缓存） |

| GET /queries | engine_query_log.list_queries（M21） | 查询日志（limit/offset/engine/status 过滤） |
| GET /circuits | duckdb_engine.circuit_status（M21） | 各端点熔断态（CLOSED/OPEN/HALF_OPEN+连续失败数） |

**管理动作**：POST /cache/invalidate（缓存失效——endpoint_id 缺省清全部；**配置保存时前端也应触发**——数据一致性纪律）。

## 四、Pushdown 调试器（核心诊断工具）

POST /pushdown/debug——**解析 SQL 产出下推树，不真实执行**：
- 对每个涉及 API 端点：逐列判定 kind（**eq/in/range/like**）+ **是否真正触达上游**（pushed_to_api）；
- **未下推审计**（not_pushed）：未触达的列+原因（「endpoint 未声明该参数或未声明 range/prefix 支持」）——M07 API 映射参数声明完备性的诊断器；
- 产出 rebuilt sql_with_filters（重建 SQL 对照）；
- 错误走 apply_error_class（error_class 契约一致）。

**诊断语义**：联邦查询慢的根因定位——下推失败=全量拉取本地过滤（性能灾难可见化）。

## 五、Doris 诊断两件

- POST /explain（两档 EXPLAIN/EXPLAIN VERBOSE；可选 catalog SWITCH；诊断慢 SQL——执行计划文本回传）；
- GET /profile?query_id（**Profile 代理**：转发 Doris FE HTTP 18030——优先 /api/query_profile（2.x+），失败降级 /rest/v1/query_profile（历史路径）；查询画像：各算子耗时/行数/内存）。

## 六、加速器管理面

CRUD（GET/POST/PUT/DELETE /accelerators）+ POST /{id}/refresh（单刷）+ POST /refresh/all（全刷——refresh_due_all）——M21 服务的 API 面；前端工作台表格管理（名称/聚合表达式/源表/目标表/新鲜度/启停/手动刷新）。

## 七、治理观测全景消费关系

| 数据 | 产地 | 本模块呈现面 |
|---|---|---|
| 引擎健康 | M12 engine_health | /health |

**原则**：观测呈现就近（各域管理页呈现本域数据）；EngineWorkbench 专管引擎域；本模块不建统一观测中台（YAGNI）。

## 八、设计原则（本模块特有)

1. **观测只读、诊断不真实执行**：pushdown debug 只解析不执行；explain 是 Doris 侧元操作——诊断不改变数据面；
2. **error_class 契约一致**：诊断端点错误同样走 apply_error_class——与执行路径同契约；
3. **降级链如实**：profile 代理两级降级（新路径→历史路径）——Doris 版本兼容显式；
4. **缓存管理联动纪律**：配置保存→前端触发 invalidate——陈旧缓存不留窗口；
5. **诊断驱动配置完善**：not_pushed 审计直接指向 M07 参数声明补全——观测反推建模质量。

## 九、验收标准

1. 四读端点数据与产地一致（health 快照/缓存计数/日志分页/熔断状态）；
2. pushdown debug：eq/in/range/like 四类各判 pushed 正确；未声明参数进 not_pushed 带原因；不触库执行（桩断言）；
3. explain 两档可用；catalog 非法标识拒；profile 代理新路径失败自动降级历史路径；
4. 加速器管理：CRUD/单刷/全刷全链（M21 服务联测）；新鲜度展示正确；
5. 缓存 invalidate：指定端点/全部两模式；配置保存联动（M07 联测）；
6. 前端工作台：调试器输入 SQL→下推树可视化+未下推清单；熔断表实时刷新；加速器表格操作全通。

## 十、风险与偏差登记
