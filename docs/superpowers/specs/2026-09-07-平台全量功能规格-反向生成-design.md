# DeepAssetLens 平台功能设计规格（反向生成）

> **反向生成声明（2026-09-07）**：本文档以当前全部代码为唯一事实源、按 brainstorming 技能的设计规格体裁（架构/组件/数据流/错误处理/测试）反向生成——内容与当前功能**一摸一样**：零新增设计、零规划，只述现状。
> **取证基线**：git HEAD `5358632`；运行中后端（28000）live OpenAPI 实测 **239 个路径**；数据模型 **83 张表**；前端 **21 条路由/18 个页面**；后端 45 个路由模块、65 个服务、core 11 件、78 个测试文件。

## 一、架构

**定位**：DeepAssetLens（tupu 平台）——企业数据资产的深度探查与**可控问数**平台。五大能力域一体：图谱建模、数据资产、语义管理、能力指标、问数智能体；支撑面：系统配置、认证权限、技能工作流、调度后台、知识库、工单、治理观测、测试质量。非目标：通用聊天机器人、无守卫的自由 SQL 执行、代码执行类能力（Sandbox 为框架红线管控）。

```
前端 React(23000, 21 路由/18 页, AntD, KeepAlive 页签, 懒加载分 chunk)
  │  setupProxy 统一转发（前端禁硬编码后端端口，一律相对路径）
  ▼
FastAPI(28000, main.py)
  ├─ AuthMiddleware（Authentik OIDC；ENABLE_AUTH=0 短路放行）
  ├─ 239 个 API 路径：/api/v1 152 · /api/v2 46 · /api/kg 9 · /api/data-intelligence 8 ·
  │   /api/engine 12 · /api/guards 5 · /api/capabilities 6 · 根 1（健康检查）
  ├─ MCP Server 挂载（/mcp/sse——deepagent 与外部 client 共用工具层）
  └─ lifespan 启动十二步：init_db → 三事件表清理 → master_activity 迁移 → 版本归一化
       → Qdrant 语义同步 → Neo4j 全量重建 → 实体/属性向量后台同步 → task_worker
       → 查询日志清理 → 加速器刷新 → MCP 挂载检查 → Agent 单例预热
        │
        ▼
服务层（65 服务 + core 11 件）  →  存储层：MySQL 3306（tupu 主库·83 表）｜PG 25432（pg_tupu）
                                  ｜Doris 9030（catalogs: es_tupu/pg_tupu/internal）｜ES 11200
                                  ｜Neo4j 7687（图谱）｜Qdrant 6333（向量多集合）｜SQLite（checkpointer/偏好）
外部：Authentik 9100（SSO）｜LLM 网关多连接（GLM/DeepSeek 等 openai_compatible）｜Sandbox 9385
```

**通用铁律**：①路由=权限边界，每问有契约（允许集），执行前过守卫，管理域写操作有版本与审计；②框架原生件优先于自研（Agent 循环用 deepagents 骨架，自研只做业务锁）；③护栏先行（能力开关总闸+白名单+契约声明+管理页四件套，缺一不启用）；④数据驱动（SKILL.md 剧本唯一事实源、金标锚定、能力开关全配置化——改配置=缓存键变=重建生效）；⑤YAGNI 命中即止。

## 三、数据流

### 3.1 问数主链（端到端）

```
用户输入（ChatRequest：thread_id/user_input/user_selection 点选上下文/llm_connection_id）
  → 四级路由+意图分类（skill_router/intent_classifier；S2 歧义→clarify_required 澄清模式）
  → QueryContract 组装（SKILL.md 剧本预载/金标 bundle 注入：top score≥0.90 且带 SQL→lock_engine
     /指引预载 query_contract.build_guidance_block；注入失败静默降级不阻断）
  → 守卫闸门（skill_policy 契约海关+template_guard 模板守卫+scope 范围校验）
  → 分岔：
     A 金标直通（资格门 route_type∈(generic,scenario)：direct_pipeline 直执行 SQL→
       answer_renderer 确定性渲染→行数+口径注解，0 LLM 轮）
     B Agent 工作流（十步装配→决策门中间件逐轮把关→工具调用（kg_action 16 分支/引擎执行）→
       多轮推进）
  → translator think 流双通道分流（决策草稿/答案草稿增量帧）
  → SSE 七事件推帧（think/token/final/recommend/sql_result/trace/done 含 timing）
  → delivery 收尾（输出契约 apply_output_contract：禁 Markdown 明细表时剥离表格→
     scrub_markdown_tables 前端帧前最后一道/证据链/推荐）
  → 落账三本账（guard_events/capability_events/kg_engine_query_logs）+run_events 事件流
```

### 3.2 同步流

- **Neo4j 全量重建**：启动钩子触发；新体系权威（老 /sync 端点与 chat.py 引用冻结为收编项，行为不变）；
- **Qdrant 多集合同步**：词条（standard_semantic_qdrant）/实体+属性（entity_attr_vector_service）/金标（tupu_golden_qa）；
- **task_worker 轮询**：2s 优先级取队（任务队列）；周期低优先级任务（三事件表清理/查询日志清理/加速器刷新 300s）。

## 四、错误处理

| 面 | 当前行为 |
|---|---|
| 守卫链 | 十项校验，MAX_VIOLATIONS=2；可纠正 5 类限额（2/3 次）超限终止；HITL 触发（TABLE/CATALOG_MISSING+180s 超时）挂起等待用户→resume 续跑 |
| 工具调用 | 决策门：模型未同轮写明下一步判断→该轮全部工具 ToolMessage 拒绝（原工具不执行）；补判须新 tool_call_id，旧调用绝不复用、绝不假装备成功 |
| 引擎面 | duckdb 电路保护；直通失败回退 Agent 工作流；跨 catalog 守卫（引擎路由按三段名/catalog 归属校验） |
| 装配面 | create_tupu_agent fail-safe；子代理四护栏（关闭降级 None/空交集拒+spec_invalid 事件/清单交集窄化/parent_tools 父工具面校验拒） |
| 降级链 | trace 未配 LangSmith key→本地结构化日志；金标注入失败→静默降级（warning 不阻断）；Neo4j 停机→健康降级（sync ok:False）；坏数据源→探活降级（connected:False+message）；快照类导入缺失→容错降级（secretary_state） |
| 配置变更 | 三因子缓存键变（连接/守卫版本/能力版本/文件指纹）→Agent 重建生效；引擎健康 TTL 缓存+invalidate/force |
| 并发 | 同 thread 会话锁串行（锁池上限 200 防无界）；e2e 必须串行（并发串扰会话） |
