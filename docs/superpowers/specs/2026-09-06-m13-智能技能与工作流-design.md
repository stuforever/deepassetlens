# M13 智能技能与工作流 设计规格（金标准）

> 套件：DeepAssetLens 全量金标准 M13（总纲见 m00）。as-if-greenfield 视角。
> 取证基线：HEAD `0d67f4c`（2026-09-06）。本模块改动须先过两技能管线并回写本 spec 状态。

## 一、模块定位

技能工作流域（全平台最重的业务域之一）：**技能包体系**（五件套 ZIP/版本/文件树/SKILL.md 解析）、**执行体系**（同步/异步/任务队列/Worker 控制）、**调试体系**（断点/单步/变量快照）、**智能技能体系**（LLM 工作流：三场景管道/双模式/等待用户输入/rewind 回溯）、**统一 Run 体系**（会话/Run/事件 SSE）、配套（模板库/定时调度声明/密钥管理/技能-API 绑定/工具清单）。

**边界**：TaskWorker 消费体归 M14（本模块提交任务）；SKILL.md 文件式问数剧本归 M18（_sync_scenario_skills 把剧本同步进 skills 表仅为可见性）；planner 模型连接归 M11；场景剧本技能的数据面在 data/skills/。

## 三、技能包体系（skills 5 表）

- **skills**：技能主档（skill_code/status 草稿-发布/类型 natural·python·sql·http·mixed——M01 种子五类型）；
- **skill_versions**：版本（VersionService：create/publish/archive/**normalize_all_versions_to_filesystem**——启动钩子⑦，库版本归一化落文件系统）；
- **skill_exec_logs**：执行日志（ExecutionService 生命周期 create→complete）；
- **skill_api_bindings**：技能-API 绑定（SkillApiBindingService upsert；**standard_semantic_query 绑定**——M08 语义查询函数作为技能 API 暴露）；
- **文件树**：技能包内文件 CRUD（files/content 三端点）+ **SKILL.md 解析端点**（frontmatter 数据化契约，与 M18 剧本解析同规）；
- **ZIP 五件套**：export（完整目录导出）/import（五件套导入）——技能的分发单元。

## 四、执行与调试体系

**执行三通道**：同步（POST /executions——当前激活版本立即跑）/异步（/executions/async 后台）/任务队列（POST /tasks→TaskQueue→M14 TaskWorker 消费；retry 端点）。**ExecutionEngineV2**（core）：执行引擎（M01 worker 调用 execute(skill_id, input_payload, created_via)）。**Worker 控制三端点**（status/start/stop——运行时管理）。

**调试会话**（九端点）：创建会话→**单步执行**（step）→状态/变量快照/日志→**断点设置/移除**→终止。表：kg_debug_sessions（scheduler.py）。

**工具清单**：GET /tools（Tool Calling 接口）+ **GET /tools/v2（risk_level 过滤）**——供技能编辑器引用可用工具（与 M17 能力开关联动）。

## 六、统一 Run 体系（runs.py）

**会话-Run-事件三层**：Conversation（统一会话）→ AgentRun（创建即执行）→ RunEvent（事件流，**SSE 流式端点** /events/stream）。`agent_run_runtime`（运行时编排）+ `run_event_sink`（事件汇）。**v1 chat.py 为前身**（conversations/conversation_messages 表 + Neo4jSyncService 老引用——M05 双轨证据），新功能一律走统一 Run。

## 七、配套面

- **模板库**：templates 三端点（列表/详情/**apply 应用建技能**——skill_templates.py）；
- **定时调度声明**：schedules 五端点（创建/列表/暂停/恢复/删除）——执行体在 M14（kg_skill_schedules→TaskQueue 投递）；
- **密钥管理**：secrets 三端点（**值脱敏**返回；创建/更新/删除）——技能运行凭据与代码分离；
- **技能类型管理**：五端点（CRUD+disable）；
- **版本物理快照**：POST /versions/{version}/snapshot（发布时归档到文件系统）。

## 八、设计原则（本模块特有）

1. **包-版本-快照三层**：技能=包（文件树）→版本（库内）→快照（发布时物理归档）——分发走 ZIP 五件套，不依赖库；
2. **执行通道分级**：交互执行（同步）/后台执行（异步/任务）/调试执行（单步断点）三通道共享 ExecutionEngineV2；
3. **LLM 工作流可回溯**：waiting_user_input 挂起 + rewind 回退步序 + parent_run_id 链——人机协作管道不因一步失败全重跑；
4. **密钥与技能分离**：secrets 独立管理值脱敏——技能内容可导出分发而不泄密；
5. **统一 Run 是唯一新入口**：新会话型功能走 Conversation/AgentRun/RunEvent；chat.py 冻结为兼容层。

## 九、验收标准

1. 技能包：CRUD→文件树编辑→版本→publish→ZIP 导出→导入 往返一致；SKILL.md 解析字段与 M18 契约一致；
2. 执行三通道：同步结果/异步轮询/任务队列重试（与 M14 联测）；
3. 调试：断点命中暂停→单步→变量快照→终止全链；
4. 管道：三场景各跑通一条；waiting_user_input 挂起后续跑；rewind 后从指定步重跑且原 run 保留（rewound 状态+rewind log）；
5. 统一 Run：创建即执行；SSE 事件流完整（与 M16 流式联测规约一致）；事件可回放；
6. secrets 值脱敏；模板 apply 产新技能；调度声明创建后 M14 可投递；
7. tools/v2 risk_level 过滤正确（与 M17 开关联测）。
