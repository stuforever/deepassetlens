## 二、三层入口架构（大入口）

```
第一层 平台门户（大入口，全员）
  / 专家门户：enabled 专家卡墙——卡显示专家入口点（对话/功能页/后台*）        *权限可见
第二层 专家空间 /e/{slug}/**
  /e/{slug}/chat          对话（通用，所有专家必有）
  /e/{slug}/{page}        功能页组（EXPERT_PAGES 注册表——tutor 四页）
  /e/{slug}/admin/*       专家后台（本设计新增——DeepTutor 个性化后台的迁移落点）
第三层 平台配置（admin）
  /llm-config /guards /capabilities /vector(KB) /skills /memory-admin /观测
```

## 三、通用 vs 专家划分原则（问题 1 的判定口诀）

**「引擎归平台，实例归专家；协议通用，数据专家」**（与三注册表原则同构）：

| DeepTutor 个性化后台能力 | 归层 | tupu 落点 |
|---|---|---|
| LLM/模型配置 | 平台配置 | ③ LLM 连接（已有） |
| KB 引擎/文档解析 | 平台配置 | ④ kb_engines/向量管理（已有） |
| 记忆槽类型 | 平台配置 | ② memory_slots（已有） |
| 用户/学习者认证 | 平台配置 | Authentik 域（远期接页面级） |
| **学情管理（跨用户报表）** | **tutor 后台** | `/e/tutor/admin/progress`——教师视角跨用户掌握度看板（复用 /api/tutor/mastery + 跨用户参数，admin 依赖） |
| **题库管理（母题/变式 CRUD）** | **tutor 后台** | `/e/tutor/admin/questions`——learning_mother_questions 管理面（**当前完全无管理面**，PG 表裸奔） |
| **教材管理** | **tutor 后台** | `/e/tutor/admin/materials`——tutor 卡 knowledge_sources 所指 KB 的文档管理视图（**调④既有端点**，不另起引擎；平台层向量管理仍管基础设施） |
| **调度设置（FSRS/复习参数）** | **tutor 后台** | `/e/tutor/admin/schedule`——目标保持率/参数覆写（读 experts 卡参数或 env 面） |
| 周报配置 | tutor 后台 | ⑥-3 cron 触达（定时专家任务首例） |
| 槽实例/工具面/知识源（卡） | 专家配置 | ① CRUD（已有）——入口归并进专家后台首页 |

**专家后台首页**=`/e/{slug}/admin`：域数据管理分区（tutor 四区如上）+ 该专家卡配置入口（槽/工具面/知识源，admin 权限）——**专家的「控制台」**。

## 四、权限矩阵与实现路径

| 角色 | 门户 | 专家空间（对话/功能页） | 专家后台 | 平台配置 |
|---|---|---|---|---|
| 平台管理员 admin | ✅ | ✅ | ✅（全部专家） | ✅ |

## 十、补充判定（2026-09-12 追问后实测与定调）

### 10.1 权限现状实测：**已启用，不是没有**
- 登录体系在：`core/auth.py` L501 `get_current_user`（Authentik 接入）+ L497 依赖族（require_permission/check_resource_permission）+ L215 `is_admin`；前端 UserBadge 已显示 admin/operator/default 三态角色；
- 写保护在工作：experts/guards/capabilities/memory 四 router 实测 `_require_admin`（非 admin：GET 可读、写 403——guards.py L11 文件头即写明）；资源 ACL 五动作（read/write/execute/delete/admin——ResourceAclDrawer）；
- **「看不到」的真因**：(a) 你以 admin 身份用——全通无感知；(b) **专家后台还不存在**（本件 §二第三层尚未实施）——缺的是面，不是权限。

### 10.2 专家配置双入口（判定：「建在平台，管在专家」）
- **专家后台 `/e/{slug}/admin`**（§三）：域内维护——卡配置（槽/工具面/知识源）+域数据四区；
- **平台配置层「专家管理」**：生命周期治理——⑥-2 专家工厂向导（新建/克隆/启停/删除规划）——创建属平台治理动作；
- **现状缺口实测**：`/api/experts` CRUD 六方法在（api.ts L592-604），但前端消费点**全部只读**（AppSider/ExpertPortal/ExpertChat/MemoryAdmin 四处 list/get）——**专家配置界面零存在**，目前只能 API/种子操作——专家配置界面=本件实施批第一优先。

### 10.3 前台调用模型（判定：**显式调专家，技能不出前台**）
- 大入口=专家卡墙：用户选「跟谁聊」（①拍板门户模式的自然延伸）；
- 技能=专家的装配面内部能力：`expert_paths.skills_roots(card)`（L30）**按卡参数化**——技能根随专家走，注入发生在装配期，用户不可见不可选；
- 技能显性化=**展示≠调用**：专家空间呈现「我会什么」（⑥-1 工具箱引用表/门户卡能力标签），点击仍进对话由专家调度；
- 平台技能中心（现有 /skills 页）=**后台管理面**（技能包安装/维护，管理员向）——对照 WorkBuddy：他们 C 端用户是配置者（技能市场自装），tupu 用户是**使用者**、配置者是管理员——产品形态不同，故调用模型取「专家显式、技能隐式」；
- 远期 team 型/跨专家技能复用时，技能注册表+专家引用（WorkBuddy 模式）再评估——判据：出现第二个用同技能族的专家。
