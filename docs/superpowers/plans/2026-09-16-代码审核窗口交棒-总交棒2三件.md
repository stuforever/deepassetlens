### R2 A-4 check 端点与前端守卫的语义分叉
- `GET /api/v1/auth/check`（auth.py）：auth=1 无 token→401；有 token 无权→`{allowed:false}`。前端 `RequireExpert` 用原生 fetch，401 时 `j?.data?.allowed` 为 undefined→`!!undefined=false`→重定向——**行为对但靠隐式 undefined**，判断是否应显式分支。
- `check_resource` 用 `SessionLocal()` 直建（非 `get_db` 依赖）+无 try/except 包 `check_permission`——评估是否该收敛到依赖注入；`get_current_user` 抛 401 直接冒泡是否符合「判定面不抛 403」的设计意图。
- `RequireExpert` 非 admin 每次 mount 一次 check 请求（无缓存）——auth=0 开发态走 admin 快路径不受影响，auth=1 生产态的请求放大与闪烁风险——评估是否需要会话级缓存。
- `RequireAdmin` 向后兼容别名硬编码 `expertId="tutor"`——审既有调用点是否有非 tutor 后台路由（当前仅 `/e/tutor/admin`，确认无漏）。
