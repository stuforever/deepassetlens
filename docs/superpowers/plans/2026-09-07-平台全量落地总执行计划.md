## 一、执行协议（每个模块任务统一六步循环）

对批次内每个模块 M<NN>，按以下六步执行（任务节只给路径与模块特有物，不再重复协议）：

- **P1 读双文档**：读 spec `docs/superpowers/specs/2026-09-06-m<NN>-<slug>-design.md`（重点：组件清单/核心语义/API 面/验收标准/偏差登记表）与 plan `docs/superpowers/plans/2026-09-06-m<NN>-<slug>.md`（全文）。
- **P2 断点盘点**：`grep -c "\- \[ \]" docs/superpowers/plans/2026-09-06-m<NN>-<slug>.md` 确认未勾数与 §〇 断点表一致；不一致→先按实际状态修正断点表（偏差登记），再继续。
- **P3 逐任务执行（plan 为步骤权威）**：按模块 plan 任务顺序逐任务推进——
  - 测试步骤：先跑该任务指定的测试命令。绿→核对断言语义与 spec 一致→勾选复选框（`- [ ]`→`- [x]`）；红或文件缺失→用 test-driven-development 技能补齐（写失败测试→确认失败→最小实现→绿）；
  - 实现步骤：代码已存在→读文件对照 spec 验收语义核验关键行为（不重写已达标实现）；行为不符→用 systematic-debugging 技能取证定位→按裁决链小步改代码或记偏差；代码缺失→按 plan 内代码块实现；
  - commit 步骤：用模块 plan 任务内给定的 commit 消息提交（同模块可按任务边界聚合，但必须可追溯到对应任务）。
- **P4 模块门禁**：工作目录 `backend/` 下 `python -m pytest`——全绿且 passed 数 ≥ 会话基线（批次 0 记录值，只升不降）。涉前端模块另跑 `cd frontend && npm test -- --watchAll=false`（不降基线）。
- **P5 偏差登记**：执行中发现的代码↔spec 差异，在该模块 spec「偏差登记」节补一行 `| 日期 | 差异 | 处置 |`（与 M07 既有 2026-09-07 行同构）；即使零差异也登记一行「批次核验通过」结论。
- **P6 台账与收尾**：实施台账（`docs/问数智能体vNext最终设计文档_实施定稿`）登记批次行；遵守 M00 §六.4「每批次独立 commit」。
