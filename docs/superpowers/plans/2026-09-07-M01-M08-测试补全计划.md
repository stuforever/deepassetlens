# DeepAssetLens M01-M08 测试补全（金标准对齐补测）实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 为已落地的 M01-M08 八个模块补全 pytest 测试——按各模块 spec「验收标准」节逐条映射、缺口补测，直至八模块验收标准条目 100% 有绿色测试锚定、映射表 grep 可复验、全量 pytest 只升不降。

**架构：** 「金标准对齐补测」——测试是对既有实现的规格锚定（characterization），不是从零 TDD：每条验收标准写测试断言 spec 行为，红=抓到金标偏差（走 systematic-debugging+偏差登记+小步修复），绿=登记映射。扩展现有 `test_m01..m08` 八件测试文件（不推倒已绿的 928 个测试函数）。

**技术栈：** pytest（`backend/pytest.ini`：timeout 30s、`-m "not integration"`、testpaths=tests；integration 标记=依赖外部服务的测试，默认排除）；真 MySQL 3306（SessionLocal 直连为既有模式）；外部依赖件（Neo4j/Qdrant/Doris/ES/Authentik）单测用假件/桩。

## 〇、定位与边界（执行前必读）

**为什么补**：M01-M08 已落地（八份模块 plan 复选框全勾、八批提交入库），但模块级测试薄——实测八件 `test_m0*` 合计仅 **49 个测试函数**（M01 7/M02 9/M03 8/M04 3/M05 4/M06 6/M07 7/M08 5），且全仓 928 个测试函数集中在问数域历史批次族（批13/batch/里程碑等），管理域（图谱/资产/语义/基座/认证）锚定稀疏。

**交付物定义**：不是重写（基线只升不降铁律——已绿的 928 个测试一个不删），是**增量补全**：spec 验收标准清单制覆盖 + 映射表登记 + 缺口补测。

**覆盖定义（重要）**：pytest-cov 未安装，且按 AGENTS.md 决策优先级（现有依赖优先、不加新包）**不引入**——本计划的「全面」= **验收标准清单制**：每条 spec 验收标准 → 至少一个绿色测试函数，映射表写在测试文件头部、grep 可复验。这与金标准哲学一致（文档是判据，不是行覆盖率）。

**先例（本计划的价值证明）**：M01 spec「偏差登记」2026-09-07 行——补测抓到 `SessionLocal` 未设 `expire_on_commit=False`，TaskWorker `expunge` 后访问 `task.task_code` 即 DetachedInstanceError，**调度执行体从未真正跑过（被异常吞掉）**，已修复并全量回归。测试补全=金标偏差的探测器。

**边界**：
1. 只动 `backend/tests/test_m01_base.py` … `test_m08_semantic.py` 八件（映射可引用其他文件既有测试）；映射盘点范围=全 `backend/tests/` 目录（不止 test_mNN）；
2. **生产代码零改动**为默认；例外=补测抓到偏差→systematic-debugging 取证→小步修复+spec 偏差登记行（修复涉主链时补跑 e2e）；
3. 不碰 M09-M23 范围（另一计划《2026-09-07-平台全量落地总执行计划》负责）；两计划并行时：动不同测试文件、全量门禁各自跑并各自记增量，建议串行或错开；
4. **禁改清单纪律同样适用于测试**：休眠/占位件按登记态断言——M04 血缘页占位、M05 老 /sync 冻结、M07 SmartJoinReview 预留，测试断言其占位/冻结/预留态本身，不得测出「功能缺失」就改生产代码。

## 一、执行协议（每个模块统一六步循环 C1-C6）

- **C1 读判据与盘点**：读该模块 spec 的「验收标准」节（§号+行号见任务卡）逐条摘出；通读现有 `test_m<NN>_<slug>.py` 全文；再以验收条目关键词 grep 全 `backend/tests/` 盘点既有覆盖（不止 test_mNN 文件，避免重复造测试）。
- **C2 建映射表**：在测试文件模块 docstring 下方写固定格式注释块，逐条登记：
  ```
  # 验收标准映射（M<NN> spec §<节>，2026-09-XX 补全）：
  # §七.1 冷启动 83 表/重启幂等 → test_init_db_idempotent（本文件）
  # §七.2 外部依赖全断降级 → 缺口（本次补：test_startup_degrades_xxx）
  # §八.3 五级权限链 → test_xxx（test_m02_auth.py）
  ```
  引用他文件测试写 `文件名::测试名`；缺口行必须带「本次补：」前缀——补完后改写为实际测试名。
- **C3 逐缺口补测（金标准对齐补测纪律）**：每个缺口写一个（或一组）测试函数——
  - 断言 spec 描述的行为（断言值以 spec 语义为准，如 400 状态码、状态机次序、幂等零副作用）；
  - **红=抓到偏差**：用 systematic-debugging 取证定位，二选一——测试写错（修测试）或代码偏差（小步修复+该 spec「偏差登记」节补行 `| 日期 | 差异 | 处置 |`，格式同 M01 既有 2026-09-07 行）；
  - **绿=登记映射**；
  - 每个测试带「变异锚点」docstring：何种生产代码改动会让它失败（既有 test_m01_base.py 范式）；
  - 外部依赖件（Neo4j/Qdrant/Doris/ES/Authentik）：单测用假件/桩/monkeypatch 断言逻辑与降级路径；必须真连外部服务的测试打 `@pytest.mark.integration`（默认排除，不计入 C4 门禁）。
- **C4 模块门禁**：工作目录 `backend/`，`python -m pytest`——全绿且 passed 数 ≥ 会话基线（批次 0 记录值，只升不降）。
- **C5 偏差登记**：该模块 spec「偏差登记」节——有偏差补行；零偏差也登记一行「2026-09-XX 测试补全批次核验通过：§X 条目 N/M 条锚定」。
- **C6 commit+台账**：commit 消息 `M<NN> 测试补全：验收标准 A/B 条锚定（补 C 测）`；实施台账（`docs/问数智能体vNext最终设计文档_实施定稿`）登记批次行。
