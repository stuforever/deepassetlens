# 权限体系重构 实现计划（金标准，v1.4）

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** Authentik 4 容器 → SuperTokens 1 容器（13567，数据落 tupu_pg）；用户/角色/权限管理面全部自建（新增 13 端点：iam 10 含 audit + session 3；/auth/config 原地改；+ 前端两页）；MCP 工具权限并入五层判定链（资源类型 tool + 专家白名单交集 + 审计）；私塾 vendor auth 面清零；**教学工具 11 件重新 MCP 化（含 🔴-4 用户上下文传递）+ 2 个教学技能包融入平台技能体系（v1.3/v1.4）**。权限相关容器 7→1。

**架构：** 见 `docs/superpowers/specs/2026-09-24-权限体系重构-design.md` §2 目标态架构图。provider 表驱动验签（双跑两路 JWKS）→ 统一 require_permission 出口 → API/工具两域判定 → auth_audit_log 落痕。

**技术栈：** supertokens-postgresql（Docker）、supertokens-python[fastapi]（仅登录签发/建号，验签仍自研 JWKS）、SQLAlchemy（+1 审计表）、React+AntD（两管理页，沿用 settings D 型模板）。

**规格来源：** `docs/superpowers/specs/2026-09-24-权限体系重构-design.md`；背景调研 `docs/2026-09-24-权限管理方案调研-python-agent.html` §8-§10。

**纪律：**
- 端口 13567 注册 AGENTS.md 端口表（≥10000 铁律）；禁止动既有端口。
- ENABLE_AUTH=0 语义不变（匿名=admin 直通）——全部新守卫沿用，测试基建零影响。
- deps 叠加不互替：私塾批1 先双轨、对拍通过再摘 vendor 依赖。
- 验签不引 SDK：supertokens-python 只用于登录签发/建号，验签走自研 JWKS 缓存路径（纯 ASGI 中间件零改动）。
- 浏览器验收一律 Playwright headless（AGENTS.md 铁律），串行执行。
