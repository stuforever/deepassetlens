# M07 映射与 API 编排 实现计划（金标准）

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [x]`）语法来跟踪进度。

**目标：** 从零构建整合层——实体映射规则（多源表→实体+溯源推导）、DuckDB 联邦 API 虚拟表（配置驱动零改代码：列契约/缓存/分页/限流熔断）、对象级 API 映射（伪 SQL 无 WHERE）、多源 SQL 整合三端点（verify/LLM 重写/受控执行）、数据预览、前端映射管理三 Tab。

**架构：** 三条整合路径对齐实体 source_mode（物理表=EntityMappingRule；SQL 整合=integration-sql；API 整合=ApiEndpoint 虚拟表+EntityApiMapping）；溯源从规则实时推导不落血缘表；伪 SQL 模板与运行期条件隔离；LLM 只产出建议。

**技术栈：** FastAPI、SQLAlchemy、DuckDB（联邦执行体在 M21）、requests（API 拉取）、React+AntD。

**规格来源：** `docs/superpowers/specs/2026-09-06-m07-映射与API编排-design.md`。

**纪律：** 加新 API 零改代码；pseudo_sql 禁含 WHERE；LLM 产物不直接落库；JSON 列双形态兼容。
