# 自评（rubric）耗时解剖：为什么最后的结果输出要等这么久

> 2026-08-24 · 设计窗口产出（框架源码级分析）
> 实测锚点：「查询项目数量」Agent 路径，答案 ~60s 流完，done 67.5s，grader 报 12.2s；历史典型区间 20-40s。

---

## 一、自评的完整过程（deepagents.middleware.rubric 源码级）

```
答案流式完成（用户已看到全文）
   ↓ ① 触发
Agent 循环自然终止（stop_when 命中）→ RubricMiddleware.after_agent 钩子（L573）
   ↓ ② 组装载荷（_build_grader_payload, L774-804）
把【整条轨迹】压扁成纯文本：_build_grader_transcript(state["messages"], L948)
   —— 系统提示+契约+问题+每一轮工具调用与结果+完整答案，全部塞进一个 <transcript> 块
   外面再包 <rubric> 块（4 条标准）+ nonce 随机围栏（secrets.token_hex(8)，每次调用都不同）
   ↓ ③ 发起第二次完整 LLM 调用（_agrade, L746）
grader.ainvoke({"messages":[HumanMessage(整个载荷)]})
   —— 一条全新会话、一条巨型 HumanMessage、等待完整返回（streaming=True 但用的是非流式消费）
   要求结构化输出 response_format=GraderResponse（每条标准的判定+理由 JSON）
   ↓ ④ 解析裁决（_extract_graded）
satisfied → 放行，流程继续到 final/done
needs_revision → jump_to='model' 注入修订 HumanMessage → 答案整轮重生成（再 25-40s）→ 再评
   ↓ ⑤ 桥接上屏
on_evaluation 回调 → contextvar 桥 → SSE rubric 事件 → 置信度徽标
```

## 二、时间花在哪：逐项分解

以观测到的 12.2s（小上下文）与典型 20-40s 分别标注：

| 成本项 | 机制 | 小题 | 典型 |
|---|---|---|---|
| **Prefill 全量重算** | 单条巨型 HumanMessage + **每次调用换 nonce 围栏** → 与主循环的任何缓存前缀都不共享，服务端自动前缀缓存必然 miss；5 轮轨迹压扁后 5-15k token 逐 token 读入 | 3-6s | 8-20s |
| **交叉核对生成** | 「数字必须来自工具返回」要求 grader 在长轨迹里跨区域比对数字——注意力密集型工作，且要输出每条标准的理由 JSON（结构化解码拉长生成） | 3-6s | 8-15s |
| **串行位置税** | 它排在「答案已完成」之后、「final/done」之前——全程阻塞交付 | 全额 | 全额 |
| **失败翻倍** | needs_revision 时：重生成一轮(+25-40s)+复审 | 0（罕见） | +25-40s |
| 载荷组装/桥接 | sanitize/token/回调 | <0.1s | <0.1s |

**一句话归因：自评是「在答案已经交付给用户的眼睛之后，又发起了一次完整的 Agent 级 LLM 往返」——而且这个往返天生吃不到任何缓存。**

## 三、四个结构性原因（为什么它注定慢）

1. **它是第二次完整 LLM 往返**：与主循环任意一轮同量级（25s 级），却被追加在用户感知的最后一段；
2. **构造上反缓存**：nonce 围栏每次随机（防注入的正确设计！）+ 单条巨型消息 + 全新会话——三重保证零前缀复用。防注入与快，在这里结构性冲突；
3. **任务本身是重活**：四条标准里「数字来自工具返回」「口径披露」都是跨轨迹的多跳核对，不是一眼判断；
4. **最差的位置**：哪怕 12s，也正好卡在「用户已看到全文」和「界面停止转圈」之间——感知成本被放到最大。

## 四、本次 12.2s 的讽刺点

「查询项目数量」是干净的 COUNT 题：verification 全绿、单一数值结果、数字被 SkillPolicy 锁死来自工具返回。**这 12.2s 花在了复核一套已经被模板+闸门结构性保证过的事情上。** 这正是批1-B/B'-1 规则跳过的靶心——该题命中 clean_aggregate 口径后此段归零。

## 五、已有设计与本解剖的对应关系（收益重估）

| 手段 | 作用机制 | 对本段的节省 |
|---|---|---|
| 批1-B 示例锚定免评 | sim≥0.85 直接 rubric=None | 整段归零（锚定题） |

| 场景路径无 rubric | 模板结构性保证，无需评 | 天然为零 |

## 六、结论

自评慢不是因为实现浪费——nonce 围栏、全轨迹压扁、结构化输出都是正确甚至必要的设计（防注入、防作弊）——而是因为**「独立仪器复核」这件事本身就要一次完整的模型往返**。工程上的正解从来不是把它调快，而是三选一：不评（分档豁免）、后评（异步化）、轻评（小模型）。我们的设计恰好三条都有，按批10 排序落地即可。
