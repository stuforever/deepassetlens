## 一、摘要回退官方（①定调）

### 1.1 决策

撤 `_TupuSummarizationMiddleware` 子类、撤观测钩子（批5-C3，0 触发无账可记）、HarnessProfile 不再常态排除摘要件；改为官方工厂实例 + 同名替换：

```python
if _on("summarization"):
    _summ = create_summarization_middleware(model, backend)   # 官方工厂,官方默认
    middleware_list.append(_summ)                               # 同名替换框架自动件
    middleware_list.append(SummarizationToolMiddleware(_summ)) # 官方手动压缩件
else:
    # 开关关闭语义不变:排除栏变为开关的执行器
    excluded_middleware={"SummarizationMiddleware"}
```

排除栏语义转变：**从"常态排除默认件"变为"开关关闭时才排除"**（能力开关的总闸地位不变）。

### 1.2 潜在风险登记（不改决定，只入账）

170k > 模型真实窗口 → 主动压缩永不触发，保护 = ContextOverflowError 应急路（压缩+重试）。真触发时代价=延迟尖峰+缓存全碎于最糟时刻。当前 0 触发=零观测损失。**复盘触发条件**：日志出现超限重试 / 会话普遍 >100k token / 批13-G 数据显示长会话常态化。届时优先方案：为模型补 profile（max_input_tokens）使官方工厂自适应 85%，而非再自定义。

### 1.3 连带取消

- 批13-W **W-2 摘要参数配置化：取消**（无自定义参数可配）；
- 13-AA ① 同名替换待研：**被本方案吸收**（回退即同名替换）。

## 三、占位符站转技能设计（③定调）

### 3.1 转换设计

AGENTS.md 常驻纪律新增：

> 「技能文件中的 ⟦中文占位符⟧ 不是真实表名。写 SQL 前必须先调 search_entities 解析为物理表名（entity_en_name）；SQL 中严禁出现 ⟦⟧ 字样。」

### 3.2 安全网（意外发现）

契约站模板守卫天然兜底：未翻译占位符写进 SQL → 表名不在已批准模板表集合 → **模板守卫拒绝** → 模型重写。转换后=「提示词为主 + 模板守卫为底」双层结构。

### 3.3 代价登记

每占位符 0 轮 → +1 轮（模型主动查）；依赖自觉但有硬校验兜底。装配清单 manifest 的 entity_resolver_installed 字段移除；探针改为「SQL 含 ⟦⟧ 必被拒」的守卫验证。

## 四、评分站转技能自评设计（③定调）

### 4.1 转换设计

系统提示词加自检段：

> 「输出最终答案前自检（不合格自行重写后再交）：①每个数值可追溯到工具结果；②表名与检索到的物理表名一致；③结论与数据口径一致。」

### 4.2 开关设计

能力项 `rubric` 增参数 `mode: "middleware" | "skill_prompt"`，默认 skill_prompt（用户定调），middleware 路径代码保留随时可切回。

### 4.3 代价登记（如实）

①同模型自评相关性偏差；②丢独立评分模型（温度0.0）；③丢 rubric.evaluation 治理记账；④金标锚定免评（13-C）执行器需在契约层重安置或放弃。**验证**：e2e（Playwright 串行）跑质检类问题对比 middleware/skill 两模式的答案质量抽样。

## 五、数据摘要站技能化设计（④：2026-08-24 二次定调，推翻当日早前「留站」结论）

**理解纠正**：count/sum 统计是模型写 SQL 聚合的本职（与该站无关）。该站真正职责=结果行数截断+双通道（模型看 10 行 / 全量推前端表格）。

**早前留站结论的修正**：当时论断「前端全量通道=站的地盘」只对一半——通道确实不在 MCP 工具手里，但**也不必长在站里：SSE 路由层（流式循环代码）本就握有前端 HTTP 流，可亲手写 data_result 帧**。站，可以整个消失。

### 5.1 一件三拆

| 原站职责 | 迁移去处 |
|---|---|
| ① 截断（模型只看 10 行样本） | **MCP 工具端**（execute_sql 等返回前自己截断） |
| ② 派发（全量推前端表格） | **SSE 路由层**（监听 on_tool_end → 按指针取全量 → 写帧） |
| ③ 指令纪律（样本≠明细/聚合结论） | 原本就在工具响应文本里（不动）+ **AGENTS.md 常驻一条**（技能的"书"） |

### 5.2 result_ref 指针机制

```
工具执行: 查回 8000 行
  → 全量存暂存柜(result_ref=uuid, TTL 10min, 上限条数双淘汰)
  → 返回给模型: 样本10行 + row_count + 指令 + result_ref 指针
SSE路由层: on_tool_end 发现 result_ref → 取全量 → 写 data_result 帧(前端协议不变)
```

**前端协议零变更论证**：站用 adispatch_custom_event(config=...) 是因为站不拥有 HTTP 流只能借道；路由层自己就是流的主人，直接写帧，格式与前端现解析的一模一样。中流表格时机等价（工具刚结束、模型下一轮思考前）。

### 5.3 代码落点

1. **mcp_server.py**：四个查询工具内嵌截断+暂存（~60 行）；指令文本（现 _directive）随迁；
2. **sse.py 路由层**：流循环加 on_tool_end 监听，响应含 result_ref 即取数写帧（~30 行）；解析规则：任何工具输出带 result_ref 字段即派发——「管辖工具集」概念消解（哪个工具截断它自己知道）；
3. **query_result_store.py 新模块**：uuid 暂存柜（dict+lock+TTL+条数上限，~40 行）；
4. **AGENTS.md §一 追加纪律**：「execute_sql 等查询工具返回的是前10行样本+row_count+result_ref：全量结论只能基于 row_count 或 SQL 聚合；完整明细已由系统推前端查询结果表，禁止复述样本为明细、禁止分页重查」。

### 5.4 代价与风险（如实登记）

| # | 代价 | 等级 | 缓解 |
|---|---|---|---|
| 1 | result_ref 是新关联机制（现靠 config 隐式绑定会话） | 🟡 | uuid 不可猜+TTL 10min+同进程；跨会话取数需猜中 uuid，登记接受 |
| 2 | 暂存柜内存管理 | 🟢 | 上限+TTL 双淘汰 |
| 3 | 新失败面：路由取数失败→前端无表 | 🟡 | 日志告警+前端兜底文案+探针覆盖 |
| 4 | 查询工具变"胖"（承担展示协议） | 🟢 | 返回"模型该看的摘要+指针"符合 MCP 工具哲学 |
| 5 | 并发多帧乱序 | 🟢 | 帧带 tool_name+sql，前端按帧渲染 |

**连带红利**：批13-W 的 W-4 中「DataSummary 管辖工具集」配置项**取消**（工具自识别）。

**小结果（row_count≤10）**：全量给模型且带 result_ref（前端表格同样要走派发通道）。
