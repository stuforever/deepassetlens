# 二、重大决策变更：题库能力移除（本次新增定调）

## 2.1 决策内容

**移除「自动积累的运行时题库」全部机制，锚定燃料源整体切换到金标库（golden_qa）。**

| 移除项 | 处置 |
|---|---|
| qa_examples 运行时注入（build_examples_payload 进契约消息） | 停用，改注入金标检索结果（语料完全人工策展） |
| 👍 反馈自动入库链路（feedback_service upsert） | 移除；👍👎 转为纯观测信号 + 「金标候选推荐」队列（高赞无覆盖问题列表，管理员手动采纳录入） |
| qa_examples API 面（POST/seed/status/delete） | 下线（保留一个迭代周期 deprecation 壳） |
| Qdrant `tupu_qa_examples` 集合 | 退役（导出备份后清理） |
| hit_count/漂移自动禁用等题库运维件 | 随集合退役 |

## 2.2 为什么这样切：移除的是「自动积累」，不是「锚定能力」

用户对题库的全部不满（自动生成/不可控/改不了/错了没法指导）指向的是**语料的产生方式**，不是「用相似问答辅助回答」这个机制本身。金标库恰好是没有这些毛病的那一半：

| 对比 | 旧题库 qa_examples | 新燃料源 golden_qa |
|---|---|---|
| 语料来源 | 用户点赞自动入库 | 人工策展录入/eval 灌入 |
| 编辑权 | ❌ 无编辑端点 | ✅ 完整 CRUD（PATCH 支持） |
| 审核 | 无 | 天然=录入即审核 |
| 回滚 | 无版本化 | git 管理 seed 数据 |

## 2.4 金标库增强需求（承接题库职责的改造清单）

1. 向量检索：golden_qa 建 embedding 并入 Qdrant 新集合 `tupu_golden_qa`（写入/更新/删除同步）；
2. 字段核对：直通管道需要 `engine` 字段（决定执行工具）——若 golden 表缺该列则补迁移；
3. 命中统计：hit_count+最近命中时间（管理页可见，支撑策展决策）；
4. 管理页：现有 CRUD 之上加「候选推荐」标签页（来自反馈统计的待录列表）。

```

  │

  │    A L0 直通管道：金标精确命中 → 直接执行验证SQL → 模板渲染（0 AI，<4s）
  │    B L1/L2 Agent 循环：多轮工具调用（每次过守卫管道）→ 结构化终答（response_format）
  │    C 澄清卡
  │
  ├─ 自评后置：规则跳过为主 + 异步徽标（批13-B）
  │
  └─ 单帧交付：状态行四态 → done 一次成型（批13-A）
       全程安全控制 = 守卫管道（六守卫函数化，后台三级配置，批13-E）
       观测 = 三本账 + 分段计时（批13-K）
```

# 四、批次详解

## 批13-A 单帧交付 v2【最高优先·用户痛点】
- **目标**：输出区只有两种形态——状态行 或 完整交付卡；不存在未结构化文本上屏。
- **改法**：
  1. 撤销批1-A 双写：answer_draft token 不再写 streaming_answer/气泡，改为驱动状态机；
  2. 四态文案：提交「正在理解问题…」→ 工具期「检索数据中…」→ first_answer_token「答案生成中…」→ answer_committed「答案整理中，正以结构化方式输出，请稍候…」；
  3. done 一次性渲染交付卡（标题+徽标+表格+结构化正文+推荐 chips）；
  4. 可选开关 `TUPU_EARLY_TABLE`（表格属结构化元素可提前入卡，默认关）；
  5. done 兜底链第三优先级回退为 payload（draft 不再有内容）。
- **量级**：前端 1d。**验收**：e2e 全程无逐字文本；两事件间可见整理中文案；done 无二次排版。

## 批13-B 自评后置
- B'-1 规则跳过扩展：`apply_rubric_tier` 加第二条——verification 全绿 + row_count 型结果 → 免评（governance 记 `clean_aggregate`）；
- B'-2 异步化：answer_committed 即发 final+done(rubric_status=pending)，grader 移后台，rubric 事件原地翻转徽标；needs_revision 显式「复核修正」标注替换（max_iter=1 保证最多一次）；
- 量级：B'-1 0.5d；B'-2 1d（实施窗口已以 `_TupuRubricMiddleware` 批10② 开工，按本设计收口）。

## 批13-C 金标锚定体系（题库移除落地）★本次核心
- 按 §二执行移除清单 + 金标增强四项；
- 契约注入段改写：`build_examples_payload` → `build_golden_payload(db, question)`（同接口不同语料源，编排层零改动）；
- 直通管道判定源切换：example_hits → golden_hits（sim≥0.95 + engine 字段）;
- 👍👎 重定义：feedback_service 移除入库逻辑，新增候选推荐聚合查询（近 N 天高频点赞且无金标覆盖的问题 TopM）；
- 量级：2d。**验收**：全链路 grep 无 qa_examples 运行时引用；「统计用电客户数量」经金标命中走直通 <4s；注入审计事件带 golden_id。

## 批13-D 调度拆分
- `data_intelligence_stream.py` → `app/api/freeplan/` 包六模块（endpoint/session/prep/translator/delivery/sse），对外路由协议字节不变；
- 三步走：纯函数→状态机→瘦主干，每步 pytest 全绿再进下一步；字符串断言类测试同步更新锚点；
- 量级：1~1.5d。

## 批13-E 守卫策略管道 + 后台配置
- 六守卫独立函数化（统一 Guard 接口 check(GuardContext)→GuardResult），原实现包壳不搬家；
- 三级权限：🔴红线（SQL 只读/绝对禁止工具，只读展示）/🟡策略（模板守卫/引擎锁/stop_when/输出契约/HITL，block|warn|log）/🟢参数（LIMIT/纠错次数/相似度阈值）；
- `guard_policies` 表 + 管理页「安全策略」面板（含触发统计）+ fail-closed（配置加载失败=全启用）；
- SkillPolicy 内部改调 run_guards()，中间件壳保留；
- 量级：3d。**验收**：默认配置行为与现状一致；关模板守卫预期生效且审计留痕；API 关红线→403。

## 批13-F 原生能力三项启用
1. **response_format 结构化终答**：FinalAnswer schema（conclusion/findings/risks/recommendations）映射交付卡槽位；场景路径 POC（验 stop_when 相互作用/时延增量/中文遵从率≥95%/事件归类）→ 全路径；scrub 降兜底；
2. **store 用户偏好记忆层**：AsyncSqliteStore + (user_id,"preferences") 命名空间；读→契约「已知偏好」段（≤5 条带来源）；写→显式指令捕获/管理页录入，全审核制+总闸；不做 LLM 自动归纳入库；
3. **interrupt_on 双轨审批**：静态策略轨（管理页勾选工具人审，演示/培训模式）+ 动态异常轨（自研保留）；Agent 单例缓存键纳入审批配置版本号；
4. 另：PatchToolCalls 补装配（搭车本批）、Summarization 子类退役验证（trigger/keep 参数化）。
- 量级：POC 0.75d + 接入 2d + 审批轨 1d + 杂项 0.5d ≈ 4d。

## 批13-G 减轮次组合（金标版）
- E 指引预载：意图规则分类 → sql-query 对应小节嵌契约（省 read_file 轮）；
- D 实体预解析修正版：与金标检索共用一次 embedding；**相似度阈值+来源标注**（修预解析错挂事故）；checkpoint 沿用的注明「来自上轮」；
- C 金标首选计划：sim 0.90~0.95 注入首选 SQL 计划（≥0.95 已走直通）；
- 量级：1.5d。

## 批13-H search_entities 混合检索
- 三级融合：精确 code → LIKE → 同义词扩展+向量召回（match_type 字段向后兼容）；属性事实源仍 MySQL；Qdrant 断开静默降级；
- 量级：1d。**验收**：「配变/专变」命中配电变压器；同输入同输出。

## 批13-I 缓存观测与稳定化
- C1 契约文案模板化（同场景逐字节一致）；C2 工具顺序固化；C3 摘要触发治理可见；C4 DeepSeek usage cache_hit/miss 探测与记录（不透传则降级 TTFT 观测）；
- 量级：1d。

## 批13-J 路由治理
- R1 触发词变更→金标 eval 全量的发布门槛；R2 intent_classifier 单模块（已落地，维持）；R3 否定模式检测（「不要 X」不触发 X 场景的低成本正则升级）；
- 量级：0.5d。

## 批13-K 计时外露 + grader 轻模型
- done 载荷加 timing 五段；rubric 耗时进 evidence；徽标 hover 展示；TUPU_RUBRIC_CONNECTION_ID 配置文档化；
- 量级：0.5d。

# 七、全局验收纪律（每批通用）

1. Playwright e2e（`_pw_e2e.py` 串行）为唯一验收标准，后端直连脚本不算数；

3. 涉及事件协议的改动：SSE 事件序列比对通过；
4. 涉及守卫/策略的改动：默认配置下行为与现状一致（纯重构证明）；
5. 每批完成更新本文件的批次状态标记。
