# 数据智能对话 完整设计 v2

> 核心理念：默认路径是「查实体→查属性→出SQL」，关系作为推荐而非强制环节。大模型深度思考，3次尝试才弹窗。LangGraph原生编排，节点=任务=技能（五件套）。

def exit_router(state):

## 四、boss_router 与 LLM 交互（L1核心）

### 4.1 节点函数

```
boss_router节点函数:
  1. 读 GraphState → user_input + secretary_state(记忆)
  2. 调 boss_router技能.execute({user_query, secretary_state, llm_connection_id})
  3. 写回: current_task, goal, router_confidence, router_locked_hint, router_reason
  4. return state → 条件边 route_by_task 接手
```

### 4.2 技能内部4环

```
① SYSTEM_PROMPT: 7任务定义 + goal规则 + 路由规则
② LLM(MINIMAX-M3) → 原始JSON
③ Pydantic RouterDecision 校验(task必须∈7合法值)
④ 状态机强约束 enforce_state_machine
```

### 4.3 RouterDecision 模型（改造点）

```python
VALID_TASKS = {
    "实体定位", "属性定位", "关系定位", "溯源定位",
    "SQL拼装", "SQL执行", "分类查询",
}
# 注意: 去掉"兜底"，LLM失败走重试+clarify，不降级

class RouterDecision(BaseModel):
    task: str
    goal: str = "sql_assembly"  # 新增: sql_assembly(默认) | knowledge_only
    confidence: float = Field(ge=0.0, le=1.0)
    extracted_keywords: list = Field(default_factory=list)
    reason: str
    need_clarify: bool = False
    clarify_question: str | None = None
    vector_store_hint: str | None = None
    locked_hint: dict | None = None  # 新增: 高置信直锁值
    # locked_hint示例:
    # 实体: {"entity_code":"...", "entity_name":"客户", "l1":"...", "l2":"..."}
    # 属性: {"attribute_name":"联系电话", "attribute_en_name":"phone"}
    # 关系: {"relation_type":"main_business", "from":"...", "to":"..."}

    @field_validator("task")
    def _check_task(cls, v):
        if v not in VALID_TASKS:
            raise ValueError(f"task必须是{VALID_TASKS}之一")
        return v

    @field_validator("goal")
    def _check_goal(cls, v):
        if v not in ("sql_assembly", "knowledge_only"):
            raise ValueError("goal必须是sql_assembly|knowledge_only")
        return v
```

### 4.4 SYSTEM_PROMPT（改造点）

```
你是"数据智能对话"的老板路由助手。

## 你的任务
判断用户输入应该走7个任务中的哪个，并判断用户目标。

## 7个合法任务
1. 实体定位 - 找业务实体(L2X主数据/L4X业务活动)
2. 属性定位 - 找实体的具体字段
3. 关系定位 - 找实体间关系(主从/跨链/业务时序)
4. 溯源定位 - 找字段在哪个物理表(血缘)
5. SQL拼装 - 自动生成查询SQL
6. SQL执行 - 执行SQL返回结果
7. 分类查询 - 查分类层级(L1下有哪些L2 等)

## goal判定规则
- 默认 goal=sql_assembly: 用户最终想得出SQL查数据
- 仅当出现"我就想知道/只问知识/不用查数据/了解一下"等显式限定词 → goal=knowledge_only
- goal=sql_assembly时，每个任务完成后自动推荐下一阶段直至SQL执行
- goal=knowledge_only时，停在当前任务不推荐

## 路由规则
- 提到具体业务实体名 → 实体定位
- 提到具体字段名 → 属性定位
- 提到关系/关联/时序 → 关系定位
- 提到血缘/溯源/物理表 → 溯源定位
- entity+attribute已锁 + 提到拼/组装SQL → SQL拼装
- 已拼装SQL + 提到执行/跑 → SQL执行
- "L1下有哪些L2"类分类查询 → 分类查询

## locked_hint规则(高置信直锁，跳循环)
- confidence≥0.8 且实体名明确 → locked_hint填实体信息
- 属性定位且属性名明确 → locked_hint填属性信息
- 不确定时locked_hint=null，走Think循环

## 输出JSON
{
  "task": "<7个里选一个>",
  "goal": "sql_assembly|knowledge_only",
  "confidence": <0.0~1.0>,
  "extracted_keywords": ["关键词"],
  "reason": "一句话解释",
  "vector_store_hint": "entity|attribute|null",
  "locked_hint": {...}|null
}
```

### 4.5 状态机强约束（保留，调整）

```python
def enforce_state_machine(d, sec):
    # 规则1: 未锁entity，强回实体定位(分类查询除外)
    needs_entity = d.task in {"属性定位","关系定位","溯源定位","SQL拼装","SQL执行"}
    if needs_entity and not sec.entity_locked:
        d.task = "实体定位"
        d.locked_hint = None
        d.reason = f"[状态机]需先锁实体({d.reason})"
        return d, True

    # 规则2: 未锁attribute，强回属性定位
    if d.task == "SQL拼装" and not sec.attribute_locked:
        d.task = "属性定位"
        d.locked_hint = None
        return d, True

    # 规则3: 未拼装SQL，强回SQL拼装
    if d.task == "SQL执行" and not sec.assembled_sql:
        d.task = "SQL拼装"
        return d, True

    return d, False
```

## 五、技能内 Think-Act-Verify（L2）

### 5.1 单次执行模型

每个技能节点单次执行 = 一个策略。不内部for循环，靠LangGraph自环。

```
技能节点函数:
  1. 读 state.next_strategy (第1次默认策略池[0])
  2. 执行该策略 → 得候选
  3. verify: 置信度评估 + 业务合理性校验
  4. 通过 → 
       写记忆(confirmed + 旗标 + snapshot)
       流式输出 think_stream: "✓ 定位到: 客户(conf=0.92)"
       state.locked = True
       state.attempt_count = 0
       return state
  5. 不通过 →
       流式输出 think_stream: "✗ 第N轮失败: 原因, 换策略Z"
       state.attempt_count += 1
       state.locked = False
       return state
  → exit_router 接手: locked? next_step : (attempt<3? self_loop : clarify)
```

### 5.2 策略池（按技能配置）

**实体定位 策略池**:
```
[
  "vector_recall",      # 向量召回 entity_embeddings, top_k=15
  "llm_classify",       # LLM推理 + L1/L2/L3/L4分类辅助
  "graph_traverse"      # 图谱遍历找高频实体
]
```

**属性定位 策略池**:
```
[
  "vector_recall",      # 向量召回 attribute_embeddings, top_k=15
  "precise_query",      # 实体已锁时精准查该实体属性
  "llm_infer"           # LLM推理属性语义
]
```

**关系定位 策略池**:
```
[
  "graph_traverse",     # 图谱遍历 RELATES_TO
  "llm_infer"           # LLM推理关系类型
]
```

**SQL拼装 策略池**:
```
[
  "llm_generate",       # LLM生成SQL
  "template_match"      # 模板匹配 kg_entity_mapping_rules
]
```

### 5.3 verify 规则

| 技能 | 置信度阈值 | 业务校验 |
|---|---|---|
| 实体定位 | ≥0.8 锁定 | 必须是主实体(is_main_table)或明确关联实体 |
| 属性定位 | ≥0.8 锁定 | 属性必须属于已锁实体 |
| 关系定位 | ≥0.7 锁定 | 关系类型必须是 main_related/main_business/business_business |
| SQL拼装 | LLM自评≥0.8 | SQL语法校验 + 表名存在性校验 |

### 5.4 重新思考机制

**用户主动怀疑**（"不对/不是这个/重新想"）:
- router识别为 rethink 信号
- 回滚当前任务 think_history + 清除该层旗标
- 重跑Think循环（attempt_count归0）

**系统自检怀疑**（置信度0.5~0.7灰区）:
- 不直接锁，追加一轮反思："这个结果合理吗？有没有更优解？"
- 反思后置信度↑ → 锁；仍灰区 → 进入下一轮策略

## 七、next_step 推荐（L1节点）

### 7.1 核心规则

**goal=sql_assembly（默认）**：推荐推进链上前一项

```
读5旗标:
  entity_locked=F → 推荐"定位实体"
  entity_locked=T, attribute_locked=F → 推荐"查属性"
  attribute_locked=T, relation_locked=F → 推荐"查关系"(可选，非强制)
  attribute_locked=T → 推荐"拼SQL"(主推)
  assembled_sql≠null, sql_executed=F → 推荐"执行SQL"
  sql_executed=T → 推荐"换条件重查"或"结束"
```

**goal=knowledge_only**：静默不推荐，任务结束即结束。

### 7.2 关系推荐策略（关键）

按你的要求：默认路径是实体→属性→SQL，关系作为**推荐**而非强制环节。

```
属性锁定后:
  next_step 主推 "拼SQL"
  次推 "查关系"（仅当检测到该实体有关联实体时才推）
  
关系定位完成后:
  next_step 推 "拼SQL"（关系信息可选注入SQL的JOIN）
```

### 7.3 自动推进

用户下一句话若命中推荐项语义（推荐了"拼SQL"，用户说"那就拼吧"）:
- router识别为命中推荐 → 直跳对应任务，不重新分类

### 9.2 左侧定位树

- **默认骨架**: L1示例1/L1示例2/L1示例3 → L2示例1/L2示例2 → L2X占位
- **确认后填充**: 人确认实体后，节点填入真实名称
- **属性子节点**: 确认属性后，在实体节点下长出属性子节点
- **关系线**: 三种颜色
  - 主数据实体间(蓝): L2X→L2X
  - 主数据与业务活动(绿): L2X→L4X
  - 业务活动间(黄): L4X→L4X
- **默认不展示**: 问"L1下有哪些L2"时不在树上展示，只在右侧对话框列出

### 9.3 溯源区

- 默认占位（叉叉标记原表一/原表二）
- 确认溯源后展开: 实体 → 物理表 → 字段（三层血缘）
- 骨架形状不变，确认后填充实际名称

### 9.4 右侧对话框

- **思考流**: 逐字流式打字机效果，展示Think-Act-Verify每轮
- **确认卡**: 单选/多选/开放反问
- **结果卡片**: 实体列表/属性列表/关系图/SQL/执行结果
- **推荐卡片**: next_step推荐项，可点击
- **按时间倒序**: 可回溯历史消息

### 9.5 待确认的3个UI决策点

1. **Think流式展示**: 逐字流式打字机 vs 按轮次块整块显示
2. **think_history展示**: 默认展开(透明) vs 折叠(点开才看)
3. **重新思考回滚范围**: 只回滚当前任务最新一轮 vs 整个任务清空重来

## 十、七个任务定义

| 任务 | 终点判定 | 技能链 |
|---|---|---|
| 实体定位 | 实体已锁(entity_locked=T) | router→(locked_hint直锁 OR Think循环)→memory_update |
| 属性定位 | 属性已锁(attribute_locked=T) | router→(路径A:实体未锁走Think / 路径B:实体已锁精准查)→memory_update |
| 关系定位 | 关系已锁(relation_locked=T) | router→graph_traverse→memory_update |
| 溯源定位 | 溯源结果已出 | router→lineage_query→memory_update |
| SQL拼装 | assembled_sql已生成 | router→llm_generate→memory_update |
| SQL执行 | sql_executed=T | router→execute+preview |
| 分类查询 | 层级结果已出 | router→graph_hierarchy_query(静默结束,goal=knowledge_only时) |

### 默认主路径（goal=sql_assembly）

```
实体定位 → 属性定位 → [关系定位(可选推荐)] → SQL拼装 → SQL执行
```

关系定位是**推荐环节**，不是强制环节。属性锁定后主推SQL拼装，次推关系定位。
