四张数据库表（启动时自动建）：

- `auth_users` — Authentik sub 镜像
- `auth_roles` — 角色定义（admin/operator/viewer + 自定义）
- `auth_user_roles` — 用户↔角色 N:N
- `auth_resource_acl` — 资源级 ACL（per-skill / per-workflow 授权）

## 5.2 特性开关：ENABLE_AUTH

通过环境变量控制，开/关行为：

| `ENABLE_AUTH` | 行为 |
|---------------|------|
| `0`（默认） | 所有请求按"匿名 admin"处理，与改造前等价；UserBadge 显示 `anonymous` + `admin` + `权限关闭` |
| `1` | 公共路径（`/`、`/docs`、`/api/v1/auth/config`、`/api/v1/auth/dev-login`）放行；其他路径无 token → 401，假 token → 401，合法 token → 解析用户走 RBAC |

公共路径（`_PUBLIC_PATHS`）：
```python
("/", "/docs", "/openapi.json", "/redoc", "/api/v1/auth/config", "/api/v1/auth/dev-login")
```

可选 token 路径（`_OPTIONAL_AUTH_PATHS`）：`/api/v1/auth/me`（有 token 解析，无 token 匿名）

## 5.3 关键流程：Authentik OIDC 集成

### 5.3.1 验签（`_verify_jwt`）

```python
def _verify_jwt(token: str) -> Dict[str, Any]:
    unverified = jwt.get_unverified_header(token)
    kid = unverified.get("kid")
    keys = _fetch_jwks()    # 缓存 10min
    pubkey = RSAAlgorithm.from_jwk(...)
    claims = jwt.decode(

    # （Authentik 默认 access_token 不含这些 claim）
    ...
    return claims
```

### 5.3.2 用户 upsert（`_upsert_user`）

JWT claims 解析后：
- `sub`（必填）作主键查 `auth_users`
- `preferred_username || nickname || email || sub` 作为 `username`
- `groups` 同步到 `groups_snapshot`
- 按 `GROUP_ROLE_MAP` 映射到角色：
  - `tupu-admin` → `admin`
  - `tupu-operator` → `operator`
  - `tupu-viewer` → `viewer`
  - 兜底：未匹配任何 group → `viewer`
- 同步 `auth_user_roles`（新增/删除差异）

### 5.3.3 中间件（`auth_middleware`）

```python
async def auth_middleware(request, call_next):
    if not ENABLE_AUTH:
        request.state.user = _ANONYMOUS   # 匿名 admin
        return await call_next(request)
    path = request.url.path
    if any(path == p or path.startswith(p + "/") for p in _PUBLIC_PATHS):
        request.state.user = _ANONYMOUS
        return await call_next(request)
    if request.method == "OPTIONS":
        request.state.user = _ANONYMOUS
        return await call_next(request)
    auth_header = request.headers.get("authorization", "")
    is_optional = any(path == p or path.startswith(p + "/") for p in _OPTIONAL_AUTH_PATHS)
    if is_optional and not auth_header.lower().startswith("bearer "):
        request.state.user = _ANONYMOUS
        return await call_next(request)
    if not auth_header.lower().startswith("bearer "):
        return JSONResponse(401, {"detail": "缺少 Authorization: Bearer <token>"})
    token = auth_header[7:].strip()
    try:
        claims = _verify_jwt(token)
    except HTTPException as exc:
        return JSONResponse(exc.status_code, {"detail": exc.detail})
    db = SessionLocal()
    try:
        user = _upsert_user(db, claims)
    finally:
        db.close()
    request.state.user = user
    return await call_next(request)
```

## 5.5 资源级 ACL

### 5.5.1 数据模型

```python
class ResourceACL(Base):
    __tablename__ = "auth_resource_acl"
    id              = Column(Integer, primary_key=True, autoincrement=True)
    resource_type   = Column(String(64), nullable=False)   # skill / workflow / data_source / metric / ...
    resource_id     = Column(String(255), nullable=False)  # 具体 id，'*' 表示所有
    principal_type  = Column(String(16), nullable=False)   # user | role
    principal_id    = Column(String(64), nullable=False)   # user.sub 或 role.code
    actions         = Column(JSON, nullable=False)        # 列表：read/write/execute/delete/admin
    granted_by      = Column(String(64), nullable=True)
    granted_at      = Column(DateTime, default=datetime.utcnow)
    expires_at      = Column(DateTime, nullable=True)
    __table_args__ = (
        UniqueConstraint("resource_type", "resource_id", "principal_type", "principal_id", name="uq_resource_acl"),
        Index("ix_acl_resource",  "resource_type", "resource_id"),
        Index("ix_acl_principal", "principal_type", "principal_id"),
    )
```

### 5.5.2 判定优先级（自上而下命中即放行）

```python
def check_permission(db, user, resource_type, action, resource_id=None) -> bool:
    if user.is_admin():                                       # 1. admin 一票通过
        return True
    if _has_permission_via_role_default(user.roles, ...):     # 2. 角色默认权限模板命中
        return True
    if _has_permission_via_acl(db, user, ...):                # 3-5. ACL 命中
        return True
    return False
```

## 5.7 前端 OIDC 流（PKCE）

[`frontend/src/auth/oidc.ts`](../frontend/src/auth/oidc.ts) 的关键函数：

```typescript
fetchAuthConfig()      // 拉 /api/v1/auth/config（OIDC 公开配置）
getStoredToken()       // 从 localStorage 读 tupu.oidc
isTokenValid(t)        // 校验 expires_in
clearToken()           // 401 时清

// PKCE helpers（_b64url 等）
// generateAuthUrl() / exchangeCodeForToken() / refreshToken() / logout()
```

[`AuthGate.tsx`](../frontend/src/auth/AuthGate.tsx) 行为：
1. 未登录访问任何页面 → 检测 `localStorage` 无 token → 生成 `code_verifier + state` → 跳 Authentik `/authorize`
2. Authentik 登录后回调 `/auth/callback?code=xxx&state=yyy`
3. 用 `code` 换 `token` → 写 `localStorage` → 路由到原页面
4. axios 拦截器自动塞 `Authorization: Bearer <token>`
5. 收到 401 → 清 token → 重新走 1

## 5.8 故障排查

| 现象 | 排查 |
|------|------|
| frontend 一直 spinning "加载权限配置..." | backend 没起 / 8100 端口不通；F12 看 `/auth/config` 请求 |
| 跳了 Authentik 但永远回不来 | `redirect_uri` 不匹配；Authentik UI Provider → Redirect URIs 应为 `http://localhost:3000/auth/callback`（strict 模式） |
| 401 一直重定向 | localStorage 里 token 过期；F12 → Application → Local Storage → 删除 `tupu.oidc` |
| `/auth/me` 返回 `is_anonymous=false` 但 `username` 是 hash | Authentik 没注入 `preferred_username` claim；需要配 ScopeMapping（见 `OPERATION_MANUAL.md` §2.4） |
| 改了 Authentik 配置但用户仍是旧角色 | JWT 是离线签的，不会主动刷新；让用户登出重登 |

## 5.9 Authentik Provider 关键配置

需要在 Authentik UI → **Applications → Providers → tupu-oidc → Edit** 勾选 Scopes：

- `authentik default OAuth Mapping: OpenID 'openid'`
- `authentik default OAuth Mapping: OpenID 'profile'`
- `authentik default OAuth Mapping: OpenID 'email'`
- `authentik default OAuth Mapping: Proxy outpost`（含 groups）
