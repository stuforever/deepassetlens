## 11.1 本地环境准备

| 依赖 | 版本 | 检查命令 | 备注 |
|------|------|----------|------|
| Python | 3.11 | `python --version` | 同步系统 Python ≥ 3.11 |
| Node.js | 18+ | `node --version` | npm ≥ 9 |
| Docker Desktop | latest | `docker --version` | Windows 上 WSL2 后端 |
| MySQL | 5.7+/8.0 | - | 业务真源（外部，端口 3306） |
| Git | any | `git --version` | - |
| Windows Terminal | - | - | 推荐用 PowerShell + UTF-8 |

> ⚠️ Windows 下 PowerShell 默认 GBK 编码会导致 Python 启动失败，**所有启动命令前置 `$env:PYTHONUTF8="1"`**。

## 11.2 启动顺序（开发态完整流程）

```powershell
# 0. 准备环境变量（仅当前 session）
$env:PYTHONUTF8 = "1"

# 1. 启动基础设施（6 容器）
cd d:\gitcangku\DB-GPT\tupu
docker compose --env-file .env.infra -f docker-compose.infra.yml up -d

# 健康检查（6 个 Up 状态）
docker compose -f docker-compose.infra.yml ps

# 2. 启动 backend（端口 8100）
cd backend
python -m pip install -r requirements.txt    # 首次或升级时
$env:ENABLE_AUTH = "0"                        # 默认关 Authentik
python -m uvicorn app.main:app --host 127.0.0.1 --port 8100 --reload

# 3. 启动 frontend（新开 PowerShell 窗口）
cd d:\gitcangku\DB-GPT\tupu\frontend
$env:BROWSER = "none"
npm install                                   # 首次
npm start

# 4. （可选）LangGraph Studio（再开一个窗口）
cd d:\gitcangku\DB-GPT\tupu\backend
$env:PYTHONUTF8 = "1"
$env:LANGSMITH_API_KEY = "lsv2_pt_dummy"
langgraph dev --host 127.0.0.1 --port 2024 --no-browser --allow-blocking
```

启动后访问：

- 前端 UI：http://localhost:3000/
- Backend API：http://localhost:8100/docs
- Authentik 管理：http://localhost:9100/（开 `ENABLE_AUTH=1` 后）
- LangGraph Studio：https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:2024

## 11.7 常见问题速查

| 现象 | 排查 / 修复 |
|------|------------|
| `UnicodeDecodeError: 'gbk' codec can't decode` | `$env:PYTHONUTF8 = "1"` |
| `pymysql.err.OperationalError: (1045, ...)` | 改 `DATABASE_URL` 中的用户名/密码 |
| `ConnectionRefused: Neo4j` | 启动 `docker compose -f docker-compose.infra.yml up -d neo4j` |
| `langgraph dev` 报 `LSD_PROM_METRICS_ENABLED` 缺属性 | 锁定 prerelease：`pip install --force-reinstall --no-deps "langgraph-api==0.10.0" "langgraph-runtime-inmem==0.30.0" "langgraph-cli==0.4.29"` |
| `starlette` 版本冲突 | `pip install "starlette>=0.37.2,<0.39.0" --force-reinstall --no-deps` |
| npm start 后 F5 报 404 | 检查 `proxy: http://127.0.0.1:8100` 是否生效 |
| 改 `kg_standard_dict` 不生效 | 重启 backend（注入默认值在 init_db） |
| Authentik 一直 loading | `tmp_authentik_bootstrap.py` 是否成功；Authentik UI 能不能进 |
| 启用 `ENABLE_AUTH=1` 但用户提示 401 | Authentik 引导是否完成；Provider Scope 是否含 `groups` |
| LangGraph Studio 找不到 graph | 确认 `langgraph.json` 路径 `./app/services/query_attribute_langgraph.py:studio_graph_factory` 字面量正确 |
| 前端请求一直 401 | `localStorage.tupu.oidc` 可能过期，F12 → Application → 删除后重登 |
| `Ensure_permission: skill:read` 失败 | `check_permission` 默认拒绝；参考 `OPERATION_MANUAL.md` 5.5 加 ACL 授权 |

## 11.8 编码规范

### 11.8.1 Backend（Python）

- 沿用现有风格：**不加**不必要的注释（项目风格）
- 命名：snake_case 函数 / PascalCase 类 / SCREAMING_CASE 常量
- type hint：核心函数完整标注
- import：stdlib / 3rd-party / 自家 三段式，组间空行
- docstring：仅 public 类/函数加，模块级简短一句

### 11.8.2 Frontend（TypeScript）

- 函数式组件 + Hooks
- 类型先行（先 `interface` 后实现）
- 状态用 Zustand 仅放"全局相关"，页面级用 useState
- 组件文件名 = 组件名 PascalCase

### 11.8.3 提交规范

```
<type>(<scope>): <subject>

feat(skills): 新增 step7_query_cache
fix(query-attribute): 修复 step5 confidence 计算 NaN
docs(wiki): 补充 11-开发指南与测试
refactor(core): scheduler_core 拆分 ExecutionEngine
```

## 11.9 新建能力的标准流程

> 以"加一个 Step3_4 新技能"为例

1. **建技能包**（`backend/data/skills/step3_4_my_new_step/`）
   - `SKILL.md`、`requirements.txt`、`assets/{input,output}_schema.json`、`scripts/main.py`
2. **在 v2 平台导入**（UI → 技能管理 → 导入 ZIP 或手填）
3. **绑定到 workflow**（UI → 工作流管理 → 编辑对应 workflow）
4. **试跑**（UI → 工作流调试 → 设置断点 + 监控变量）
5. **自动化测试**：写 `backend/tmp_test_my_new_step.py`，跑回归
6. **若涉及 LangGraph**：改 `query_attribute_langgraph.py` 节点定义 + `query_attribute_workflow_bootstrap._query_attribute_nodes()`

## 11.12 安全清单

- [ ] 生产环境必须 `ENABLE_AUTH=1` 并启用 Authentik
- [ ] 不在仓库 commit 任何 `tmp_test_*.py` 中的真实 token / API key
- [ ] 改动 `core/auth.py` 必须由熟悉 RBAC 的 reviewer 二次确认
- [ ] 改 `core/execution_engine.py` 沙箱白名单时谨慎（防止 skill 脚本逃逸）
- [ ] 生产部署务必把 `.env.infra` 改成 64 字符随机密钥
- [ ] Authentik 的 `AUTHENTIK_SECRET_KEY` 必须 ≥ 50 字符随机
- [ ] MySQL 不开放外网；Neo4j / Qdrant / Authentik 端口通过防火墙限制来源 IP
