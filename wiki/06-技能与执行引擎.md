## 6.1 技能数据模型（4 表）

```python
# models/skill.py
class Skill(Base):
    __tablename__ = "skills"
    skill_id           = Column(String(36), PK, default=_uuid_str)
    skill_code         = Column(String(100), unique, nullable=False, index=True)
    name               = Column(String(255), nullable=False)
    skill_type         = Column(String(50), nullable=False)        # natural/python/sql/http/mixed
    status             = Column(String(20), default="draft")
    current_version_id = Column(String(36), index=True)
    storage_path       = Column(String(500), nullable=True)        # 五件套根目录
    tags               = Column(JSON)
    priority           = Column(Integer, default=0)
    timeout            = Column(Integer, default=30)
    retry_policy       = Column(JSON, default={...})
    resource_limits    = Column(JSON, default={...})
    permissions        = Column(JSON, default={network:True, filesystem:False, shell:False, ...})
    app_type           = Column(String(50))                        # smart_qa/smart_metric/smart_conn/...
    target_menu        = Column(String(50))                        # 菜单归属

class SkillVersion(Base):
    __tablename__ = "skill_versions"
    version_id     = Column(String(36), PK)
    skill_id       = Column(String(36), FK("skills.skill_id"), index=True)
    version        = Column(String(20))                            # "1.0.0"
    status         = Column(String(20), default="draft")
    input_schema   = Column(JSON)
    output_schema  = Column(JSON)
    content        = Column(JSON, default=dict)                   # 元数据（轻量引用，真正文件在磁盘）
    dependencies   = Column(JSON, default={pip:[], apt:[], env_vars:{}})
    changelog      = Column(Text)

class SkillExecLog(Base):
    __tablename__ = "skill_exec_logs"
    log_id          = Column(String(36), PK)
    version_id / skill_id / execution_code
    input_data / output_data
    status / error_message / duration_ms
    created_via     = Column(String(20), default='manual')         # manual/agent/workflow/schedule/debug
    is_debug        = Column(Boolean, default=False)
    started_at / completed_at

class SkillApiBinding(Base):
    __tablename__ = "skill_api_bindings"
    binding_id / skill_id / version_id
    api_code / api_name / api_type / provider_type / target_ref
    target_ref      = Column(String(255), nullable=False)          # ★ 关键: "service:foo.method"
    enabled / timeout_seconds / retry_policy / auth_mode / route_config
```

## 6.2 五件套技能目录（Filesystem Layout）

每个技能存储在 `backend/data/skills/<skill_code>/`：

```
<skill_code>/
├── SKILL.md                  # 技能说明文档（Markdown 格式）
├── requirements.txt          # 第三方依赖（pip / apt / env_vars）
├── assets/
│   ├── input_schema.json     # 入参 JSON Schema
│   └── output_schema.json    # 出参 JSON Schema
└── scripts/
    └── main.<ext>            # 入口脚本
```

### 6.2.1 五种 `skill_type` 与入口

| type_code | name | ext | 编辑器 | 入口格式 |
|-----------|------|-----|--------|----------|
| `natural` | 自然语言 | txt | PromptEditor | prompt 文本 |
| `python` | Python | py | PythonEditorV2 | `def main(input: dict) -> dict` |
| `sql` | SQL | sql | SQLEditorV2 | 单条 SQL |
| `http` | HTTP | yaml | HTTPEditorV2 | method/url/headers/body_template/auth |
| `mixed` | 混合 | yaml | MixedEditorV2 | 多 step 序列 |

## 6.5 ExecutionEngineV2：统一执行入口

[`backend/app/core/execution_engine.py`](../backend/app/core/execution_engine.py) 是所有技能执行的统一入口。

### 6.5.1 关键方法

```python
class ExecutionEngineV2:
    def execute_by_code(
        self,
        db: Session,
        skill_code: str,
        input_data: Dict[str, Any],
        *,
        llm_connection_id: Optional[str] = None,
        timeout: Optional[int] = None,
        is_debug: bool = False,
        created_via: str = "manual",
        event_callback: Optional[Callable] = None,
        skill_api_bindings: Optional[Dict[str, str]] = None,
        ...
    ) -> Dict[str, Any]:
        """按 skill_code 加载 + 注入全局 + 执行 + 落日志"""
```

### 6.5.2 Python 沙箱（PythonExecutor 6+2 全局注入）

```python
# 执行 Python 技能时自动注入到 main() 的 globals
GLOBAL_INJECTIONS = {
    "_db_session":              db,                  # SQLAlchemy session
    "_common_stop_words":       [...],               # kg_common_stop_words
    "_standard_dict":           {...},               # kg_standard_dict
    "_nl2cypher_semantic_data": {...},               # 标准语义检索结果
    # v5 新增
    "_current_user":            AuthUser(...),       # 当前用户上下文
    "_retriever":               SemanticRetriever(), # 语义检索器
}
```

### 6.5.3 完整执行流程

```
1. 加载 Skill + SkillVersion
2. 校验 input_schema（jsonschema_validator）
3. 按 skill_type 选择执行器
   ├─ natural  → 调 LLM (kg_llm_connection_configs)
   ├─ python   → 沙箱编译 + exec
   ├─ sql      → 提交数据源（kg_data_source_configs）
   ├─ http     → requests 调用
   └─ mixed    → 按 step 序列组合
4. 收集 output
5. 校验 output_schema
6. 落库 skill_exec_logs（含 input/output/status/duration_ms/created_via）
7. event_callback (SSE emit) — 若提供
```

## 6.8 定时调度（SkillSchedule）

`/api/v2/schedules` 提供 cron 表达式调度的能力：
- 创建：`POST /api/v2/schedules`（含 cron_expression）
- 列表：`GET /api/v2/schedules`
- 暂停：`PUT /api/v2/schedules/{code}/pause`
- 恢复：`PUT /api/v2/schedules/{code}/resume`
- 删除：`DELETE /api/v2/schedules/{code}`

存于 `kg_skill_schedules` 表，由 `TaskWorker` 周期性 check `next_run_at`。

## 6.11 完整工作流

```
┌────────────────────────────────────────────────────────────────┐
│ 用户在 UI 点 "Run"                                                │
└────────────────┬───────────────────────────────────────────────┘
                 │
                 ▼
        POST /api/v2/skills/{id}/executions
                 │
                 ▼
       ExecutionEngineV2.execute_by_code()
        │ 加载 Skill + 当前 Version
        │ 校验 input_schema
        │ 注入 Python 沙箱 6+2 全局
        │ 按 skill_type 路由
        │   ├─ natural → 调 LLM
        │   ├─ python  → 沙箱 exec
        │   ├─ sql     → 执行 SQL
        │   ├─ http    → HTTP 调用
        │   └─ mixed   → step 组合
        │ 校验 output_schema
        ▼
        落库 skill_exec_logs
                 │
                 ▼
        返回 { execution_code, status, output, duration_ms, log_id }
```
