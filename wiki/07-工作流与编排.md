## 7.2 SchedulerCore（DAG 即时执行）

[`backend/app/core/scheduler_core.py`](../backend/app/core/scheduler_core.py) 中定义了 6 个核心类：

```python
class TaskScheduler:
    """单线程任务调度：submit_task / get_next_task / complete_task / retry_task"""

class DAGParser:
    """解析 dag_definition (nodes/edges) → 执行计划"""

class DependencyResolver:
    """拓扑排序：按 edges 找无依赖的 next node"""

class ExecutionEngine:
    """单步执行：调 SkillService.execute()"""

class DebugController:
    """断点 / 变量快照 / 单步 / continue / stop"""

class SchedulerCore:
    """编排核心：execute_workflow / debug_start / next / run_to_end / stop / restart_from_step
    落库 kg_dag_workflows + kg_dag_executions + kg_dag_step_executions
    """
```

## 7.3 PipelineRuntimeService（kg_smart_pipeline_* 三表）

[`backend/app/services/pipeline_runtime.py`](../backend/app/services/pipeline_runtime.py) 是 smart_qa / smart_metric / smart_conn / smart_traceability 四个场景的统一记录层：

```python
class PipelineRuntimeService:
    @staticmethod
    def create_run(db, *, scene, mode, workflow_code, input_payload, context_payload, trace_id, parent_run_id, rewind_from_step_order) -> SmartPipelineRun

    @staticmethod
    def get_run(db, run_id) -> SmartPipelineRun

    @staticmethod
    def list_steps(db, run_id) -> List[SmartPipelineStepRun]   # 按 step_order 排序

    @staticmethod
    def add_step(db, *, run_id, step_order, step_code, skill_code, status, confidence, duration_ms, input_payload, output_payload, warnings, logs, next_action, error_message) -> SmartPipelineStepRun
```

`logs` 字段会自动补充三段式 `input / processing / output`，便于前端逐步展示。

### 7.4.4 Checkpointer

```python
# 进程级 InMemorySaver 单例
def _get_default_checkpointer():
    global _DEFAULT_CHECKPOINTER
    if _DEFAULT_CHECKPOINTER is None:
        from langgraph.checkpoint.memory import InMemorySaver
        _DEFAULT_CHECKPOINTER = InMemorySaver()
    return _DEFAULT_CHECKPOINTER
```

> ⚠️ InMemorySaver 是**进程级**，重启后 thread 状态全部丢失。审计追溯不依赖它，步骤事件已落 `kg_smart_pipeline_step_runs`（通过 `step_event_callback`）。

### 7.4.5 HITL API

```python
from app.services.query_attribute_langgraph import (
    run_query_attribute_via_langgraph,
    get_thread_state,
    resume_thread,
    rewind_thread,
)

# 1. 跑一次（自动生成 thread_id）
result = run_query_attribute_via_langgraph(db, user_query="查用电客户的客户名称", metadata_source="system")
thread_id = result["thread_id"]

# 2. 看当前状态
state = get_thread_state(db, thread_id)

# 3. 续跑（state 保留）
result2 = resume_thread(db, thread_id)

# 4. 从 step3 重跑
result3 = rewind_thread(db, thread_id, to_step_id="step3")
```

## 7.7 故障排查

| 错误 | 原因 / 修复 |
|------|------------|
| `UnicodeDecodeError 'gbk' codec` | Windows 编码问题；启动前 `$env:PYTHONUTF8="1"` |
| `AttributeError: module 'langgraph_api.config' has no attribute 'LSD_PROM_METRICS_ENABLED'` | 装到了 prerelease；锁定到 stable：`pip install --force-reinstall --no-deps "langgraph-api==0.10.0" "langgraph-runtime-inmem==0.30.0" "langgraph-cli==0.4.29"` |
| `starlette` 版本冲突 | Studio CLI 会装 starlette 1.x 但 fastapi 0.112 要 0.38.x；`pip install "starlette>=0.37.2,<0.39.0" --force-reinstall --no-deps` 强制降回 |
| graph 列表为空 | `langgraph.json` 路径错误；确认 `"./app/services/query_attribute_langgraph.py:studio_graph_factory"` 字面量正确 |

## 7.10 学习路径建议

1. **概念入门**：StateGraph、TypedDict state、reducer 合并语义 — 看 `langgraph_skill_wrapper.SkillNodeFactory.wrap()` 的 return patch
2. **路由 & 条件边**：`add_conditional_edges()` — 看 `query_attribute_langgraph._build_graph()` 的 `_make_router()`
3. **Checkpointer**：BaseCheckpointSaver / InMemorySaver / SqliteSaver — 看 `_get_default_checkpointer()` 和 `get_state` / `get_state_history` / `update_state` 三件套
4. **HITL 模式**：interrupt / resume / fork — 看 `rewind_thread()` 用 `update_state(target_snapshot.config)` 制造 fork 的细节
5. **Studio 调试范式**：0 参 graph factory — 看 `studio_graph_factory()` 为什么用 `_build_graph(db, None, None, with_checkpointer=True)`
