# 04 · 数据模型与数据库

> 全部 ORM 模型位于 [`backend/app/models/`](../backend/app/models/) 目录，分 4 个文件。
> 所有表使用 `declarative_base` 风格，主键统一为 `String(36)` UUID（`_uuid_str()` 默认值）。

## 4.1 数据库连接

```python
# backend/app/core/database.py
DATABASE_URL = os.getenv(
    "DATABASE_URL",
    "mysql+pymysql://root:root@localhost:3306/tupu?charset=utf8mb4",
)
engine = create_engine(
    DATABASE_URL,
    pool_pre_ping=True,
    pool_recycle=3600,
    pool_size=10,
    max_overflow=20,
)
```

⚠️ 注意：`docker-compose.yml` 顶部注释明确"postgres + neo4j 已移除：tupu backend 100% 走本地 MySQL 3306，不引用这两个"——但实际代码里 Neo4j 仍可能通过独立服务被使用（参见 `services/graph_sync.py`）。

## 4.2 自动建表与兼容迁移

启动时 `main.py` 的 `lifespan` 会：

1. `Base.metadata.create_all(bind=engine)` — 缺啥建啥
2. `ensure_schema_compatibility()` — 对**已存在**的旧库补齐新字段（见 [`database.py:20-538`](../backend/app/core/database.py)）

`ensure_schema_compatibility()` 覆盖以下表的字段补齐：

| 表 | 补齐字段举例 |
|----|--------------|
| `kg_source_field_imports` | `ref_table_en / ref_data_usage_desc` |
| `kg_entities` | `entity_en_name / entity_explanation / sort_order` |
| `kg_llm_connection_configs` | `description / api_path / is_default / timeout_seconds` |
| `skill_exec_logs` | 索引 `idx_exec_logs_skill_time` + `is_debug` 字段 |
| `skill_api_bindings` | 整张表（如不存在则 CREATE）+ 字段补齐 + 索引 |
| `kg_dag_executions` | 索引 `idx_dag_exec_workflow_time` |
| `kg_concepts` | `sort_order / system_names` |
| `kg_smart_skills` | `skill_kind / version / skill_content / skill_descriptor / ...` |
| `kg_smart_skill_types` | 整张表 + 字段补齐 |
| `kg_entity_concept_links` | 整张表 + 迁移存量数据 |
| `kg_smart_skill_workflows` | `target_menu / strategy_config` |
| `kg_smart_planner_configs` | `retrieval_mode / vector_model_name / keyword_weight / vector_weight / rerank_enabled / query_*_workflow_code` |
| `kg_entity_relations` | `relation_category / direction / cardinality / source_field_name / target_field_name / join_expr / remark` |
| `kg_metrics` | `metric_level / metric_unit / metric_subject / stat_grain / business_caliber / ...` |
| `kg_metric_derived` | `config_mode / expr_dsl / base_metric_id / time_period / ...` |
| `kg_metric_query_logs` | 整张表（如不存在则 CREATE） |
| `kg_metric_dim_bindings` | `join_route_json / join_route_status / join_route_updated_at` |
| `kg_smart_pipeline_step_runs` | `logs` |
| `skills` | `storage_path` |
| `skill_types` | 整张表 |
| `kg_skill_schedules` | 整张表 |
| `kg_standard_dict` | 整张表 + 10 条默认词条（用户→用电户、客户→用电户、...） |

> 💡 兼容迁移使用 `INFORMATION_SCHEMA` 判断字段是否存在（MySQL 版本），不会重复 ALTER。

## 4.4 关键关系

```python
# models/skill.py
Skill.versions = relationship("SkillVersion", foreign_keys="SkillVersion.skill_id", backref="skill")
Skill.exec_logs = relationship("SkillExecLog", foreign_keys="SkillExecLog.skill_id", backref="skill")
SkillVersion.exec_logs = relationship("SkillExecLog", backref="version", cascade="all, delete-orphan")

# models/scheduler.py
DAGExecution.workflow = relationship("DAGWorkflow", backref="executions")
DAGStepExecution.execution = relationship("DAGExecution", backref="step_executions")
Conversation.messages = relationship("ConversationMessage", backref=...)
Conversation.runs = relationship("AgentRun", backref=...)
AgentRun.events = relationship("RunEvent", backref=...)
```

## 4.5 初始数据（init_db.py）

首次启动时 [`init_db.py`](../backend/app/core/init_db.py) 会种入：

1. **电力图谱 4 级概念树**：
   - L1：`客户` / `设备` / `供应商`
   - L2：`用电客户` / `发电客户` / `计量点` / `电能表`
   - L3：`业扩接入&电源并网` / `计量采集`
   - L4：`业扩申请` / `电量采集` / `功率采集`
   - 关联 16 个实体（用电户/电能表/电能表日电量明细表/...）
2. **5 个默认 SkillType**：
   - `natural` (自然语言, txt) / `python` / `sql` / `http` / `mixed`

## 4.6 关键不变量

- **不删除历史表**，通过 `ensure_schema_compatibility` 加列兼容老库
- **`kg_entity_concept_links`** 是 `Entity.concept_id` 迁移后的中间表，保留双向 N:N 能力
- **`kg_metric_query_logs`** 是新建的指标查询日志表（2026-06 加）
- **所有时间字段**默认 `server_default=func.now()`，部分 `onupdate=func.now()`
