# 三模块统一技能化 5 周迭代计划（Jira拆分版）

## 1. 计划目标
- 完成智能问数、智能联结、智能溯源的技能去重与统一编排。
- 保留双模式：用户模式 + 开发者模式。
- 开发者模式补齐“可回退”能力（现有模板能力基础上增强）。
- 问数/联结统一为“基于数据实体实例化表查询”；溯源保留来源端追溯。

## 2. 迭代节奏总览
| 周次 | 主题 | 主要交付 | 里程碑 |
|---|---|---|---|
| W1 | 盘点与协议冻结 | 技能映射、I/O统一协议、回退模型设计 | 评审通过并建完Jira |
| W2 | 核心检索/关系合并 | semantic_retrieval + field_grounding + relation_planner | 三模块前3步贯通 |
| W3 | 问数条件与交互 | condition_normalizer + disambiguation + SQL蓝图 | 本月字段不确定可交互 |
| W4 | SQL链路统一 | sql_generator + validator_executor + 双模式联调 | 问数/联结切到新链路 |
| W5 | 溯源收口与上线 | lineage_analyzer、回退能力、灰度发布 | 100%切流并下线重复技能 |

## 3. Jira Epic 规划
### Epic A：技能统一与去重（W1-W4）
- A1 建立技能映射台账并冻结目标skill_code。
- A2 建立Core技能注册与版本发布规范。
- A3 完成旧技能兼容适配层（输入输出字段映射）。

### Epic B：双模式能力建设（W2-W5）
- B1 用户模式输出标准化（解释卡+结果表）。
- B2 开发者模式步骤面板统一。
- B3 新增步骤回退、分支重跑、差异对比。

### Epic C：问数/联结实体查询链路（W2-W4）
- C1 实体实例化表查询约束落地。
- C2 时间条件映射与交互式字段选择。
- C3 SQL蓝图/SQL生成/校验执行统一。

### Epic D：溯源链路与证据输出（W3-W5）
- D1 lineage_analyzer统一化。
- D2 保持attribute_traces与table_relations_grouped兼容。
- D3 溯源解释卡与开发者证据视图。

### Epic E：灰度发布与回滚（W4-W5）
- E1 workflow版本灰度策略。
- E2 旧技能deprecated与下线流程。
- E3 回滚预案演练与验收。

## 5. 每周工作计划（执行版）
### W1（架构冻结周）
- 输出并评审：技能映射台账、统一I/O协议、状态机与回退模型。
- 建立Jira结构：Epic、Story、子任务、验收标准。
- 完成风险清单：性能、兼容性、回滚路径。

### W2（核心能力合并周）
- 完成 `semantic_retrieval`、`field_grounding`、`entity_relation_planner` 合并。
- 三模块改为调用Core技能前3步，保留旧技能兼容适配。
- 开始埋点：步骤耗时、命中率、回退率。

### W3（问数交互与可回退周）
- 完成 `condition_normalizer` 和 `interactive_disambiguation`。
- 完成开发者模式“步骤回退”后端能力。
- 前端增加回退入口与回退后流程恢复。

### W4（SQL统一执行周）
- 完成 `sql_blueprint_builder`、`sql_generator`、`sql_validator_executor` 合并。
- 问数/联结切换到新SQL链路。
- 开发者模式完成回退前后差异对比。

### W5（溯源收口与灰度周）
- 完成 `lineage_analyzer` 统一并对齐旧返回结构。
- 三模块双模式联调、稳定性压测。
- 按流量灰度发布并执行回滚演练，完成旧技能下线。

## 6. 测试计划（重点）
- 功能测试：
  - 问数：多实体明细查询，字段归属准确，时间字段歧义可交互。
  - 联结：关系路径稳定，SQL仅访问实体实例化表。
  - 溯源：来源表/来源字段/关联证据完整。
- 开发者模式测试：
  - 每步可查看输入输出。
  - 可回退到任一步并重跑后续步骤。
  - 回退前后输出差异可视化正确。
- 回归测试：
  - 旧接口兼容、历史工作流可用、灰度下无严重回归。

## 7. 人力建议（最小配置）
- 后端：2人（技能合并1人、编排与回退1人）
- 前端：1-2人（双模式UI、回退交互、对比视图）
- 测试：1人（回归+灰度验收）
- 产品/架构：1人（规则收敛与验收）

## 8. 风险与应对
| 风险 | 影响 | 应对 |
|---|---|---|
| 技能合并导致输出字段变更 | 前端展示异常 | 统一适配层 + 契约测试 |
| 回退能力引入状态不一致 | 调试链路不可用 | 分支模型 + 幂等重跑 |
| SQL链路切换后性能抖动 | 查询超时 | 蓝图缓存 + 索引检查 + 限流 |
| 灰度阶段问题定位困难 | 发布延迟 | run_id全链路追踪 + 一键回滚 |

## 9. 发布门禁（Go/No-Go）
- P0缺陷为0。
- 三模块核心场景通过率 >= 95%。
- 回退功能成功率 >= 99%（开发者模式）。
- 灰度30%阶段无阻塞性故障至少24小时。
